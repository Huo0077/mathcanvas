fix(intersections): scale the sampled-curve dedupe tolerance with the figure, not the origin

F15, the last unknown left by slice 3-3. The dedupe tolerance in curve-intersections.ts was
1e-4 * max(1, |x|, |y|), so it grew with how far the figure sits from the origin: a radius-1
circle measured 1e-4 near the origin but 0.1 at x ~ 1000, and a secant at y = sqrt(1 - 0.025^2)
~ 0.999687 has two real crossings 0.0497 apart that were merged into one (probe). The user draws
at x ~ 20, which is already on that scale. The relative 1e-4 was too loose in the other
direction too: a figure of size 2800 (radius 1000 circle) got an absolute tolerance of 0.1 and
lost a pair 0.05 apart.

The tolerance now only depends on how big the figure is: the union bounding-box diagonal times
1e-9, and never below the interval double can resolve at that coordinate magnitude
(EPSILON * |coordinate| * 64). Exported as intersectionDedupeTolerance so the rule can be
asserted directly. A probe justified going this tight: duplicate candidates for one crossing are
exactly equal (when a crossing lands on a sample vertex the two adjacent chords produce the same
double, separation 0.000e+0), so a machine-precision-scale tolerance is enough.

Evidence - new curve-dedupe.test.ts, 5 cases, RED before the change: the crossing count must not
depend on where the figure sits (centres 0 / 20 / 1000 / 100000 all give 2 crossings about 0.05
apart; the old code returned kind "point" at 1000 and 100000); a near-tangent pair on a
size-2800 figure survives (old code returned a single point); exact duplicates at sample vertices
are still merged (a line on the x axis through a radius-1 circle still yields 2 crossings, not
4, which guards against over-tightening); and intersectionDedupeTolerance is identical at the
origin and at x = 1000 for the same figure, is ~1e-9 relative, and scales linearly with size.

Two of my own test-data errors, both caught by probes: a radius-1000 circle's secant was defined
2000 units out, while a `line` is sampled as a finite a-100u ... a+100u chord, so the sampling
window sat entirely outside the figure (kind "none"); and the separation of a near-tangent pair
is set by the polyline's kink at the sample vertex, not by the circle's curvature, so my
0.05-expected assertion was really 5e-5. Both assertions now avoid hand-computed geometry.
Docs also lose a stale limitation: the "axis-aligned cutting plane fails" note (catalog and the
2026-09-16 section) was already fixed by slice 1B and is now recorded as such.
