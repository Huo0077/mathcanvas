# 发布 v3.0 —— 带 typed tool loop 的桌面版

发布日期：2026-09-29
提交：见本 Release 的 tag `v3.0`
产物：`mathcanvas-desktop.exe`（免安装）、`MathCanvas_3.0.0_x64-setup.exe`（NSIS）、`MathCanvas_3.0.0_x64_en-US.msi`

## 版本号为什么从 0.2.0 跳到 3.0

**这是本项目自己的版本策略，不是 semver 意义上的破坏性变更。** v0.2.0 于 2026-09-23 发布；此后 Agent 侧完成了一整轮 typed tool loop（六个阶段），本次发布把它交给用户。版本号由项目所有者指定为 `v3.0`。

打包器（`tauri.conf.json` / `Cargo.toml`）里的版本必须是合法 semver，所以文件与安装包写 **`3.0.0`**，**git tag 与 Release 用 `v3.0`**。

## 这一版带来什么

### 1. Agent 从"一次性出计划"变成"可观察、有边界、有判据"

- **只读观察循环**：模型可以调 4 个只读工具（`scene.inspect` / `search_entities` / `describe_entities` / `dependencies`）先看画布，再决定怎么画；工具结果以 provider 原生 `tool_call`/`tool_result` 消息回到下一轮。
- **有界的批次执行**：一次响应里的多个工具调用会被**整批判定后原子执行**——任一调用不是已发布的只读工具，就**整批拒绝、一个都不执行**。（这一条修掉了两个 review 抓出的严重缺陷：与只读调用同批到达的合法计划曾被**静默丢弃**；批次曾非原子，9 个调用的批次执行了 4 个才抛错。）
- **没有证据不许说完成**：声明了验收条件的运行，验证报告不构成证据时**到不了确认面板**。判据链是 `deriveAcceptance` → `taskAcceptance` → `verificationGate` → 协调器拦截。

### 2. 工具与字段的单一真源

- 每个动作字段的**形状**有唯一真源（`actionRegistry`），"工具目录 = schema = dispatcher"两个方向都有测试守住。模型可见但宿主不会执行的工具**不存在**（有测试逐条核对）。

### 3. 观测与评测

- 运行账本记录四个版本号（提示词 / 工具目录 / 动作 schema / provider 能力）**与结构化工具痕迹**；痕迹也落库，两个摘要走同一把脱敏尺子。
- `npm run eval:agent` 打印离线记分卡（模式 `deterministic_local`，**不是模型准确率**）。
- 发布门禁文档 + 机器判据，CI 会在 `checks` 作业里跑评测并在 PR 上打印读数。

| `npm run lint` | 0 error / 13 warning（基线） |
| 离线评测 | pass@1 **4/8**、pass@3 4/8、工具选择 45/45（`deterministic_local`） |
| 真实 provider 实跑 | 见下 |

**真实 provider 实跑（2026-09-29）**：用项目自己的 planner（真实提示词、动作登记表、原生工具通道），只把传输换成直连 DeepSeek（`deepseek-chat`，`tools` 能力已验证），喂一道椭圆题：

> 已知椭圆 C 的中心在原点，焦点在 x 轴上，经过点 P(2, 1)，离心率为 √2/2。求椭圆 C 的标准方程。

模型**自己推出** `x²/6 + y²/3 = 1`，给出两个动作（建椭圆 + 标点 P），**2.3 秒一轮完成**；传输日志显示 `tools=5`，正是模型面那 5 个工具。

## 如实缺口（不要当成"都好了"）

1. **没有真实 provider 的 pass@1 / pass@3 / 成本 / 延迟基线。** 上面那次是**单题**，不是比率。发布门禁的第 2 条因此**未满足**——见 `docs/acceptance/agent-release-gate.md`。
2. **圆锥曲线题目拿不到完成判定**：`deriveAcceptance` 的形状表里没有椭圆/抛物线/双曲线，所以那类运行的完成门禁是**惰性的**。
3. **草稿类工具（`draft.*`）刻意不对模型开放**：模型看不见草稿，现在启用会变成"盲验"。理由与触发条件见 `docs/decisions/2026-09-29-agent-phase2-draft-tools.md`。
4. **视觉证据只到本地布局判据**：`render.capture` / `render.inspect_layout` 未接线，`visual-fit` 仍是 `not_supported`。
5. **Agent Worker 入口明确禁用**（`docs/decisions/2026-09-28-agent-worker-strategy.md`）；几何编译仍跑在 `geometry.worker`。
6. 两个安装包（NSIS / MSI）**只验证了构建成功**，没有在本机实际安装过。免安装 exe 在本机启动、渲染、并跑过真实模型链路。

## 已知限制（技术层面）

- `ask_user` 类动作在生产路径上只有部分可达；某些形状仍登记为 `unsupported_action`（拒绝文案准确）。
- `docs/current-status.md` 落后于代码（停在 2026-09-26），尚未回填。
