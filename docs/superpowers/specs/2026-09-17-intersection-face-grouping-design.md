# 交面按支撑曲面分组（A2）设计

> **状态**：用户已确认方向（2026-09-17，"按支撑曲面分组，曲面区域面积先用网格求和并如实标近似"）。
> **用户原话**："重要的问题还在交面上，圆柱和立方体交面会被切成很多个片，这样很不合理。"
> **前置**：A1 已交付解析二次曲面层（`quadrics.ts`、`section-quadric.ts`、`CurvePiece3`）与真曲线渲染；本片把它接到**布尔交面**这条链上。

---

## 1. 根因（已用探针量化，不是推测）

立方体(4×4×4) ∩ 圆柱(R=2, h=6, 48 段) 的实测：

```
交面片数 50   交线份数 1   交点数 8
面积降序：12.5305, 12.5305, 1.0465 × 48
按法向分组：48 个侧面片，每个法向都不同
```

- **2 片**：立方体 z=±2 两平面切出的圆盘（面积 = 圆柱底面 48 边形面积）；
- **48 片**：圆柱侧面被立方体切出的 48 个小四边形——**一个几何上连续的侧面被拆成 48 个独立面片**。

链条：布尔交集在**多边形网格**上算（`intersectConvexPolyhedra3` 吃 48 边形棱柱），`intersectionPreviews3d` 又把结果的**每个面独立枚举**成一份可点预览。

**"合并共面片"修不了它**：48 个侧面片法向各不相同，一片都减不掉（已按法向直方图验证）。

**顺带查出的自有漏洞**：`IntersectionFacePrimitive.exactLoops` 在 A1 第 2 片就声明了，却**从未被任何代码写过**（死字段）；A1 设计文档 §5.5 **第 5 项"布尔交面边界"** 在计划覆盖映射里被我漏掉——本片就是补它。

## 2. 目标与验收

1. 圆柱 ∩ 立方体的交面从 **50 片 → 3 片**：两个圆盘 + 一个圆柱侧带。
2. 三片的边界都是**解析曲线**：圆盘边界是圆、侧带边界是两圈圆弧；曲面上按屏幕误差细分渲染（复用 A1）。
3. **平面区域面积精确**（圆盘 `πr²`）；**曲面区域面积用网格面片求和**并如实标 `numeric-approximation`（侧带实测 50.23 vs 真值 50.27，偏小 0.07%）。
4. 交面图元写出 `exactLoops`；旧文档（无该字段）行为不变。
5. 预览配额随之下降：一份区域一份预览，不再被"一个网格面一份"吃掉配额。

## 3. 架构

### 3.1 内核：`mergeIntersectionSurfaces3`（新文件 `intersection-surfaces.ts`）

输入是布尔交集的结果（`vertices` / `faces` / `faceNormals` / `faceAreas`）与两个来源的形状描述，输出**区域**列表：

```ts
export type IntersectionSurfaceKind = "plane" | "cylinder" | "cone"

export interface IntersectionSurfaceRegion {
  kind: IntersectionSurfaceKind
  /** 平面区域：合并后的外环；曲面区域：网格面片并起来的顶点环（渲染兜底）。 */
  points: Vector3[]
  /** 解析边界（曲面区域必有；平面区域的边界若来自二次曲面也有）。 */
  exactLoops?: CurvePiece3[][]
  /** 平面区域：法向；曲面区域：该二次曲面的轴与半径。 */
  normal: Vector3
  /** 面积：平面区域精确，曲面区域是网格求和（`areaExact: false`）。 */
  area: number
  areaExact: boolean
}

export function mergeIntersectionSurfaces3(
  intersection: SolidIntersectionResult,
  sources: { quadric?: Quadric3 }[]
): IntersectionSurfaceRegion[]
```

分组规则（写死，不留给实现猜）：

1. **平面组**：面孔的顶点共面且平面参数（单位法向 + 常数）在模型尺度相对容差内相同 → 同一组；用"取消内部共享边"合并成一个外环（内部边在两相邻面里方向相反）。
2. **二次曲面组**：面孔的所有顶点都落在**同一张**解析二次曲面上（对圆柱：`|径向 − R|` 与轴向范围；对圆锥同理），且该面不是平面组能覆盖的（侧面的 48 个小四边形不共面，正落在这里）→ 并成一个曲面区域。
3. 其余面孔（既非平面组、也不在已知二次曲面上）**逐个保留**为独立区域，并标 `kind: "plane"`（它们本来就是平面多边形），不假装它们属于某张曲面。
4. 区域顺序按面积降序，保证"哪一块最大"在多次重算之间稳定。

### 3.2 曲面区域的**解析边界**

曲面区域是"二次曲面被一组平面切出来的一片"。边界的构造方式与 A1 的截面同源：

- 把区域内的网格面片按**相邻关系**串成一条（或几条）闭合边界折线；
- 边界折线的每个顶点都落在某张切割平面上（立方体的面）或二次曲面的"端面"上；
- 边界中**落在切割平面上的连续段** → `segment` 片段；**落在二次曲面上的连续段** → 用 A1 的圆锥曲线（`Conic3`）表达为 `conic` 片段，参数区间由两端的顶点参数确定。
  - 对圆柱侧带：两圈弧落在同一个圆（半径 R、高 z₁ 与 z₂），每圈是一个 `conic` 片段（`conic3PointAt` 的参数区间由端点角度给出）；
  - 因此 `exactLoops` = `[[上圆], [下圆]]`（两个环）。

### 3.3 面积

- 平面区域：合并后外环的多边形面积（精确）；
- 曲面区域：区域内网格面片面积之和（**近似**，如实标 `areaExact: false`）。真值需要在这张曲面上做格林公式积分，留作后续项——本片不假装精确。

### 3.4 web：预览与图元

- `intersectionPreviews3d`：对每一对来源，布尔交集先过 `mergeIntersectionSurfaces3`，**一个区域一份** `面` 预览（key 仍是 `pair:<a>|<b>:面<i>`，`i` 是区域序号）；
- 创建出的 `intersectionFace` 带 `exactLoops`（曲面区域）与精确/近似标注的面积；
- 画布：`exactLoops` 存在时用 A1 的 `createCurveLoops3` 画真曲线边界（已在用）；`points` 仍用于填充与拾取。

## 4. 退化与诚实

| 情形 | 结论 |
| --- | --- |
| 两个平面实体（立方体∩立方体） | 行为不变：仍然是 6 个平面区域（旧行为就是对的） |
| 曲面区域里混进非二次曲面的面 | 如实逐个保留，不合并 |
| 区域边界串不成闭合环 | 该区域退回 `points` 多边形，不写 `exactLoops`（画布仍能画） |
| 二次曲面判定容差 | 按模型尺度相对容差（与 A1 一致），不用绝对阈值 |

## 5. 测试策略（RED → GREEN）

1. **本片存在的理由**：立方体 ∩ 圆柱的区域数 **= 3**（现在 50）——RED 会拿到 `expected 3, received 50` 这类真实失败输出；
2. 三个区域的类型：两个 `plane`（法向 ±Z，面积 `πr² = 12.566`，精确）+ 一个 `cylinder`（面积≈`2πRh'`，`areaExact === false`）；
3. 曲面区域的 `exactLoops`：两个环、每环是 `conic` 片段、且采样点确实落在半径 R 的圆柱面上（性质断言）；
4. 平面区域的边界也是解析圆（半径 R）；
5. 立方体∩立方体不受影响（仍是 6 个平面区域，面积与旧实现逐位相同）；
6. 退化：平面与实体相切、区域串环失败 → 如实退回多边形且不写 `exactLoops`；
7. 浏览器：创建交面后 `data-preview-face-count` 从 50 降到 3（沿用既有 e2e 的读数）。

## 6. 第 3 轮：区域的**填充三角化**与**真曲线边界**（2026-09-17，已交付）

第 1、2 轮把"50 片 → 3 个区域"打通了内核与创建路径，但画布上还有两处对不上：

### 6.1 曲面区域的填充不能扇形三角化（`outerRingLength`）

曲面区域的 `points` 是"前导外环 + 其余环**反向**缝合"的一条多边形，配对约定是
`points[长度 − 1 − i] ↔ points[i]`（内核 `stitchedCurvedPoints` 缝的时候就是按这条缝的）。
渲染方此前一律从 `points[0]` **扇形**铺开：对凸的平面区域没问题，对缝合带却会把两圈之间那个"洞"
整块填掉——48 段的侧带会被画成"顶上一块圆盘 + 几片横穿圆柱内部的三角形"。

- 内核 `IntersectionSurfaceRegion` 新增 `outerRingLength?: number`：**只有真的缝了不止一圈**的曲面区域才写
  （平面区域的 `points` 就是外环本身，退回 `largestFace` 时也不写）；
- DSL `IntersectionFacePrimitive.outerRingLength`（可选，旧文档没有）、schema 只收"≥ 3 的整数"；
- scene-graph 重算时写入，并且与 `exactLoops` / `areaExact` 一样**是派生的**：这一轮算什么写什么，
  算不出就把上一轮的字段摘掉（否则会把一块平面多边形当环向条带缝）；
- 渲染方（创建出来的交面**与**预览命中面片共用同一个 helper `regionFillPositions`）按**环向条带**三角化：
  8 条环向边缝 16 片，**每一片都跨在两圈之间**；退化（重合点）三角形直接跳过。

### 6.2 边界必须是真曲线（本片才真的接上）

§3.4 里写的"`exactLoops` 存在时用 `createCurveLoops3` 画真曲线边界（已在用）"**当时并不成立**：
`createIntersectionFaceGroup` 从来没读过 `exactLoops`，交面边界一直是一圈 96 段的多边形弦。
本片接上：容差可用（有限、正）时，边界交给 `createCurveLoops3`（视觉角色仍是 `intersection-face-edge`，
画布读数按角色找对象），否则如实退回多边形弦——**绝不拿 NaN / 无穷去采样**。

`threeScene` 侧：交面条目的内容签名带上"边界是解析还是多边形 + 容差档"，
`wantsExactCurves` 把"带 `exactLoops` 的交面"也算进去，否则放大后边界不会重新细分。

### 6.3 整圈的闭曲线片段走闭式段数公式

交面侧带的解析边界是**整圈** `[0, 2π]` 的 `conic` 片段。这种片段此前走开曲线的自适应二分，
而整圈的首尾是同一点 ⇒ 那根弦是**退化的**（长度 0），平坦度判据永远不满足，只能一路二分，
而二分只给 **2 的幂**段数：弦高公式要 40 段时它给 **64 段**（实测 65 个点 vs 41 个），参数间隔还不均匀。
现在 `sampleConicRange` 遇到"闭曲线 + 整圈"直接用 `sampleClosedConic` 的闭式公式。

### 6.4 曲面区域的预览不再把每个网格顶点都标成"交点"

曲面区域的 `points` 是网格多边形（48 段侧带 = **96 个顶点**），而交面预览此前把这一圈每个顶点都画一个
点标记——画布上就是两圈密密麻麻的点，和第 1 轮之前"圆上冒出 96 个点标记"是同一类噪声，也和本仓库既有的
口径冲突（"光滑交线一个采样点都不标"，见 `intersectionMarkerPoints` 的注释）。缝合处那两个拐角同样不是
几何特征，而是我们拼接多边形的接缝。现在**平面区域的拐角照旧标（4 边形 4 个），曲面区域一个都不标**；
真正的交点标记由**交线**预览负责。

### 6.5 验收（本机实跑）

- 内核：缝合带 `outerRingLength === 48`、`points.length === 96`；两个圆盘与 立方体∩立方体 的 6 个平面区域都没有该字段。
- web 单测：8 段两圈的最小样本 ⇒ 填充 **16 片**、每片 z 跨满（扇形实现给 14 片且 z 跨度为 0）；
  交面边界是 **2 条 `THREE.Line`**（各 100 段、每个顶点都落在半径 2 上），而不是 1 条 `LineSegments`。
- 预览：同一份缝合多边形在预览命中面片上也是环向条带（否则"鼠标落在洞上"也会高亮这块交面）。
- 浏览器（新 e2e `e2e/three-intersection-band.spec.ts` + 夹具 `e2e/fixtures/cube-cylinder.mgeo`）：
  `data-preview-face-count = 3`、点侧带建出**整条带**（检查器面积 50.2xx、顶点数 96、"数值近似"）、
  `data-exact-curves` **1 → 2**（把解析边界关掉的变异实验读回 1，证明这条断言不是空的）、放大后细分点增加。

### 6.6 点侧带的交互（如实记录，含第 2 轮那条被更正的判断）

第 2 轮记的"点侧带建不出交面，因为选中的实体带着默认截面预览"**只对了一半**。本轮的探针（`data-pick-readout`）：
不带任何截面预览时，点侧带**能**建出交面；被拦下的是射线**真的命中来源立方体的棱**的那种情况——
实测方位角与相机方位角相同时（45°），投影出来的侧带点恰好与立方体 (2,2) 那条竖直棱共线，
读数 `edge|cube-a-edge-25|precise|hover|behind`，按 `threePicking.ts` 既有的优先级（真命中棱 > 预览）
点击被解释为"选中那条棱"。偏离 ±30° 时读数 `face|…|coarse|hover|front` ⇒ 预览赢、创建成功；
偏离 ±50° 时射线贴着圆柱与切面的那圈交线（hover 变成 `:线`）。
**这是既有优先级的必然结果、不是新缺陷**（细目标优先在设计上是对的），e2e 因此取 ±30° 那个点，
并把这条判断写进用例注释。

## 7. 第 4 轮：圆锥的锥尖（极点）与"曲面 ∩ 曲面"（2026-09-17，用户实测反馈）

用户原话："曲面交面相当乱，交出一大堆面，但是无法获取那个曲面。"

实测（用户场景）：圆柱（r=1.5、h=4）∩ 圆锥（同底同高）——圆锥整体落在圆柱里，交集就是圆锥自己，
**48 个侧面三角形 + 1 个底面圆盘**。修复前画布上 **49 份**交面预览，点哪一块都只是一个小三角，
"圆锥面"这张曲面**拿不到**。两条根因都在"这个面是不是这张曲面上的一片"的判据里：

1. **锥尖被判成"不在曲面上"**：`radiusAt` 用的是 `ratio > 0`，而锥尖处 `ratio` 恰为 0、半径本来就是 0
   ——顶点在曲面上。于是每个带锥尖的三角形都被排除。→ 改成 `ratio >= 0`（只有越过锥尖 `ratio < 0`
   才如实返回 `null`：那不在有限圆锥上）。
2. **锥尖的角度没有意义**：它落在轴上，`atan2(0, 0)` 量出来是 0；按**所有**顶点量张角会把一张张开
   7.5° 的侧面片量成 **93°…116°**，照样被"一片最多张开 60°"挡掉。→ 张角只按**离开轴**的顶点量
   （径向 > 相对容差），少于两个这样的顶点就如实不当它是曲面片；轴上顶点仍必须满足"在曲面上"。

修完 **49 片 → 2 个区域**（一张圆锥面 + 一个底面圆盘）。接着还有半个问题：圆锥面的**边界只有底面那圈**，
锥尖在曲面内部、不在任何边界环上，于是

- 多边形填充按边界环铺 ⇒ 把"圆锥面"填成底面那团圆盘；
- 形心落在底面圆心 ⇒ 与真正的底面圆盘区域**完全同一个形心**，预览的 `hint` 分不开，点圆锥侧面
  认领到的还是那张圆盘。

→ 新增 `poleIndex`（极点＝在曲面内部、不在边界环上的那个顶点，判据从严：**恰好一个**且径向 ≈ 0），
`points[0]` 就是它；渲染方（创建出来的交面与预览命中面片共用 `regionFillPositions`）**绕极点铺开**，
边界环与顶点标记都**排除**它。极点与缝合带不会同时出现（有极点就只有一个边界环），所以两者互斥、
`outerRingLength` 在有极点时不写。

**验收（本机实跑）**

- 内核：`regions` = 1 圆锥面 + 1 圆盘；圆锥面 `areaExact: false`、面积 = 那 48 片三角形之和（比 `πrl` 小 0.1%）；
  `poleIndex === 0`、`points.length === 49`、极点在轴上且高度 = 底面 + 高；圆锥面与圆盘的形心**不再重合**（距离 > 0.05）。
- web 单测：8 段最小样本 ⇒ 绕极点 **8 片**（每片恰含极点一次）、多边形兜底边界只有底圆那 8 条边（不含极点）；
  变异（把极点分支短路）分别报 `expected [ …(7) ] to have a length of 8 but got 7`。
- 浏览器（新 e2e `e2e/three-intersection-cone.spec.ts` + 夹具 `e2e/fixtures/cylinder-cone.mgeo`）：
  `data-preview-face-count` **49 → 2**、状态栏"2 个交面"、hover 命中 `面0`、点锥面建出的交面面积 **20.1**（"数值近似"）。
  变异（把 `radiusAt` 改回 `ratio > 0`）⇒ 读数回到 **49**。
