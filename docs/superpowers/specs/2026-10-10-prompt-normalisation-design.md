# 题面规范化（让模型把用户的话翻成我们能读的写法）设计

> **状态：2026-10-10 用户已裁决"两个都做"** —— 第一件（把常见写法直接教给解析器）已实施并随 `3.3.5` 打包；
> **第二件已完成第 1 步**：安全阀核心（`promptNormalization.ts`，11 条用例）+ 计划字段 `normalisations` +
> 编译期接线（改前未核验的从句，改写后真的核验通过）。**剩下两半**：① 模型上下文 + 提示词（告诉模型
> 改写哪些、字段怎么写）；② 面板显示「原件 → 我这样读」。**这两半做完之前模型不会发出这个字段，
> 用户可见行为一字未变** —— 不显示改写就不许悄悄改写，这是硬要求。
> 相关：第一件的现场与判据见 [`CHANGELOG.md`](../../../CHANGELOG.md) 同日那条。

## 理解写回

**用户要的结果**：把一道**中文原题**粘进来就能画，不要因为"我们没见过这种写法"而永远拿不到图。

**用户的原话（这次需求的来源）**：「为什么这么死板？为什么大模型不能自己优化用户的题目转化成 agent 能理解的话呢？」

**为谁**：高中学生与教师。他们写的是课本上的中文，不会为了迁就系统改写题面；把"改用受支持的条件表达"这句话推给他们，就是把机器该干的活推给人。

**成功标准**（可测）：
1. 题面里出现"解析器不认识"的从句时，系统**先尝试读懂**（一次模型往返），而不是直接把整句挂掉。
2. 读懂之后，**几何核验照旧由确定性内核做** —— 模型只换说法，不改条件；"看出来对不对"永远不由模型说了算。
3. 每一次改写都**逐条指回原文片段**，并在界面上以「原件 → 我这样读」摆给用户看。
4. 指不回去 / 引入原文没有的点名 / 改写后仍然读不出条件 ⇒ **丢弃该条**，退回今天的行为（如实说读不懂）。
5. 常用写法（第一件已覆盖的那三类）**继续走离线确定性路径**，不花模型调用、不改黄金样本。

## 二、设计

### 2.1 触发与时机

**只在** `parseDiagramObligations(prompt).unverified` 非空时触发一次（题面在场、且这一轮要作图）。
没有"读不懂"的从句时**一次模型调用都不多发** —— 常用写法（第一件那三类）走的是离线路径。

### 2.2 三件纯函数（`packages/agent-core/src/promptNormalization.ts`）

1. **`buildNormalizationPrompt(prompt, unverified)`** → `{ system, user }`
   要求模型逐条输出 `{ original, normalized }`：`original` 必须是**原话里的一个片段**（逐字），
   `normalized` 是同一件事的**标准写法**。提示词里明确：**不许新增、删除或弱化条件**。
2. **`parseNormalizationReply(reply, prompt, unverified)`** → `{ accepted, rejected }`
   逐条校验（任一条不过就丢那一条，不整批接受）：
   - `original` 必须**逐字**出现在 `prompt` 里，且命中某条 `unverified.sourceText`；
   - `normalized` 非空，且**不引入该从句里本来没有的点名**（防"编一个新条件"）；
   - `normalized` 必须能被 `parseDiagramObligations` 读成**至少一条 given**（读不出就不算数）。
3. **`applyNormalization(prompt, accepted)`** → 新的题面文本（把原文片段替换成标准写法，其余原样）。
   调用方拿它过**同一个** `parseDiagramObligations` —— 于是"这次读懂了什么"与平时完全同一条路。

### 2.3 谁看得见（诚实边界）

- 面板/回执里显示一张「**原件 → 我这样读**」的表（逐条，含被拒的条目与原因）；
- 用户的原话**一个字都不改**地留在会话里；
- 核验结果照旧逐条给出（`passed` / `failed` / `unverified`），**由确定性内核算**。

### 2.4 接线（apps/web）

`agentRunner` 在收到用户消息之后、规划之前插一步：
`unverified` 非空 ⇒ 走模型规范化一次 ⇒ 用改写后的文本继续（解析 + 规划都用它，UI 显示原件）。
模型不可用 / 调用失败 / 全被拒 ⇒ **原样继续**（今天的行为：未核验 → 不提交）。

### 2.5 明确不做

- **不让模型决定条件成不成立**（它只换说法；判据在内核）。
- 不做"无模型的离线改写"（那要靠句型覆盖，就是第一件）。
- 不动黄金样本与离线评测读数（触发器只在有 `unverified` 时才多一步）。
- 不因此放宽门禁：读不懂且改不懂时，照旧不提交。

## 三、判据（RED → GREEN → 变异）

1. **RED**：一句带"读不懂从句"的题面 + 一个**假模型**（返回逐条改写）⇒ 断言：
   `unverified` 那几条变成可核验的 given、「原件 → 我这样读」的表里有它们、且最终核验走的是内核。
2. **反例（安全阀）**：假模型返回的 `original` **不是原文片段** ⇒ 该条被拒；返回的 `normalized`
   引入了原从句没有的点名 ⇒ 该条被拒；全被拒 ⇒ 行为与今天**逐字相同**（未核验 → 不提交）。
3. **反例（不改条件）**：假模型把 `AB⊥AD` 改写成一个更弱的说法（例如"AB 与 AD 不平行"）——
   判据：`normalized` 里的关系词必须与 `original` 同类（⊥ 只能改成 ⊥ / 垂直于…），否则拒。
4. **不变**：没有 `unverified` 时**一次都不调用**规范化通道（用假模型计数钉住）。
5. **门禁**：定向 + 全库非 Lean + `typecheck` + `lint` + 全量 e2e + 黄金样本逐字不变。

## 四、风险与回退

| 风险 | 处置 |
| --- | --- |
| 模型"把条件改弱"让自己的图通过 | 安全阀三条（指回原文 / 不许新点名 / 关系词同类）＋ 改写**摆给用户看** |
| 多一次模型往返的成本 | 只在有 `unverified` 时触发；常用写法走第一件的离线路径 |
| 读写放大（一句题面被改得面目全非） | 只替换 `unverified` 命中的片段，其余原样 |
| 回退 | 整条通道是**额外的一步**：删掉这一步就回到今天的行为；判据里有一条专门钉"全被拒 ⇒ 与今天逐字相同" |
