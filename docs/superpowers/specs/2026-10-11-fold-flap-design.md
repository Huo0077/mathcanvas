### 0.2 为什么读不出来（读代码得到的机制）

- **`AD=5√3` / `PC=4√3`**：长度句型匹配到 `AD=5` 之后，紧跟的 `√` 命中
  `diagramObligations.ts` 里那道**刻意的守卫**（"数字后面还跟着 `√/π/°/*` 之类就不算一个数"），
  **整条匹配被丢弃**。守卫拦得对（`AD=5√3` 确实不是"AD 等于 5"）——缺的是**根号数字**本身。
- **`AE:AD=2:5` / `AF:AB=1:2`**：残留扫描器（`UNREAD_CONDITION`）**早就把 `AE:AD=2` 这种形状
  当条件看**，也就是说"这是一条条件"这件事一直是知道的 —— 缺的只是**接它的读取器**。

⇒ **只加一个"折"的动作，这道题一个字都不会变**：它会在核验那一关被拦下，与折无关。

## 1. 本期范围（用户 2026-10-11 裁定）

**做「折给定角度」**：模型说「沿 EF 折起 90°」，`P` 的坐标**由内核旋转算出**；
`折至 PC=4√3` 那种**对条件求根**留给第二期（§7）。

理由：现场失败的直接原因是**模型手算空间坐标**（实测它给的 `C` 两个条件一个都不满足、
后来几次给出四个共线的点）。模型擅长的是"读出这是一次折叠、哪一片在动"，不擅长的是算坐标。
把坐标交给内核，就打中了真正出错的那一环。

## 2. 动作形状：**方案 A**（已定；方案 B 记录在此备查）

| | 方案 A（**选它**） | 方案 B（不选） |
| --- | --- | --- |
| 动作收什么 | 翻折片的**平面坐标** + 折痕两端点名 + 角度 | 一只**已存在**面片的引用 + 折痕 + 角度 |
| 要不要新前提 | 不要 —— 今天的图元就够 | 要 —— 先让面片顶点能写成"已点名的点" |
| 折痕上的点 | 两半各持一份坐标重合的拷贝 | 同一个对象，两半真正共用 |

**为什么 B 需要新前提**：`solid.create_face` 物化出的是 `face3` + **它自己私有的点**
（`faceId:v0`…），顶点只从坐标建、不接受"已存在的点"引用（`scene-graph/src/actions/index.ts`）；
而唯一跨面共享顶点的是 `solid.create_polyhedron`，它要求 ≥4 个面 —— 装不下"一片 + 一块"的开放曲面。
折的本质是两半共用一条折痕，所以 B 得先补一格。**A 用"两半各持一份坐标重合的拷贝"绕开了它**，
代价是折痕上的点在文档里有两份（几何上重合，用户看不出来）。

## 3. 语义

**沿一条直线把一只平面多边形刚体旋转给定角度。** 折痕上的两个点在轴上、不动；
其余顶点绕轴旋转。`A` 转到 `P` 是**同一个点换了个名字**，不是新造一个点 ——
题面「翻折至三角形PEF」说的正是这件事。

**坐标约定**：动作收的是翻折片**折前（平面）**的坐标与点名，另给
`apex`（哪个顶点被带走）与 `apexAs`（带走之后叫什么）。产出那只 `face3` 用**折后**的名字与坐标。

## 4. 内核

- **旋转原语已经有了**：`unfold3d.ts` 的 `rotateAboutAxis(point, origin, axis, angle)`（Rodrigues），
  只是**模块私有**。按本仓"同一件事不许两个口径"的纪律，**导出复用**，不另写一份。
- **折痕轴**：由两个点名的**当前坐标**定（`origin = 第一个点`，`axis = normalize(第二个 - 第一个)`）。
- **不动的那条边**：折痕两端必须都在翻折片上，否则就是拿一条题面里不存在的线去折 —— 如实拒绝。

## 5. 失败三分与护栏

**三种失败各自报清楚，不许含糊**：

1. **折痕两端不在翻折片上** ⇒ 拒绝，文案指到"`EF` 不是这片上的一条边"；
2. **角度非法**（≤0、>180、非有限） ⇒ 拒绝；`0°` 与 `180°` 的边界各自说清（没折 / 折平）；
3. **折完退化**（顶点重合、共线、无面积） ⇒ 走 `solid.create_face` 那一套**同一口径**的校验，
   **一条图元都不产出**。

**不许顺手打开的门**：

- **棱柱侧棱方向的角**（`∠A′AB`）—— 早已裁决不做，与折无关，不许因为"反正都在解一个角"而顺带打开；
- **多片联动折叠**（一次折多片、折上再折）—— 本期只做单片；
- **曲面折叠** —— 只做平面多边形片；
- **通用非线性求解器** —— 第二期也只解"折角"这一个未知量（§7）；
- **`planar.*` 侧不许出现折** —— 折产生的是三维构型，只能住立体工作区。

## 7. 第二期（**写在这里，本期不做**）：折至条件

模型只说「沿 EF 折起，使 `PC=4√3`」，由内核对**折角**求根。机制与现有的二面角 / 顶点角**同一套**：

- 未知量只有**折角**一个（区间 `(0°, 180°]`）；
- **2048 步扫描**找第一个符号变化区间，再**固定 200 步二分**；无 RNG、固定步数、可复现；
- 取**最小正根**（与二面角"最小正高"同一条口径，为的是可复现，不是好看）；
- **常性判据与求根分开报**：取两个不同角度测同一个量，若读数相差 ≤ 容差 ⇒ 这个条件与折角**无关**
  （恒成立 ⇒ 冗余；恒不等于 ⇒ 矛盾），文案说"实测恒为多少"，与"没找到"分三句话；
- **求根成功 ≠ 通过**：最终仍由统一核验器对**最终坐标**再量一遍，构造器**不自证**。

第二期能落地的前提是：`fixedLength(P, C)` 已经读得出来 —— **这一格 §0.4 已经补上了**。

1. `solid.fold` 能读、能构造、能核验，且**实测角度与折后坐标写进结论**；
2. §6 的每条判据都有用例，且**每条都先红过**；
3. **护栏用例**：折痕两端不在片上 / 角度非法 / 折完退化 —— 各自拒绝且不产出半个图元；
4. 门禁全绿（定向 + 全库非 Lean + typecheck + lint + 全量 e2e）+ **变异**
  （把旋转短路成恒等 ⇒ 判据红、还原复绿）；
5. 文档同步（当前状态 / 归档 / 本页状态行）与单独 commit + push + `git ls-remote` 核对。

## 10. 一件必须如实留着的事

**即使 §1、§7 都做完，这道题也不保证一次就画对**：题面里 `C` 的位置由
`∠ADC=90°` 与 `CD=3` 两条共同决定（有两个解，取不让四边形自交的那一个），
而**模型给的 `C` 实测两个条件一个都不满足**（`|DC| = 2.34`、`∠ADC ≠ 90°`）。
有了折的动作之后，模型不必再算折后坐标，但**平面那四个点仍要它自己给对** ——
给错了由核验器如实报出来（那时它拿到的是"实测 vs 题面"的具体差值，而不是一句内部码）。

这一条写在这里，是为了不让"翻折做完了"被读成"这道题一定画得出来"。
