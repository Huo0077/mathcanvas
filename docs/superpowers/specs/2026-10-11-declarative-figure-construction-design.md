# 声明式图形构造：让系统按题面造坐标，模型不再手写（乙案）—— 设计

> **状态（2026-10-11）：设计，未实施。** 本文只定设计与分期；实施要等本文过目、
> 再由实施计划接手（本仓的规矩：设计 → 计划 → 动手）。
>
> **起因**：用户那句「平面四边形ABCD…将三角形AEF沿EF翻折至三角形PEF，使得PC=4√3」，
> 在桌面端连打多次，每修好一层就露出下一层。其中**反复出现的一整类**是
> **模型手写空间坐标**，而它写错的方式每次都不一样：四个共线的点、全零顶点、
> 拿 `solid.create_polyhedron` 硬凑平面片、`C` 两个条件一个都不满足。
> 这一案治的就是这一类，而不是再补一个动作。

## 0. 今天到底发生什么（**探针实测**，不是推测）

### 0.1 题面解析这一层是好的（2026-10-11 探针）

`parseDiagramObligations(原话)` 实测：**8 条题设、0 条未核验**。

| 从句 | 读成 |
| --- | --- |
| `AB=8` | `fixedLength(A,B) = 8` |
| `AD=5√3` | `fixedLength(A,D) = 5√3` |
| `∠BAD=30°` | `planarAngle(B,A,D) = 30` |
| `∠ADC=90°` | `planarAngle(A,D,C) = 90` |
| `CD=3` | `fixedLength(C,D) = 3` |
| `AE:AD=2:5` | `segmentRatio([A,E,A,D]) = 0.4` |
| `AF:AB=1:2` | `segmentRatio([A,F,A,B]) = 0.5` |
| `PC=4√3` | `fixedLength(P,C) = 4√3` |

**条件本来就不需要模型复述** —— 它们是系统自己从原话抽的。这一条决定了本设计的形状。

### 0.2 构造机制今天对这句题面说什么（同一支探针）

```
specForPrompt(原话, givens)  →  { "status": "unrecognised",
                                  "reason": "题面里没有可识别的『在…中』形状从句
                                             （或缺点名表 / 数词与环长对不上）。" }
```

**对照**（同一支探针，换成有形状从句的题面「在四棱锥P-ABCD中，PA⊥平面ABCD，底面ABCD是菱形」）：

```
specForPrompt(...)  →  { "status": "ok",
                         "spec": { "family": "pyramid",
                                   "base": ["A","B","C","D"],
                                   "apex": { "at": "P", "foot": "A" },
                                   "relations": [ { "kind": "equal-length", "segments": [["A","B"],["B","C"]] }, … ] } }
```

**读数只说一件事**：这套机制靠**形状从句**（『在…中』那一句）来定**图形的种类**。
那句题面是**裸的平面图形 + 度量条件**，没有它能挂的钩子 ⇒ `unrecognised`。

### 0.3 现场读数（用户桌面端 3.3.14，见证搜索**已打开**）

- 第一版仍被**信封**拒：`solid.create_polyhedron` + `faces:[[0,1,2,3]]`（**一个**面）—— 与开关无关；
- 走到 `validating` 后失败，把八条报错并起来可以还原出**图上到底有哪些点名**：
  **在图上：A、E、F、P；不在图上：B、C、D**；
- 也就是说：**平面上那三个点从来没被造出来**，见证搜索没有接住这一类。

**§0 的三条合起来给出本设计的起点**：条件已经读全了、结构规格这一层认不出这种题面、
构造从未发生。所以问题不在"读不懂题"，在**"读懂了却没有能把它造出来的那一层"**。

## 1. 这一案治什么、不治什么

**治**：**模型手写坐标**这一整类失败。坐标不再由模型提供，而由内核按题面条件构造。

**不治（本设计明确不负责，免得下一轮又讨论一遍）**：

- **模型选错动作**（拿 `create_polyhedron` 画平面片）—— 那是词表可用性与报错可操作性的问题，
  与"谁来算坐标"是两件事；
- **构造器尚未覆盖的别的图形族** —— 本设计只把"由度量条件钉死的平面图形"这一类补上，
  别的族要各自另立；
- **"模型完全不声明结构"的全自动推断** —— 结构（有哪些点、哪个环、哪里折）仍然由模型声明（§2）。

## 2. 分工变了什么

| | 今天 | 这一案 |
| --- | --- | --- |
| 读题 | 系统抽条件（已在做） | 不变 |
| **声明图形结构** | 模型发动作，**含坐标** | 模型发动作，**不含坐标** |
| **算坐标** | **模型**（于是每次错得不一样） | **内核按题面条件构造** |
| 核验 | 系统 | 不变（仍是最终一关，构造器**不自证**） |

**模型剩下的活**：读懂这张图**是什么** —— 有哪些点、哪个环、哪里折起来。
这正是它擅长的；而它不擅长的"把条件解成坐标"拿走。

## 3. 机制：构造规格从哪来

复用**已有**那条通路，不新造平行词表：

1. `parseDiagramObligations` 已经从原话抽出 `givens`（§0.1 实测 8 条）；
2. `specForPrompt(prompt, givens)` 把这些条件推成一份**构造规格**（今天只认形状从句）；
3. `searchWitness(spec)` 造候选、逐条回代，选出满足全部可判条件的那一个；
4. 物化出来的坐标与点名**替换**模型给的那一份。

**这一案要补的是第 2 步**：给 `specForPrompt` 添一个**新的 family** ——
**由度量条件钉死的平面图形**（名字与字段在实施计划里定），形状是：

- `ring`：环上的点名（≥3，来自题面点名）；
- `conditions`：**从 `givens` 里筛出针对这些点名的那些**（`fixedLength` / `planarAngle` /
  `segmentRatio` / `equalLength` / `perpendicular` / `parallel`）—— **不需要模型复述**；
- 目标是 `z = 0` 平面上的坐标（立体构造是另一族，不在本期）。

**为什么复用而不是新建**：`specForPrompt` / `searchWitness` 这条路已经有形状从句、
底面构造、有界求根、逐条回代与"只回退内核源码就能证明判据能咬人"的浏览器证据。
另起一套的代价不是多写代码，是**同一件事有两个口径** —— 本仓最忌讳的那一类。

## 4. 一期：平面度量图形的构造

> **§4 的"闭式优先"已从假设变成读数（2026-10-11 探针实测，Task 0）。**
>
> 拿 §0.1 那五条四边形条件（`AB=8` / `AD=5√3` / `∠BAD=30°` / `∠ADC=90°` / `CD=3`）
> 按"先放 A 在原点、AB 沿 x 轴"的顺序闭式解，**逐条回代全部满足**：
>
> | 量 | 实测 |
> | --- | --- |
> | `\|AB\|` | `8` |
> | `\|AD\|` | `8.660254037844386`（`= 5√3`） |
> | `\|CD\|` | `3` |
> | `∠BAD` | `29.999999999999993` |
> | `∠ADC` | `90.00000000000001` |
>
> **多解与取哪一支也量过了**：`C` 由 `∠ADC=90°` 与 `CD=3` 定出**两个**解 ——
> `(9, √3)` 与 `(6, 4√3)`；"不许自交"（除相邻边外不许有边相交）**恰好留下一个**，即 `(9, √3)`。
> §4 那条"取不让四边形自交的那一支"因此是**可判的**，不是口号。
>
> **顺带量到的二期读数**（本步不依赖它）：`E = (3, √3)`、`F = (4, 0)`、`|EF| = 2`、
> **`EA·EF = −1.78e−15`（即 `AE ⊥ EF`）**、`|CE| = 6`。
> `AE ⊥ EF` 正是"`P` 绕 `E` 转、半径 `|AE|`"的来源，也是二期折的闭式旁证
>（`\|PC\|² = 48 + 36·cos θ`，`θ = 90°` 时恰为 `4√3`）。

**输入**：环（点名）+ 筛出来的度量条件。
**输出**：一组满足全部条件的坐标，或一条**可操作的**失败理由（§5）。

**方法沿用既有那套，不新造机器**：

- **能闭式解的就闭式解**（与 `deriveBasePolygon` 同一套：先定形、再落位）；
- **闭式拿不到的用有界求根**（与 `deriveApexHeight` / `solveDihedralHeight` 同一套：
  固定步数扫描 + 二分、取最小正根、无 RNG、可复现）；
- **逐条回代**：构造完必须对**最终坐标**逐条量一遍，构造成立 ≠ 通过；
- **多解要说明取哪一个**：本仓一律"取代表值 + 写进 `assumptions`"，
  而这里还要多一条 —— **取不让四边形自交的那一个**（那句题面的 `C` 有两个解）。

## 5. 失败三分（这一页必须回答的新问题）

构造失败时，三种成因**各自报清楚、不许含糊**：

1. **欠定**：条件不足以定形 ⇒ 说清**还差哪一类条件**（缺长度 / 缺角 / 缺关系），
   而不是"没找到"；
2. **矛盾**：条件互相不可能同时成立 ⇒ 说清**是哪两条、差多少**（"实测 90°，题面要求 60°"）；
3. **未覆盖**：这一类系统还不会造 ⇒ 如实说"这一族还没有构造器"，并**列出它认得哪几族**。

**禁止**：把"构造不出"降级成"未核验"（那是两件事，处置完全不同）；把"没找到"升级成"矛盾"
（与 `findContradiction` 那条既有纪律一致）。

## 6. 取舍（用户 2026-10-11 裁定：(a) 选"可选但永不静默采信"）

**坐标是"可选"还是"拿掉"？—— 本期选"可选，但永不静默采信"。**

- 构造成功 ⇒ **用构造的坐标**，并在报告里标明"坐标由系统按题面条件构造"；
- 构造不出 ⇒ 才退回模型坐标，**并且如实标注"这是模型给的、未经条件构造"**。

**为什么先这样**：这是本设计里**唯一会让现状变差**的地方。今天构造不出来时，
模型坐标至少还能画出一个（错的）图；若一上来就拿掉坐标，覆盖不到的地方会变成
**什么都没有**。先用"可选"拿到覆盖率，再谈关旧路（§8 三期）。

**"永不静默采信"是硬约束**：绝不出现"看着像构造成功、其实是模型坐标"的那一类静默成功。

## 7. 护栏（不许顺手打开的门）

1. **不许**用模型坐标冒充构造结果（§6 的落点，必须有判据钉住）；
2. **不许**把构造失败降级成"未核验"；
3. **关旗路径不动**：新 family 是**新增分支**，关掉即回到今天；
4. **不许**因为"反正要构造"就放开"按题面顺序猜坐标" —— 宁可失败；
5. **不许**顺手扩到立体族（那会同时动到底面构造与顶点模型那些既有支）。

## 8. 分期

- **一期（本次设计的实施目标）**：`specForPrompt` 的新 family + **平面度量图形的构造** +
  §5 的失败三分 + §6 的标注。**出口是拿到一个读数：同一句题面，B、C、D 能不能被系统自己造出来。**
- **二期**：**定比分点**（`E` 在 `AD` 上且 `AE:AD=2:5`）与**折**（把 `AEF` 绕 `EF` 折到 `PEF`）
  接进同一份规格。折的旋转原语已经导出（`rotateAboutAxis`），二期的活是把它接进构造规格。
- **三期**：**坐标从模型输出里拿掉**（§6 的"可选"改成"不给"）。**前提是一期的覆盖率读数够好** ——
  覆盖不到就关旧路，等于把"画错"换成"画不出"。

## 10. 明确不做

- **不新造一套平行词表**（复用 `specForPrompt` / `searchWitness` / 既有动作）；
- **不做立体图形的自动构造**（棱锥 / 棱柱那些由形状从句那条既有支走，本期不动）；
- **不做"模型完全不声明结构"的全自动推断**；
- **不碰"模型选错动作"那一类**（另议）；
- **不把"折至条件"的求解塞进一期**（那是二期，且它与 `fold` 的"折给定角度"是两件事）。

## 11. 出口（一期做完算完成的标准）

1. §0.1 那句题面能推出一份平面四边形规格，且构造出的坐标**逐条回代**通过；
2. §9 的每条判据都有用例，且**每条都先红过**；
3. §5 的三种失败**各有用例**（欠定 / 矛盾 / 未覆盖），文案可操作；
4. 护栏用例：构造成功用构造的坐标；构造不出时**不静默采信**；
5. 门禁全绿（定向 + 全库非 Lean + typecheck + lint + 全量 e2e）+ **变异**
  （把构造短路成"用模型坐标" ⇒ 判据红、还原复绿）；
6. 文档同步（当前状态 / 归档 / 本页状态行）与单独 commit。

## 12. 风险与回退

1. **最大风险是 §6 那条**：覆盖面不够时，用户从"画出一个错的"变成"什么都没有"。
   缓解：一期用"可选但永不静默采信"，并且**构造失败必须说人话**（§5）。
2. **第二个风险是"构造出来了但不是题面那个图"**（例如取了解的另一支）——
   缓解：逐条回代 + §4 的"取不合自交的那一支"，且核验器仍是最终一关。
3. **回退**：新 family 是**新增分支**；关掉它 = 回到今天（`specForPrompt` 对这类题面仍返回
   `unrecognised`，模型坐标照旧）。
