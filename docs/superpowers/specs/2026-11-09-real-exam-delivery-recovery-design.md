# 真题选择题交付链路恢复：设计

## 背景与边界

固定 50 题真实服务复测中，41 题无必答目标、22 题因作图核验不完整失败，成功交付仅 1 题。前次 31/50 采用不同入口，不能被当作当前入口的正确率基线。现有未跟踪的复测报告是调查依据；不更改其原始数据或事后评分口径。

目标是恢复“题目明确选择一项”的结构化目标和只读答题通道；不假定答案正确，不通过降低作图、图像证据或数学否证门槛获得虚高交付率。不在此版本改变默认灰度 0%、不启用第二模型、不自动提交草稿、不调用付费 provider 进行调试。

## 方案比较

- 关闭新验收或把失败标记改为成功：短期交付率好看，却将未读清图片、错误图形和被宿主否证的答案伪装成正确，拒绝。
- 所有数学选择题必须形式化证明：安全，但当前判据只覆盖有限题族，仍会在开放真题上大面积无法交付，适合作为逐步增强的证据等级而不是唯一答题出口。
- **推荐**：按用户意图区分“只读选择题答题”和“明确作图”。只读答案可以在没有独立数学证据时作为**未核验**交付；图像缺口、数学否证、目标缺项继续阻断；作图验收和用户确认不变。

## 合同

1. 从用户题面识别单选问法：稳定的 `( )` / `（ ）` / `$(\\quad)$` / `$(\\cdots)$` 空位，或有序 A/B/C/D 选项。只在单问选择题上合成一个 `single_choice` 必答目标；原有明确的多问、证明和明确作图请求保持原目标。目标 `sourceText` 与 `prompt.slice(start,end)` 必须一致，不从参考答案或选项正文制造题设。对不满足选择题结构的模糊数学请求依旧 fail closed。
2. 结构化选项严格只允许 A/B/C/D；若模型没有 `goalAnswers`，仅在自由文本具有唯一且明确的“最终答案：X”时转成候选，其他零散出现的选项字母不转换。模型提供错误 goalId、重复候选或非法结构时不偷换成可交付答案。
3. 选择题且用户未明确要求作图时，规划器只拿到只读答题能力；不把“如需图形辅助”的泛化提示理解为必须写入画布。实际要求画图时保留绘图工具、场景核验、待确认草稿，不跨越门禁。对于模型仍返回 `plan` 的情况安全失败，不静默抹掉动作再假装只读回答。
4. 无证据的答案等级必须显示“未核验”；宿主证据 `failed` 必须阻止交付；图像必要事实缺口必须转澄清，不猜；用户必须亲自确认任何待写入文档的草稿。

## 验证

- 离线冻结 50 题的题意/路由类别回归（开发集，不拿参考选项喂给解题入口），增加合并小问、证明、明确作图、无选项闲聊、错误目标 id、错误选择、图像缺口和宿主否证反例。
- 跑 agent-core、Web agent/services 相关单测、全项目 typecheck、docs gate；随后浏览器/桌面完整 UI 挑代表题验证显示等级和草稿确认。不把脚本退出码当成做题成功率。
- 若需要重新真实计费，在冻结修订、请求上限、单次运行防重复、题目逐题报告与用户授权之后，单独启动新批次；开发集改进后必须做不参与本轮改动的留出集，保留选项正确/成功交付/推导与图形核验分栏。

## 风险

OCR 可出现伪造选项、图示不确定项，选择题识别不能从选项内容推条件。某些题同时明确要求画图和选项，必须继续走双目标与作图门禁。新出口不能被模型空答案或仅“选 A”的散文绕过结构合同，不能宣称答案已验证。
