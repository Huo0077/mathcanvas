| 事实 | 说明 |
| --- | --- |
| 转换只针对**测量值** | 用户在"转换范围"一问里直接回答"只需要测量值"，所以扫的是 `document.measurements`，不是全部图元几何 |
| 形状 | 已确认：**A（切线无限长）bounded**、**B（数值转换）architectural** |

| 没有无理数机制 | 表达式求值是纯数值的（`sqrt` → `Math.sqrt`、`pi` → `Math.PI`）。**没有任何符号化的 √ / π 代数**，所以"无理数也能输出"是新写的识别算法，不是接线 |

## 2. 目标 / 非目标

**目标**

1. 切线（以及同族的法线）默认**画成无限长**、并且**按无界直线求交**；显式填过「切线半长」的仍然按填的值修剪。
2. 右侧属性栏**最上方**新增「精确形式」块：把文档里每个有效测量的数值转换成分数 / π 的有理倍数 / 二次无理数，识别不出就如实说未识别。

**非目标**

- 不扫图元几何（用户明确只要测量值）。点坐标、半径这些**不**进清单。
- 不做"用精确值替换文档里的数"：那会改变几何语义（把一个浮点半径换成符号值需要新的存储与重算路径），超出"转换"的范围。
- 不引入 CAS 依赖；不做嵌套根式与 e、ln 之类超越数（用户选的是深度 B）。
- 不改测量的求值精度，也不改 `Measurement3` 的存储（转换是**只读的展示层**）。
- 不动 3D 工作区的测量展示（面板对所有工作区都显示，但只有平面与立体**测量值**参与）。

## 3. 设计 A：切线无限长

### 3.1 规则（不新增字段）

**没有显式 `halfLength` 的切线 / 法线 ⇒ 无限长；填了 `halfLength` 的 ⇒ 有界（按填的值修剪）。**

- 为什么用这条规则而不是新增 `infinite?: boolean`：`halfLength` 只有用户手填才会出现在文档里，所以"缺省即无限"让**旧文档自动获得新行为**（正是用户要的），而想修剪的用户原样有手段；新增字段反而要写迁移与兼容分支。
- **取代上一轮的 ×1.5**：上一轮为"画长一点点"引入的 `CURVE_TANGENT_LENGTH_FACTOR = 1.5` 只在"缺省有限长度"下有意义。现在缺省是无限长，该常量对缺省路径不再生效 —— **实施时把它与它那条测试一并删除**，不留死代码；`curveTangentHalfLength` 若再无调用点也一并删掉。（如实记录：这是用户同一天内把需求从"长一点"升级为"无限长"的结果，不是遗漏。）

### 3.2 怎么表示"无限长"

`a` / `b` 仍然是文档里的字段（导出器、检查器、既有测试都用它），但**无限长时不再由 `halfLength` 决定**：

- 重算时把 `a/b` 写成 `point ± 10000` 世界单位（沿切向）。
- **刻意不按视口算**：视口一变就改文档，会让缩放/取景污染脏状态、撤销历史与"保存过没有"的判断。用固定的大长度足够覆盖任何实际视野（1e4 世界单位 ≈ 平面画布默认 1 格 = 1 单位的一万格）。
- 画布照旧画 `a→b` 这条线段：SVG 的 `viewBox` 会自然裁掉画面外的部分 ⇒ 看起来就是一条横贯视野的直线。
- **求交采样同样取这条长线段**（`samplePrimitive` 里切线/法线本来就取 `[a,b]`，长度变了、代码不变）⇒ "无限长"在求交上也成立。这也是用户上一轮"切线求交范围跟着画长变长"那条性质的延伸：现在它覆盖整个视野。

### 3.3 影响面

| 位置 | 改动 |
| --- | --- |
| `packages/scene-graph/src/operations.ts` | `recomputeCurveTangent` / `recomputeTangent`：无 `halfLength` 时用无限长常量；删掉 `curveTangentHalfLength` 与 `CURVE_TANGENT_LENGTH_FACTOR` |
| `packages/geometry-kernel/src/curve-intersections.ts` | 不需要改（采样只看 `a/b` 与 `status`） |
| `apps/web/src/components/PropertiesBar.tsx` | 「切线半长」文案改为「切线半长（留空＝无限长）」 |
| 测试 | 上一轮那条 `expected 4 to be close to 6` 的用例改为断言"缺省无限长、显式半长仍然修剪" |

### 3.4 边界

- 函数来源的切线同样变成无限长（定义域不再限定它的长度）。**这是有意的**：教科书里的切线就是一条直线；如果用户更想保留"只在定义域内"的样子，填一个 `halfLength` 即可。
- 退化的切线（`status !== "approximate"`）仍然**不画也不求交**（既有规则不变）。

## 4. 设计 B：数值精确形式转换

### 4.1 内核模块 `packages/geometry-kernel/src/exact-forms.ts`

纯函数、无新依赖；分数部分复用 `polynomial.ts` 的 `rational` / `rationalToString`。

```ts
export type ExactForm =
  | { kind: "integer"; text: string }                                  // 3
  | { kind: "rational"; text: string }                                 // 3/4、-7/2
  | { kind: "pi-multiple"; text: string }                              // π/4、2π、-3π/2
  | { kind: "surd"; text: string }                                     // √2、√2/2、(1+√5)/2、2+√3
  | { kind: "unrecognised"; text: string }                             // 未识别为精确形式（数值近似）

export interface ExactFormReading {
  form: ExactForm
  /** 精确形式的值，用浮点算出来的样子（用于与输入比较）。 */
  value: number
  /** |输入 − 精确形式|，识别不出时为 null。 */
  residual: number | null
}

export function exactFormOf(input: number, tolerance?: number): ExactFormReading
```

**候选族与顺序**（首个命中者胜，命中判据是 `|input − value| ≤ tolerance`）：

1. **整数**：`Math.abs(input − Math.round(input))` 在容差内。
2. **分数**：连分数展开求**最佳有理逼近**，分母上限 `maxDenominator = 64`（教学场景足够；再大就说明它本不是分数）。用 `rational()` 约分、`rationalToString()` 出文本。
3. **π 的有理倍数**：令 `t = input / π`，对 `t` 再做一次最佳有理逼近，分母上限 `12`（覆盖 π/12 的整数倍）。文本规则：分母 1 → `π` / `-π` / `2π`；分子 1 → `π/4`；其余 → `3π/2`。
4. **二次无理数 `(a + b√n)/c`**：对**平方自由** `n ∈ [2, 99]`、`c ∈ [1, 12]`、`b ∈ [-12, 12] \ {0}`、`a ∈ [-24, 24]` 做**有界**枚举。为省时间按"先简后繁"扫：先 `a = 0`（纯根式 `b√n/c`，即 √2、√2/2、3√3 这类），再一般情形。每步只是几次浮点乘加，总候选量 < 10⁶，实测应为毫秒级（实施时记录真实耗时）。
5. 都不中 ⇒ `unrecognised`，文本固定为「未识别为精确形式（数值近似）」。

**容差**：默认 `max(1e-12, |input| × 1e-9)`（相对 + 绝对）。刻意**紧**：宁可说"未识别"，也不要把 0.33333 硬说成 π/9。

**文本规范**（避免歧义，也让测试能写死期望）：
- 负号在最前：`-π/4`、`-3/2`、`-(1+√5)/2` 写成 `-(1+√5)/2`。
- 系数 1 省略：`√2` 不写 `1√2`；分母 1 省略：`2π` 不写 `2π/1`。
- 纯根式不带括号：`√2/2`；带整数部分才加括号：`(1+√5)/2`、`(3-√5)/4`。

### 4.2 界面：属性栏最上方的「精确形式」块

- 位置：`PropertiesBar` 渲染的第一个块（在「图元名称」之前），**不依赖选择**（没选中也显示）。
- 结构：
  - 标题「精确形式（数值转换）」+ 说明「按容差识别文档里每个有效测量的值；识别不出就如实标未识别。」
  - 表格：每行 = `测量名（来源 id 列表）` · `数值 + 单位（3 位小数）` · `精确形式` · `差值`；行尾一个「复制」按钮。例：`面积（circle-1）· 12.566 u² · 4π · 差值 1.5e-8`。
  - **测量名不在面板里再抄一份**：`Measurement3["metric"] → 中文名` 目前有**三份**副本（`planarMeasurementVisuals.ts` 的 `METRIC_NAMES`、`components/AlgebraView.tsx` 的 `measurementLabels`、`measurementVisuals.ts`（3D 测量标注）的 `names`），面板会把它提到共享模块 `apps/web/src/measurementLabels.ts` 并让这四处都从那里取 —— 否则这一轮就会造出**第四份**副本（本仓库刚刚因为"类型名单五处副本"吃过一次亏）。
  - 空状态：「还没有测量：先量一个长度 / 角度 / 面积。」
  - 读数（给 e2e 与排查用）：容器 `data-exact-form-panel="true"`，每行 `data-exact-form-row`，行上带 `data-exact-form-kind`（`rational` / `pi-multiple` / `surd` / `integer` / `unrecognised`）与 `data-exact-form-text`。
- 数据来源：`document.measurements` 里 `status === "valid"` 且 `typeof value === "number"` 且有限的项。**不**读图元几何。
- 复制：`navigator.clipboard?.writeText(text)`；不可用时按钮仍然存在且不报错（测试只断言"点了不抛异常 + 文案正确"，不断言剪贴板内容 —— jsdom 里没有真实剪贴板）。
- 折叠：沿用既有 `inspector-accordion` 的样式与键盘可达性（默认展开，因为用户要的"入口"）。

### 4.3 数据流

```
document.measurements ──filter(valid & finite)──► 每行
        │                                            │
        └── value: number ──► exactFormOf(value) ────┴──► 精确形式文本 + 差值
                                   │
                                   └── 内核纯函数（连分数 / π 倍数 / 二次无理数枚举）
```

一次渲染只算一遍（面板是纯展示，不进文档、不进撤销历史、不改任何状态）。

### 4.4 错误与退化

- 值非有限 / `status !== "valid"`：**不出行**（与"测量数字常驻画布"同一条纪律：不画假数字）。
- 识别不出：如实写「未识别为精确形式（数值近似）」，`data-exact-form-kind="unrecognised"`。
- 文档里一个测量都没有：显示空状态文案。
- 面板计算失败（任何异常）：该行显示未识别，**不**让异常冒到 React 渲染里（面板不能把整个属性栏带崩）。

## 6. 风险与边界

- **误报比漏报更糟**：`exactFormOf` 的容差取得紧（相对 1e-9），并且**族的顺序**保证"能当分数就不当无理数"。反例测试专门守这条。
- **枚举开销（原设计在此处被实测推翻，已改）**：本节最初写"有界枚举、应为毫秒级"。实测**最坏情况 114.9 ms/值**（`Math.E` 这类未识别的值会把约 70 万个候选全扫一遍），对一个每次重渲染都调用的面板完全不可接受。**改法：不枚举 n，而是由 `(a + b√n)/c = input` 反解 `n = ((c·input − a)/b)²`**，只需检查它是不是 [2, 99] 内的平方自由整数 —— 候选量降到约 1.4 万，且与 n 的范围无关。**改后实测最坏情况 0.561 ms、命中 0.006 ms**（同一台机器、同一探针；探针跑完即删）。最终是否命中仍由紧容差 `hit()` 把关，所以反解步骤里那点相对容差不会造成误报。
- **π 倍数与分数会不会打架**：`3.14159…` 的最佳分数逼近在分母 ≤ 64 内不成立，所以分数层不会先抢走 π；但 `π/4 ≈ 0.785398` 的某个分数逼近（例如 11/14）可能落在容差内 —— **实现顺序必须是"先 π 倍数再一般分数"**吗？不：0.785398 的最佳分数在分母 ≤ 64 内误差 ~1e-5 > 容差，所以顺序无关；测试里保留 `Math.PI / 4 → π/4` 一条以固定这个结论。
- **无限长切线 + 求交**：切线变成无限长后，与其它曲线的交点数会变多（以前落在可视段外的交点现在会出现）。这是"无限长"的定义使然，属于**有意**的行为变化，要在功能目录里写明。
- **旧文档**：`halfLength` 缺省的切线全部变成无限长（用户要的），逐位字段不变；`halfLength` 有值的文档一个字不变。
