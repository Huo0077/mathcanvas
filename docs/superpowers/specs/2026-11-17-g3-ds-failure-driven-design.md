# G3-DS 失败驱动升级设计（2026-11-17）

**状态：待实施设计，不是新的 DS 成绩。** 用户要求冻结36题真实 DeepSeek 作图尽力达到端到端36/36；任意未见题不承诺100%，不放宽合同、不按题号生成坐标。本设计接续 [旧 G3-DS 计划](../plans/2026-11-16-g3-ds-live-upgrade-plan.md)，以 [本轮真实36题审计](../../audit/2026-11-17-g3-ds5-live-36/README.md) 为负例基线。实际执行顺序见 [针对性实施计划](../plans/2026-11-17-g3-ds-failure-driven-implementation-plan.md)。

## 1. 问题事实与解释限度

| 门槛 | 2026-11-17 冻结36题原生 DS 强制规划 | 不能推断 |
| --- | --- | --- |
| 完整数学合同 | 0/36，3 partial、33 failed | 不能由离线36/36抵消，也不能断言“换模型必好” |
| 候选 | 10/36 非空、26/36 零候选；立体 1/18 有候选，平面9/18 | 10个候选不等于10个正确图 |
| 确定的工具冲突 | 7题读场景与 `plan_set_plan` 同一响应被原子拒绝，含历史曾通过的 GK-S08 | 不能外推到全部26个零候选 |
| 耗尽 | 28题使用单题3请求上限 | 不能断定再多重试有帮助 |
| 生产验收 | 9个非空候选 `not_supported`/partial、1个 failed/blocked | 不能把生产验收失败直接改为 pass；候选独立合同本身都没完整通过 |
| 可观察性 | 终态原因多为 `unclassified`；usage 91/93有报；实际账单未知 | 不可宣称各类失败根因占比或实际费用 |
| 交付 | 36题均未到待确认，DS候选真实画布/受控提交未运行 | `sceneWrites=0` 属于确认安全，不表示“无模型调用” |

**输入边界**：R4 终审对 `GK-S02/GK-S03/JT-S06/JT-S07` 保留 `text_with_figure_reference` 未知，详见[终审](../../audit/2026-11-17-g3-contract-review-r4/README.md)。如题图是唯一确定结构的必要信息，现有纯文字不能被模型/内核推断成真实图。Task 0 必须核对这四题的必要题图；缺图则要求用户补充、走已复核图像输入或诚实澄清。纯文字缺图不能承诺36/36；分母仍36，澄清仍计未通过。经用户核对的题图要固定版本与哈希，不把裁判答案注入模型；旧纯文字实测与R4审计原件均不改写。

本轮评测是临时桌面原生注入的强制 `ds_intent` 路线，不是产品默认确定性优先路径；受控输出是单候选的合同判断。已有正式评测对 `enumerate` 的 scope/state/branch 另有 `evaluateDrawingContractScopes`/`States`/`Branches`，但在 `MODE === "local"` 条件下才使用。这里存在**待证的评测口径分叉**：多状态题可能被误判；现有非空候选均未达合同，不得提前把0/36更改为通过。修正入口后保留旧结果并以新修订重新评测。

## 2. 设计取舍与优先级

- **选用**：工具能力分阶段发布 + 失败边界结构化记录 + 现有内核约束求解和来源验证 + 独立多状态裁判。最先用0付费复现已观察到的失败；每阶段只改一个共同根因。
- **不选**：在混合批次中“只执行读工具/只收计划”以换取数字，或仅加重试/提示词；这会产生部分执行、安全回退与不可解释成绩。
- **暂不选**：整体迁移 GeoGebra/SolveSpace/SymPy。前两者展示依赖构造与参数约束的工程思路，SymPy 提供解析求解参考，但引入其运行时与许可/部署风险需独立原型和审批，当前先复用本仓 `solver`、`DrawingIntent`、`ObligationIR` 与 `DraftStore`。

### 2.1 工具协议：先消灭我们自己制造的不可满足路径

**入口变更**：新建 `modelToolPolicy.ts` 纯函数，输入 `hasExistingGeometry`, `hasSelectedRefs`, `requiresSceneObservation`, `intentMode`，输出 `phase: "construct" | "observe"` 和允许发布的闭集工具。当前冻结集从隔离空白文档起跑；没有旧对象引用时仅发布 `plan_set_plan`（结构化施工单），不给无意义的 `scene_inspect`。已有对象确须观察时，第一轮只发布已注册的只读工具；观察结果回流后第二轮只发布 `plan_set_plan`。两轮各扣真实 network/generation；预算不足则安全拒绝，不能静默跳过观察。仍拒绝未发布工具、重复 call ID、混合读+写、畸形参数和取消后回写。**只有前置判据证实场景为空且题意不引用现有画布，才走构造阶段**，不靠“题号是GK-S08”判断。

**可证伪测试**：7个已观察混合调用题的脱敏 trace 重放，需证明空文档首轮不会发布读工具、正常 DS 施工单能被消费；另用真实已有场景与选区反例证明观察阶段不能提交、构造阶段不能再读。不能直接把历史批次“当作没发生”或削弱 `modelPlanner.test.ts` 的原子拒绝用例。

### 2.2 失败观测：记录第一处可负责的边界，而不是只有终态

统一 `G3CaseTrace`（位于 `apps/web/src/agent/fixtures/`）记录版本/题集hash/模型与profile修订、路由来源、模型是否真正发送、每请求工具名称及数量、预算扣减、工具回执、施工单解析诊断**码和字段路径**、DAG编译、stage、生产证书、独立合同、渲染和交付状态。每事件只存闭集码和引用 hash，不存模型正文、题干、密钥或工具原始输入。一次运行只要第一个失败码未被归因就不允许解释为“模型数学错误”；`unknown` 可暂留但必须进入排查队列，不能伪装 `passed`。跨层追踪以 runId/candidateHash 串联，取消/重启仍能恢复已写脱敏检查点。

### 2.3 施工单和约束：严禁补造决定数学答案的默认值

`DsDrawingIntent` 区分 display-only 自由度与数学必要参数；后者必须绑定有效的题设 sourceSpan/已验证推导/可公开给用户的假设，缺失返回 `missing_required_parameter` 而不是补表达式 `"x"`、切点 `0` 或默认区间。若用户题设确实欠定，给诚实澄清/不可行说明，**这在完整作图口径仍是未通过**。DAG cycle/missing-host/cross-scope 必须 fail-closed，不能在编译时退回原始步骤顺序。按失败义务族逐步补求解能力：先已出现的 GK-S05（立体27图元）、GK-P03/JT-P02（平面候选部分正确），并行归因26题零候选及另外7题错误候选；每族有非题号化变式和反例，不把冻结合同答案注入生成路径。

### 2.4 评测入口：生产和裁判在同一组 candidate/state/branch 下工作

建立 `FrozenDsCaseRunner`，输入 `case`、同版 provider/session、预算对象和 `candidateRenderBridge`，输出按 scope/state/branch 的 `CandidateSet` 与版本化结果；复用既有 `evaluateDrawingContract*`，**多问与多状态不强制折叠为单幅图**，缺任何必需分支即失败。生产证书与独立裁判都看同一 `CandidateSet` 的 hash，负例覆盖删一问、错状态、旧证书及候选替换。对照旧单候选与新同版集合口径只做诊断，不改写旧 0/36 历史证据。产品默认确定性优先另报，强制DS路线必须提供 DS 调用证明，不允许本地路由冒名。

### 2.5 层级验收与费用控制

零付费回放 → 有条件的新授权小样本（覆盖混合7题中的一题、历史正确 GK-S08、零候选立体、错误候选平面）→ 通过每层门禁后逐步扩至36题。请求/单题/序列化输入大小/输出 token 必须在提交前设硬闸；金额只能按已核实的官方价目表和严格的输入/输出上限做**保守估算**，若无法保证当前价格、服务端隐藏用量或其他可计费工具则停止并请求额外授权。实际 provider usage 不完整时费用记 `unknown`；价格上界不当作真实账单，也不声称程序能绝对控制服务商实际扣费。每题逐项计 `DS invoked`、`first attempt`、`bounded repair`、`contract`、`certificate`、`same-candidate browser render`、`controlled isolated commit/reload`、`humanReviewed`（只用户/教师可写）。旧36离线截图不能计入新的DS渲染；未见题与视觉警告另报。

## 3. GitHub 项目具体借鉴与不借鉴

| 项目（源仓库） | 只借机制 | 与当前问题的绑定 / 不做 |
| --- | --- | --- |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | 显式工具调用及状态流 | 借鉴“分阶段发布—执行—回传”组织；解决7个混合调用负例；不照搬整套代理框架 |
| [GeoGebra](https://github.com/geogebra/geogebra) | 构造对象及依赖更新 | 用于设计命名实体、派生点和源条件的依赖验证；不从其代码复制坐标模板 |
| [SolveSpace](https://github.com/solvespace/solvespace) | 参数化约束求解模型 | 为10题错误候选的联立条件/冲突解释提供参考；不直接加其二进制引擎 |
| [SymPy](https://github.com/sympy/sympy) | 求解后代回条件核验与不确定性的表达 | 借鉴验证纪律；不未经原型、部署及许可审查引入Python运行时 |

## 4. 总退出与止损

**分层目标而非口号**：阶段A先对全部36题记录可追责首失败边界；阶段B修复已证实7题工具混批路径且守住原子拒绝；阶段C逐族处理26零候选，结构上无法作图的题必须清楚标出题图/信息欠缺而不造值；阶段D 10错误候选达到全题合同+生产证书；阶段E经新授权的真实DS冻结36题同候选端到端36/36，再单列未见题。中间任何“部分正确”“可看见”“模型调用了”“离线绿”均不算完成。若一次改动使已通过题退化、安全拒绝失效或出现答案泄漏，立即回滚到可复现基线。产品发布另需用户/教师可读性与非沙盒桌面实机签收。
