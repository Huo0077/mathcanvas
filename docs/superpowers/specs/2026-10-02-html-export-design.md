# HTML 导出（自包含快照 + 可再导入存档）设计

**日期：** 2026-10-02 ｜ **状态：** 待用户审阅 ｜ **来源：** `current-status.md` §四 E 类第 3 项「HTML / GeoGebra 导出」中的 **HTML** 一半（GeoGebra `.ggb` 不在本设计范围内）

## 1. 用户工作与验收

用户画完一张图后，从导出菜单选**「导出 HTML」**，拿到一个 `.html` 文件。双击它，任何浏览器都能打开：看到标题、那张图、"**这次导出漏了什么**"、以及"怎么再打开"的说明。

把文件发给老师 / 同学时，对方**不需要装 MathCanvas、不需要联网**就能看图；若对方装了 MathCanvas，可以把 `.html` 直接拖回去，文档**原样回来** —— 标签、样式、参数都在。

**验收判据（都可复核，且不靠"看起来对"）：**

1. 打开后那张图与 `exportSvg(document)` / `exportEngineeringSvg(drawings)` 的产物**逐字一致**（就是同一段 SVG 内嵌，不是重画一遍）。
2. 文件里**零外部引用**：没有指向网络的 `src` / `href`、没有 CDN、没有外链字体。
3. 内嵌的 `.mgeo` 用 `decodeMgeo` 解回来，与原文档**深度相等**。
4. 有损失时，损失清单出现在**文件正文**里（不是只在导出界面弹一下）。
5. 标签里含 `</script>` 时，HTML 的结构不被破坏。
6. 一份 `.html` 里**只有一个** `<svg>`；且**内嵌的那个 SVG 内部不含 `id="…"` 属性**（这条是"已核实"的性质，不是要新加的约束：两个产出器都只用 `data-*`，见 §4 末尾。注意它约束的是 **SVG 内部**，不约束 HTML 自己 —— 存档块那个 `<script>` 是带 `id` 的，见 §5）。

## 2. 决定记录（2026-10-02，用户逐项确认）

| # | 问题 | 用户决定 |
| --- | --- | --- |
| 1 | 给谁、干什么 | **交作业 / 分享：自包含静态快照**（单文件、内嵌 SVG + 元数据、双击即开、不依赖本应用、不联网、不可交互） |
| 2 | 第一批覆盖范围 | **平面几何 + 工程制图**；立体几何 3D 画面留待后续单独决定 |
| 3 | 平面几何用哪个视野 | **复用 `exportSvg` 的标准视野**（固定 `WORLD_BOUNDS` / `VIEWBOX`，含 21×13 网格）。即"标准视图"，**不是**"我屏幕上当前这一张" |
| 4 | 要不要嵌 `.mgeo` 源 | **嵌** —— HTML 同时是快照与**可再导入的存档** |

**决定 3 的已知代价（如实记）：** 用户若平移 / 缩放过，HTML 里的图与他屏幕上看到的**不完全一样**。换来的是**可复现**：同一份文档永远得到同一张图，验收判据也好写。"当前屏幕视野"是一条独立的后续增强，不在本批。

**决定 4 的已知代价（如实记）：** 文件变大；且文档 JSON（含用户的标注与标签）对收件人**可见**。这是用户明确选择的取舍。

## 3. 方案与边界

**采用 A 方案**：新增 `apps/web/src/persistence/htmlExporter.ts`，**组合既有的两个 SVG 产出器**，不新画几何；在两个 `ExportFormat` 联合里加 `"html"`；命令层加 `export-html`；**继续走既有导出预检**。

被否掉的方案：

- **B（先统一两处重复的 `ExportFormat` 与导出管线，再让 HTML 当普通格式接入）** —— 长期更干净，但要动**导出闸门本身**，diff 大、风险高，本批不需要。**YAGNI**。
- **C（用独立 HTML 模板文件 + `?raw` 引入）** —— 模板好改，但引入构建期资源与转义边界；本批模板很小，不值得。

**本批明确不做：**

- 不做交互（拖点、联动数值）——那是"可交互"那条路，是另一个量级。
- **不做立体几何 3D 画面**（画布是 WebGL，没有 SVG 产出器；"截图 PNG 还是走工程正投影"是一个尚未决定的独立问题）。
- 不做样式定制 / 主题 / 字体选择。
- 不做多文档打包（一份 HTML 只装当前这一个文档）。
- 不做 GeoGebra `.ggb`（本设计只覆盖 E 类第 3 项的 HTML 一半）。

## 4. 产物结构

单个 `.html`，UTF-8，自包含。`<head>` 只有 `<meta charset>`、`<title>`、一段内联 `<style>`。正文四块，顺序固定：

1. **标题块** —— 标题取 **`document.metadata.name`**（实测 `packages/dsl/src/types.ts:955`：`DocumentMetadata = { id, name, createdAt, updatedAt }` —— 字段叫 **`name`，不是 `title`**；而且 DSL 自己保证有值，默认 `"Untitled geometry"`，所以**不需要**我再编一个"基于日期的默认名"）；再加导出日期、工作区名、图元计数。
2. **图块** —— 按当前文档的工作区选产出器：
   - 平面几何 → `exportSvg(document)`
   - 工程制图 → `exportEngineeringSvg(drawings)`
3. **"这次导出漏了什么"** —— 来自既有预检 `exportService` 的 omission / WinAnsi 丢字 / 不可投影条目，渲染成人能读的列表；**无损失时明确写"无"**。
4. **存档块** —— 内嵌 `.mgeo`，加一句"怎么再打开"。

结尾写**格式版本**与**应用版本**：没有这两个号，以后认不出这份文件是哪一代产物。

**已核实的两个事实（决定了这个结构是可行的）：**

- `exportEngineeringSvg(drawings: ProjectedDrawing[]): string` 把**四视图放在同一张 SVG** 里 —— 所以工程制图那半个也只内嵌一个 `<svg>`。
- 两个产出器**都不使用 `id="…"` 属性**（只用 `data-*`）—— 所以内嵌时**没有 id 冲突**风险。

**第三个工作区（立体几何）必须先定行为 —— 这一条是复审时实测发现的，原写法会踩坑**

实测 `apps/web/src/persistence/fileExports.ts:95-97`：SVG 出口的分支条件是 **`getDocument().workspace === "cad"` 才走工程产出器，否则一律走平面的 `exportSvg(getDocument())`**。于是：

| 工作区 | 现行走哪一支 | 本批是否覆盖 |
| --- | --- | --- |
| `cad`（工程制图） | `exportEngineeringSvg(drawings)` —— 四视图 | ✅ 覆盖 |
| 平面几何（`geometry` / `conics`） | `exportSvg(document)` | ✅ 覆盖 |
| **`geometry3d`（立体几何）** | **也落进"否则"那一支**，会用**平面**导出器去导一份 3D 文档 | ❌ 不在本批 |

而平面导出器**刻意不投影 3D 图元**（`exporters.test.ts:79` 的断言与注释写着 "planar SVG is not a fake 3D sphere projection"）。所以照现有分支直接做，用户在立体几何里点导出会得到：**导出"成功"、HTML 里只有一个坐标网格、没有任何图形** —— 正是本仓库最讨厌的"静默半死"。

**因此本批要求（硬性）**：在 `geometry3d` 工作区点"导出 HTML"时**明确拒绝** —— 走既有 `setFileError` 通道给一句人话（例如"立体几何画面的 HTML 导出不在本批范围"），**而不是**吐出一份空 HTML。并且要有测试钉住：**3D 文档导出 HTML → 报错且不产生下载**，**配反向对照**（平面几何文档 → 正常产出）。

## 5. 安全与诚实性（硬约束，不是"最好做到"）

1. **转义一切文档派生文本**：标题、标签、注释文本进入 HTML 前必须转义（`<`、`&`、`"`）。
2. **内嵌 JSON 必须把 `<` 写成 `\u003c`**。原因是具体的：用户标签里完全可以出现 `</script>`，那会**提前闭合脚本块**，后面的文档内容就变成了可执行的 HTML —— 这是**注入**，不是理论风险。
3. **损失必须落进文件**：只在界面上提示一次是不够的。收件人拿到的是图，他有权知道"有几个对象没进来"。
4. **id 约束**：本批两个工作区互斥，所以不会出现两个 SVG 同时在文件里。若**将来**有一批要把两张 SVG 放进同一份 HTML，必须先把内部 `id` 加前缀（这份约束写在这里，是为了让那一批的人知道要处理）。

| 范围 | 必须看到的证据 |

| 工程制图导出 | 单测：产物含 `exportEngineeringSvg(drawings)` 的输出；四视图标签（主 / 俯 / 左 / 轴测）都在 |

## 7. 发布边界

本设计只交付**当前 `main` 的源码能力**。它**不**改变桌面安装包的主张：`v3.1.0` 已经发布，本次 HTML 导出若之后要随安装包发出去，需要一个**新的版本号**、从确定的发行提交重打、并核对哈希 —— 与 `docs/release/v3.1.0.md` 同一套口径。设计通过或 CI 变绿**都不等于**"已经发布了含此功能的新安装包"。

## 8. 未决与风险

- **未决**：立体几何 3D 画面要不要进 HTML（若进，"当前视角截图 PNG"与"走工程正投影生成 SVG"是两条不同的路）。本设计**不覆盖**，等第一批交付后再决定。
- **风险**：产物里的格式版本号一旦定下就不该随意改；改动要按版本号区分，否则老文件认不出。
- **风险**：`exportSvg` 会画网格。本批**沿用**（与现有 SVG 导出行为一致）。要"不带网格"是另一个决定，不在本批。

**一个必须现在就定的取舍（否则它会变成"忘了"）**

第 8 处是 **Agent 提议导出**的那条通道。本批**不让 Agent 提议 HTML 导出** —— HTML 是"给人看 / 分享"的产物，而那条通道现有的形态是"提议导出并把结果回给模型"，要加就得连带设计"模型拿这个 HTML 干什么"，属于另一个话题。

**但"不做"要写成有意的"不做"，而不是漏掉**：实施计划里必须有一条**明确判据** —— Agent 的格式联合**保持四个不变**，并有一个测试钉住它。否则下一个人看到两个联合不一致，会以为是 bug 顺手"修齐"，反而破坏本批边界。

**为什么单列这一节**：如果只改第 6、7 处就以为做完了，结果会是**菜单里点不到**（缺 1、2）或**工具栏不给用**（缺 5）—— 功能写完了却摸不着，这正是本仓库踩过多次的坑。

## 10. 三件"实现前必须知道"的实测事实（免得计划里写错）

1. **标题字段叫 `name`，不叫 `title`** —— `packages/dsl/src/types.ts:955` 的 `DocumentMetadata` 是 `{ id, name, createdAt, updatedAt }`。DSL 自己会给默认值（`codec.ts:40` 的 `"Untitled geometry"`），所以**不需要**自造默认名（§4 第 1 条已按此更正）。
2. **现成的转义函数是模块私有的，拿不到** —— 实测 `apps/web/src/persistence/engineeringExporters.ts:76` 的 `escapeXml` 与 `exporters.ts` 里的同名工具**都没有 export**。所以 HTML 导出器**不能直接复用**它们：要么在本模块自带一个转义函数（并给它自己的单测），要么先把其中一个导出出来。**这是一个要写进计划的决定**，不能含糊过去 —— §5 第 1 条要求"转义一切文档派生文本"，而做这件事的工具现在够不着。
3. **应用版本：走桌面外壳那条桥，而且它就是产品版本**（这条原本我写着"没核实"，现已实测解决）—— 链路是 `apps/desktop/src-tauri/src/commands/providers.rs:282-295`：`let version = app.package_info().version.to_string();` 再交给 `runtime::build_runtime_info(&version, …)`；Tauri 的 `package_info().version` 取自 **`tauri.conf.json` 的 `version`**，也就是**发布时我改的那个产品版本**（当前 3.1.0）。`runtime.rs` 里那一堆 `"0.1.0"` 是**单测夹具**，不是真值。
   **但仍有一档要如实处理**：浏览器（非桌面外壳）里拿不到这条桥，`desktopRuntime.ts` 会给出 `"unknown"`（其单测 `:85` 明确钉了这一档）。所以产物里的版本戳要**如实写 `unknown`**，不编号、也不省略。
