# 空间"线重合"的判据与求解（`coincident`）—— 设计

> **状态（2026-10-10）：设计已写，未实施。** 这一页只定设计、不动代码。
> 它是「下一步计划」§3-F「具体缺口（代码层，按需排期）」里**最后一项**：
> "空间'线重合'的**求解**（今天只安全拒绝）"。
>
> **这一页查出一件改变优先级的事**（见 §0.3）：**今天没有任何产品入口能声明一条空间重合约束** ——
> 解析层不产出它、Agent 动作表里没有它、界面上没有约束编辑器。所以这一项的现状不是
> "用户看得见但做不出来"，而是"**这条约束只能从外部文档进来**"。
> 因此本页的结论是：**判据与求解都值得做，但必须先决定入口**（§5）。

## 0. 今天到底发生什么（**探针实测 + 读码**，不是推测）

### 0.1 内核那一侧：没有判据；而且**两个诊断入口对同一份文档给两个答案**

探针（2026-10-10 实测，跑完即删）拿两条**异面**线段建一条 `coincident` 与一条 `parallel`：

| 读数 | 实测 |
| --- | --- |
| `constraintResidual3(coincident)` | **`null`** |
| `constraintResidual3(parallel)` | `0.7071067811865475`（**无量纲**：`\|u×v\|/(\|u\|\|v\|)`） |
| `diagnoseConstraints3([coincident, parallel])`（**复数**那个） | **只返回 `parallel` 那一条** —— `coincident` 被 `filter` 掉了，**不是**返回"未核验" |
| `diagnoseConstraint3(coincident)`（**单数**那个） | 返回一条诊断：`residual: null`、`satisfied: false`、说明文字 `"缺少有效空间来源，无法计算约束残差。"` |

**这两行合起来才是准确的事实**（第一版这里写成"下游分不清 ⇒ 所以拖动只能一律拒绝"，**因果说错了**，见下）：
同一份文档，**单数**入口说"这一条算不出来"，**复数**入口干脆不提它 —— 两个公开 API 对"文档里有没有一条没判过的约束"给出**不同答案**。
`diagnoseConstraints3` 目前只有两个消费者：`solvePoint3Constraints`（**只有用例在用**）与 `relations.test.ts` 的同源核对，
所以这是**一处潜在的口径分叉，不是今天拖动拒绝的原因**。

### 0.2 拖动那一侧：碰到就拒绝，原因是**它被分类成 `planar-only`**（与上面的诊断列表无关）

`apps/web/src/constrainedDrag3.ts` 用 `isPlanarOnlyConstraint3` 把约束分成两拨：
平面那一拨（就是 `coincident`）**不参与 3D 求解**；一旦被拖的点与它沾边，
就返回 `unsupported_spatial_constraint`（文案来自 `constraints3dProjection` 的 `skipped` 条目，
里面写着 `planar-only` 的理由）。**没沾边的拖动照旧通过**，注脚写"N 条平面约束不参与 3D 拖动"。
也就是说：**拖动层读的是那张 `planar-only` 分类表，不是 `diagnoseConstraints3` 的返回值** ——
把 §0.1 那条分叉修好，**不会**自动改变拖动行为；拖动那一侧要改的是分类表本身（§2 阶段 A）。

### 0.3 入口那一侧：**今天没有入口**（这一条改变这一项的优先级）

| 可能的入口 | 事实 |
| --- | --- |
| 题面解析 | **不产出** `coincident`：`diagramObligations` 的关系种类里没有它；`witnessSearch` 的注释直说这一类"**根本没有对应类型**" |
| Agent 动作 | `actionIds.ts` 的 `DRAFT_ACTION_IDS` **没有**约束类动作（`addConstraint` / `deleteConstraint` 只在 scene-graph 的**领域操作**层，不在模型的工具表里） |
| 界面 | `apps/web/src` 下**没有**约束编辑器组件（`*onstraint*` 一个文件都没有；约束只在属性栏的分区名里出现过） |
| 能力登记 | `capabilities.ts` 把 `constraint-authoring` 记为 `available`（平面 + 立体，前提"目标在同一文档里"）—— 也就是说**能力表说它可用，而产品面上没有一处能创建它** |

**结论**：空间 `coincident` 今天只能从**外部/程序构造的文档**进来（夹具、导入、e2e 里直接写 store）。
所以这一项的现状不是"用户点了没反应"，而是"**没有用户路径**"；判据与求解做出来之后，
**第一条能看见它的用户路径仍然不存在**。

### 0.4 二维那一侧早就有规则（3D 要照它，而不是另发明一套）

`packages/geometry-kernel/src/constraints.ts` 的 `projectLineConstraint(first, second, "coincident")`：
**第二条线的方向对齐第一条 ⇒ 把第二条线的中点投影到第一条直线上 ⇒ 保长重算两端点**。
"3D 里没有唯一投影"这句注释（`constraints3dProjection.ts:149`）说的其实是
"**没有唯一的最小改动**"—— 二维那条规则本身也是一个**决定**（保长 + 中点投影），不是什么必然。

## 1. 语义（必须先钉死，否则判据会各说各话）

1. **"线重合"指的是两条线所在的直线重合**，不是"两条线段首尾相接"、也不是"端点落在对方之内"。
   判据只有两件：**方向平行** + **一条线上的某个点落在另一条线上**。
   端点是否落在对方**内部**属于 `pointOnLine` / `collinear`，**不在**这一条的语义里。
2. **残差无量纲**（与 `parallel` 同一把尺子，1e-6 的默认容差才有意义）：
   `residual = max(方向项, 位置项)`，其中
   - 方向项 = `|u×v| / (|u|·|v|)`（与 `parallel` 的残差**同一个式子**）；
   - 位置项 = `dist(第二条线上的一点, 第一条直线) / 尺度`，点取**第二条线的中点**（与二维那条规则同一处取法）；
   - **尺度 = 形状尺寸**（不是坐标量级）—— 与面环判据那两种尺度同一条口径：
     浮点噪声 ∝ 坐标量级，几何退化 ∝ 形状尺寸。
3. **退化一律"未核验"、不当成满足**：任一条线长度为 0（端点重合 / 缺来源）⇒ 残差 `null`
   ⇒ 沿用既有的 `"缺少有效空间来源，无法计算约束残差。"`，**绝不**返回 0。
4. **不许把"平行"偷偷当成"重合"**：方向项与 `parallel` 相同，所以**只判方向必然把"平行但异面"说成重合**
   —— 位置项是这一条约束的**存在理由**，不是补充。

## 2. 分两期（判据 / 求解），每期各自可独立收口

### 阶段 A：**判据**（把"没判过"变成"判过"）

- `constraintResidual3` 补 `coincident`（按 §1 的式子）；
- `diagnoseConstraints3`（复数那个）**不再 `filter` 掉它** —— 让两个诊断入口对同一份文档给**同一个答案**
  （今天单数说"算不出来"、复数不提它；`solvePoint3Constraints` 与 `relations.test.ts` 是它的两个消费者）。
  这一条是**口径统一**，不是拖动行为的原因（§0.1/§0.2 已说清）；
- 那两份 `NO_SPATIAL_JUDGE`（`constraints3dProjection.ts:121` 与 `constraintIR.ts:75`）与拖动层的
  `isPlanarOnlyConstraint3` **必须一起重新决定**，而且**只留一处真源**（现在两处各写一份，
  文件里已有注释承认这是"同一个判断写两遍"）；
- **用户可见的行为变化**：被拖的点与重合约束沾边时，
  ① **保住重合的拖动从"一律拒绝"变成"照旧通过"**；② 破坏重合的仍然拒绝，
  但文案从"这条约束没有空间判据"变成**"这次拖动会让 `AB` 与 `CD` 不再重合（残差 …，容差 …）"**。

### 阶段 B：**求解**（照二维那条规则）

- 规则（与二维**逐条对应**，不另发明）：第二条线**方向对齐**第一条（按它当前朝向定符号，避免翻转）
  ⇒ 它**中点**投影到第一条直线（`projectPointOntoLine3` **已经有了**）⇒ **保长**重算两端点；
- `CONSTRAINT_PROJECTION_DECISION.coincident` 从 `planar-only` 改成 `project`
  —— 那张表是 `Record<ConstraintType, …>`，**改它编译器会逼着人重新决定**（当年把它写成 `Record` 就是为了这一刻）；
- **只动自由点**：锚点由既有的 `anchoredPointIds` 决定；对齐或平移需要动锚点时**如实拒绝**，
  与这一层其它约束同一条账（`unsatisfied` / `exhausted` 那一套照旧）；
- 求解**成功 ≠ 通过**：最终坐标仍由核验器 / 判据自己再量一遍（构造与判定分开，这条在本仓是硬规矩）。

## 3. 失败三分（与阶段 B（B1）那张表同型）

| 结局 | 什么时候 | 说什么 |
| --- | --- | --- |
| **满足** | 残差 ≤ 容差 | 报出残差（既有的"约束已满足，残差 …"格式） |
| **不满足** | 残差 > 容差 | 报出残差与容差，并**指名是哪一项超了**（方向 / 位置）—— 用户要能分辨"不平行"与"平行但错开" |
| **未核验** | 线退化为零长 / 来源缺失 / 求解要动锚点 | 沿用既有"缺少有效空间来源"；**绝不**降级成"满足" |

## 4. 护栏（不许顺手打开的门）

1. **不许把"重合"降级成"平行"**（§1.4）。判据必须有一条**平行但异面**的反例用例，它**必须红**。
2. **三处 `planar-only` 必须同步**（§2 阶段 A）：不同步就会造出"内核说有判据、拖动层说没有"
   这种最难查的分叉 —— 本仓已经为此吃过一次亏（两处各写一份的注释就是那次留下的）。
3. **阶段 A 与阶段 B 的用例分开改**：`constraints3dProjection.test.ts` 现在同时钉着
   "`coincident` 是 `planar-only`"与"它不在 `PROJECTABLE` 里"两条断言。阶段 A 只该动前者，
   一次把两条都改掉会让"我们到底做了哪一期"读不出来。
4. **关旗路径不动**：约束拖动是实验开关后的能力，关着时一行行为都不变。
5. **能力表与入口的一致性**：`capabilities.ts` 说 `constraint-authoring` 可用，
   而产品面上没有入口（§0.3）。这一条**不许**在这一块里悄悄"修好"（那不是判据或求解的事）——
   要么单独立项做入口，要么把能力表的措辞改成"操作可用、界面入口未做"。

## 5. **这一页最重要的结论：先决定入口**

判据与求解都做得出来（二维有现成规则、三维只差两处改动），但**做出来也没有用户路径**（§0.3）。
所以推荐顺序是：

1. **先裁决入口**（三选一，各自代价不同）：
   - (a) **题面入口**：给解析层加一条"直线重合"的说法（要新语义、要与 `parallel` 区分、要能被核验）；
   - (b) **Agent 动作入口**：把 `addConstraint` 登记进 `DRAFT_ACTION_IDS`（要 schema、要能力校验、
     还要回答"模型为什么该被允许加约束"）；
   - (c) **界面入口**：约束编辑器（最贵，且要把"约束"这个概念讲给高中生听）。
2. **入口定了之后**，按本页 §2 做阶段 A（判据）→ 阶段 B（求解）。

**没有入口之前，这一项按"已设计、暂不实施"记账** —— 这也是本页存在的主要价值：
下一个接手的人不用再把 §0 的四件事重查一遍。

## 7. 风险与回退

1. **最大风险与角度那两块同型**：把"没有判据"变成"通过"。所以判据必须自己算（不读构造方自述）、
   必须有"平行但异面"的反例，且**退化必须落未核验**。
2. **第二个风险是 `planar-only` 的三处分叉**（§4.2）：处理办法是"一处真源 + 一条钉住它的判据"。
3. **回退**：阶段 A 只把 `null` 换成数值 ⇒ 不认识它的旧调用点仍然安全（它们本来就按"没判据"处理）；
   阶段 B 只改 `Record` 的一个取值 ⇒ 回退就是把它改回 `planar-only`。
4. **尺度选错会让判据在大小悬殊的图上失真**：所以 §1.2 明写"形状尺寸"并配一条**整体缩放不变性**用例。

## 8. 出口（做完算完成的标准）

1. 阶段 A：`coincident` 有**空间判据**且出现在诊断列表里；拖动的两种结局（保住 / 破坏）各有浏览器或
   单元判据；扩展名（`constraints3dProjection` / `constraintIR` / 拖动层）三处同一个答案；
2. 阶段 B：投影规则与二维**逐条对应**，锚点不可动时如实拒绝；`PROJECTABLE` 随之变化且有用例钉住；
3. 门禁全绿（定向 + 全库非 Lean + typecheck + lint + 全量 e2e）+ **变异**
   （把位置项短路 ⇒ "平行但异面"那条判据当场红、还原复绿）；
4. 文档同步（当前状态 / 归档 / 本页状态行 / 下一步计划 §3-F）与单独 commit + push + `git ls-remote` 核对。

## 9. 明确不做

- **面重合 / 实体重合**（`coplanar` 已经有了，面"重合"是更强的说法，单独一类）；
- 把二维的 `projectLineConstraint` 换成**最小二乘**（那是另一条规则，会让二维行为也变）；
- **泛化约束求解器**（R18 照旧：一个未知量、有界、固定步数、无 RNG 之外的不做）；
- **在本块里顺手造入口**（§4.5 / §5）：入口是一个独立决定，不是判据或求解的副产品。
