# 平面数值角条件（`∠ABC=60°`）—— 设计

> **这一页只定设计，不动代码。** 落点、判据清单与风险在下面逐条写清；实施按本仓的收口清单另开区块。
> 它是「下一步计划」§3-F 里"底面点名数值角"那一项的第一步 —— 那一项今天**如实拒绝/未核验**，
> 而"大部分高中立体题都能画"这个用户裁决绕不过它。

## 0. 要解决什么

`∠ABC=60°` 这类句子在高中立体几何题面里极常见，而今天它**整句落进 `unverified`**
（`diagramObligations.ts` 的 `UNREAD_CONDITION` 正则接住它）。后果不是"画不出来"，而是
**整题永远有一条条件未核验** —— 用户看到的是一句"这条我没核"，而不是"这条对不上"。

这一页要定的就是：**把它读成一条一等条件**，并说清哪一半现在能做、哪一半不做。

## 1. 现状（读代码得到的事实，不是推测）

| 事实 | 落点 |
| --- | --- |
| 见证关系有五种 kind：`perpendicular` / `parallel` / `equal-length` / `segment-length` / `dihedral` —— **没有平面角** | `packages/geometry-kernel/src/witness/constructors.ts` 的 `WitnessRelation` |
| 题设种类里有 `dihedral`（**二面角**）与 `perpendicular` / `parallel`，**没有平面角** | `packages/agent-core/src/diagramObligations.ts` 的 `DiagramObligationKind` |
| `∠ABC=60°` 由 `UNREAD_CONDITION` 接住 ⇒ 进 `unverified`，并被四条用例 + 一条 benchmark 案例钉住 | `diagramObligations.ts:328` 起；用例见 §5 |
| **量角的工具早就有**：`angleBetween(vertex, first, second, "interior")`、`measureAngle3`、反应式那边的 `angleBetween(points[1], points[0], points[2])` | `dynamic-measurements.ts` / `measurements3d.ts` / `reactive/derivedNodes.ts` |

**一句话结论**：**判据那一侧几乎是白送的，难的是构造** —— 而构造在两个底面族上本来就是闭式的
（环首直角 ⇒ 矩形、菱形取代表角、直角梯形取两条不等的高），所以"底面环上的角"这一支可以现在就做。

## 2. 语义（必须先钉死，否则判据会各说各话）

1. `∠ABC` 是**以 B 为顶点、BA 与 BC 两条射线的内部角**，取值 `(0°, 180°)`；
   `180°`（三点共线同向）与 `0°`（退化）一律拒绝，**不当成"等于 0 的角"放行**。
2. **不许与"两条直线的夹角"混用**：后者取 `[0°, 90°]`。同一个 `∠ABC=120°` 在两种读法下
   **是不同条件**，而画面上两条线看不出区别 —— 这正是"判据写混了不会红"的那一类。
   所以新的 kind 叫 `planarAngle`（带顶点与两条边），**不叫** `angle`。
3. 只收 `∠` + **三个点名** + `=` + 度数值（可带 `°`）；点名后缀按 S1 的词表（`A′` / `A₁`）。
4. **单位只收度**。题面写弧度（`∠ABC=π/3`）今天不认，如实落 `unverified` ——
   "认不出 ⇒ 未核验"这条纪律不因为多了一种单位而松动。
5. 三个点名必须**互异**且都出现在同一张点名表里；否则如实拒绝（那是写法错误，不是几何条件）。

## 3. 分两期

### 阶段 A：**底面环上**的角（本期设计的目标）

- **读**：`∠ABC=θ°` 且 A、B、C **都在底面环上** ⇒ 新 `DiagramObligationKind: "planarAngle"`
  （`targets: [A, B, C]`、`value: θ`）。
- **构造**：新 `WitnessRelation` kind `planarAngle`
  （`{ kind: "planarAngle", targets: [A, B, C], value, unit: "degree" }`），在
  `deriveBasePolygon` 里按**闭式**放：B 处的两条邻边，一条方向已定（底面起点），另一条按 θ 旋转。
  其余自由度（边长、另一条边）取代表值并写进 `freeValues` / `assumptions` ——
  与"环首直角 ⇒ 矩形""菱形取代表角 60°""直角梯形取两条不等的高"**同一条口径**。
- **不许取 0/180**：θ 落在那两个端点时拒绝（`degenerate-base`），不是"画一条直线当角"。
- **判据**：核验器对 `planarAngle` 逐条量（自己算 `angleBetween`，**不读构造过程的中间量**），
  结论里**写出量到的度数**："∠ABC 实测 57.31°，题面要求 60°"。
- **能做的边界**：三角形 / 四边形底面闭式可做；**五边形以上**（走 `deriveRepresentativePolygon`
  代表正多边形）与"角的两条边有一条不在底面环上"**仍旧拒绝或未核验** ——
  与既有底面条件同一条口径（正 n 边形满足不了一个指名的角，不换形状）。

### 阶段 B：涉及顶点或环外点的角（**本期明确不做**）

`∠PAB` 这类角里有环外点（顶点 `P`）⇒ 要**有界求根**（与二面角的 `solveDihedralHeight` 同一套：
对内核自己的度量求根、有预算、超预算如实报"未核验"而不是给个近似值）。它值得单独一页设计，
因为它要回答"求根失败时这一条算什么"这个新问题。

## 4. 明确不做（写在这里，免得下一轮又讨论一遍）

- `sin∠PAB = 0.5` / `cos∠ABC = 1/2` 这类**三角关系**：那不是角本身，而是它的函数值 —— 单独一类；
- 用角条件把**侧棱方向**钉死（`∠A′AB=60°`）：**早就裁决不做**（要"环外点名顶点"概念 + 角度求解）；
- 弧度、角度制混写；
- `∠ABC = ∠DEF` 这类**两角相等**（关系而非数值）；
- 泛化的"任意角约束求解器"。

## 6. 风险与回退

1. **最大的风险是"从'未核验'变成'通过'"**：那会把一条今天如实标未核验的条件变成绿。
   所以：判据必须**先能判、判得过才通过**（核验器自算，不读构造方自述），
   且**构造不出来的形状一律拒绝**（绝不静默换一个题面没说的形状 —— 这是本仓最忌讳的那条）。
2. **关旗逐字契约**：`obligationIR` / `witnessSearch` 关着时路径不变（角条件不进那条路）。
   开旗路径的 golden 若动，按 P2-C 那次的口径：**先逐字段证明差异范围**，再决定是否重抓，
   并把修订写进样本的 `revised`。
3. **回退**：新 kind 是**新增**，不认识的旧数据不受影响；解析若读错，症状是"这条条件未核验"
   （与今天完全一样），不会更坏。这也是为什么这一支可以安全地先做小的那一半。
4. **一条容易被忽略的边界**：底面环上的角可能**与其它条件矛盾**（例如同时点名"环首直角"与
   "`∠DAB=60°`"）。这一支必须**拒绝并说出矛盾在哪**，而不是先满足一个再看另一个 ——
   与直角梯形那一支"两条高度给了不同值就是自相矛盾，如实拒绝"同一条账。

## 7. 出口（做完算完成的标准）

1. 底面环上的 `∠ABC=θ°` **能读、能构造、能核验**，且**实测度数写进结论**；
2. **满足不了的形状拒绝**：至少两类用例 —— 五边形以上（正 n 边形代表满足不了）、
   以及**与其它条件矛盾**的那一类；
3. 四条既有"未核验"用例改成新语义并逐条说明；benchmark 码表如实重记（若动）；
4. 门禁全绿（定向 + 全库非 Lean + typecheck + lint + 全量 e2e）+ **变异**
   （把角的构造短路 ⇒ 判据红、还原复绿）；
5. 文档四处同步（当前状态 / 归档 / README / 发布门禁）与单独 commit + push + `git ls-remote` 核对。
