# 轨道圆：独立的空间圆 + 画布缩放（设计）

> **状态（2026-09-17）**：用户已确认方向并批准方案。设计要点由用户拍板两处：①圆**自带圆心坐标**、是独立对象（不保留"圆心是某个点"的引用，也不加锁定开关）；②开工范围包含**画布上的半径手柄**（缩放）与沿用三色环（旋转）。
> **用户原话**：「轨道圆的内容做的很差，根本不是我要的那种，我要的轨道圆是点在圆上而不是圆跟着点走，而且圆要可以缩放旋转」。
> **不在本轮**：多边形轨道（`face3`）的独立化、半径吸附刻度、把圆心挂到某个点上的开关、平面（2D）画布上的任何改动。

---

## 1. 背景：现状是实测出来的，不是推测

改动前用一次性探针（跑完即删，不进仓库）在同一份文档上量了三条：

| 现象 | 实测证据 |
| --- | --- |
| 圆跟着点走 | 拖圆心那个空间点：点坐标 X `0 → -0.9588`，同时轨道的「圆心 X」读数是 `-0.959`——轨道的圆心**就是**那个点。检查器页脚自己写着"圆心跟着那个空间点走：改点的坐标或拖点，整条轨道一起平移。" |
| 圆心点删不掉 | 删除该点得到 `object is referenced by another object: point3-1`，点仍在对象列表里 |
| 画布上不能缩放 | 从圆周往外拖 70px，「圆轨道半径」稳定在 `3`。同一时刻 `data-rotation-handles = 3`——旋转环是有的，缺的正是缩放 |

根因是**数据模型选错了主从**：`Circle3Primitive` 存的是 `centerId: string`（引用一个点当圆心），于是圆是那个点的派生物。用户要的是反过来——圆是对象，点是乘客。用户口径（上一轮原始需求）："增加一些可以旋转，平移的平面图元……主要作用是作为约束轨道"——轨道是被操作的对象，不是某个点的附属品。

## 2. 目标与非目标

**目标**：`circle3` 变成**自带圆心坐标的独立空间圆**；已有点绑到它上面后**只沿圆周滑动**（点沿圆，不是圆随点）；圆能在画布上**拖本体平移、拖半径手柄缩放、拖三色环旋转**；圆心坐标可在检查器里直接编辑；旧文档与草稿自动迁移。

**非目标**：见文首"不在本轮"。`face3`（空间多边形轨道）保持由点定义——它是通用图元，顶点就是它的定义，要独立得另立图元类型，属另一件事；本轮只保证圆的语义正确。

## 3. 数据模型

```ts
// packages/dsl/src/types.ts（改）
export interface Circle3Primitive extends PrimitivePresentation {
  id: string
  type: "circle3"
  /** 圆心坐标**自己存**：圆是独立对象，不再引用任何点。 */
  center: Vector3
  normal: Vector3
  radius: number
}
```

一句话概括这次改动：**`centerId: string` → `center: Vector3`**。`normal` / `radius` 不变。

## 4. 迁移（旧文档与草稿）

`decodeMgeo` 对不合法的文档是 `throw`（`Invalid geometry document: …`），所以迁移**必须在 `validateDocument` 之前**——否则用户更新后老 `.mgeo` 直接打不开。codec 里已有同款先例：`withSectionClassification` 就是在校验前给旧截面补 `classification`。

- 新增 `withCircleTrackCenter(primitives)`（与 `withSectionClassification` 同形）：把 `{ type: "circle3", centerId, … }` 换成 `{ type: "circle3", center: <该点的坐标>, … }` 并**删掉 `centerId`**。
- **幂等**：已经是新形状的文档原样返回（再解一次不变），有单测。
- **悬空引用**（`centerId` 指向不存在的点，只有手改过的文件才可能出现）：那条轨道无法定位，**丢掉这一个图元**，其余文档照常打开。理由：宁可少一条轨道，也不能让整份文件打不开；`centerId` 的引用保护在旧版本里就挡着 UI 删除，所以正常存出来的文件不会出现这种情况。
- `schemaVersion` 保持 `"0.1"`，不强制升级文件；导出的 `.mgeo` 直接写新形状。
- 加载与草稿恢复两条路都会经过 `decodeMgeo`（`App.tsx` 的 `load(...)` 与 `loadDraft(...)` 都调它），所以只改一处。

## 5. 内核

- `hosts3.ts`：`host3FromPrimitive` 的 `circle3` 分支从"查点表拿圆心"改成直接读 `primitive.center`；`circleHost3(center, normal, radius)` 签名本来就是坐标圆心，**不动**（它的一维闭合域、`closedU`、退化拒绝都不变）。
- `quadrics.ts`：`conic3FromCircle3(primitive, points)` → **`conic3FromCircle3(primitive)`**——不再需要点表，参数整个删掉（这也是新模型更干净的直接证据）。调用方只剩渲染（`createCircle3Line`）与它自己的单测。
- `measurements3d.ts` 的圆面积只读 `radius`，不动。

## 6. 场景图

`circle3` 从"点驱动对象"挪到"**自带几何的对象**"那一类（模板实体那一支就是样板）：

| 位置 | 改动 |
| --- | --- |
| `managedPointIds` | `circle3` 不再返回 `[centerId]`，返回空 |
| `isFreeDraggable3` | `circle3` 移出"点驱动"名单，改成与模板实体同类：自身可拖 |
| `translatePrimitive3` | 新增 `circle3` 分支：平移 `center` |
| `rotatePrimitive3` | `circle3` 走"自带几何"分支：转 `normal`；给了 `pivot` 时 `center` 一起公转（默认枢轴就是它自己的圆心，所以绕自己转时圆心不动） |
| `primitiveDependencies` | 去掉 `circle3 → centerId` 这条依赖边 |
| `patches.ts` 的 `isReferenced` | 删掉 `circle3.centerId` 这条引用保护 ⇒ 圆心点从此可以随便删 |
| `patches.ts` 的 `radius3` 校验 | 不变（仍是"正数、有限"，`circle3` 在允许名单里） |

**副作用（正向）**：`EDITABLE_GEOMETRY_TYPES` 与 `radius3` 名单都不用改；绑定在轨道上的动点的依赖边（点 → 宿主）也不变，所以改半径/转向后动点照旧重算。

## 7. 画布交互

选中**恰好一个**轨道时（与旋转环同一条规则），圆上出现：

1. **半径手柄**：顶点在**宿主参数 0** 处——用 `circleHost3(center, normal, radius).evaluate({ u: 0 })` 取，于是"手柄所在的那一点"就是"绑上去的动点参数 0 所在的那一点"，不需要另写一套基。
   - `visualRole: "track-radius-handle"`、挂 `userData.primitiveId = 轨道 id`（于是平移拖动时它跟着走）、`excludeFromFit`（手柄不是内容，不参与取景）。
   - 为了"这个点能拉"一眼可见：手柄画成与点手柄同款的小球，并从圆心到它画一条**虚线半径**（只在选中时出现）。
2. **缩放会话**：`pointerdown` 命中手柄 → 进入缩放会话。指针射线与**圆所在的平面**（`center` + `normal`）求交，半径 = 交点到 `center` 的距离；射线与平面平行（正对着圆看）时不猜，本帧不更新。下限与属性栏一致取 **0.01**；**不吸附**（要精确值用属性栏的半径框）。
3. **拖本体平移**：走既有的自由拖动那条路（改完后移动的是圆自己的 `center`，不会再拽着某个点走）。
4. **旋转**：沿用世界轴三色环（拖红环 = 绕 X 转），圆心不动、法向转过去；属性栏「朝向」的相对旋转照旧。

**画布交互的管辖范围**（避免歧义）：半径手柄与三个旋转环是**显式手柄**，不受「自由拖动」开关影响（与上一轮旋转环同一条规则）；**拖圆本体平移仍受该开关管辖**（与其它对象一致：开关关着时左键拖动是转视角）。手柄与环都按**同一条出现规则**：恰好选中一个对象、它可转、且未锁定（复用 `rotationHandleTarget` 那套判定，锁定的轨道既不给环也不给手柄）。

**优先级**：半径手柄 > 三色环 > 平移/选择。手柄是更具体的靶子（它压在圆周上，而"拖圆周"也可以解释成平移），与既有拾取哲学一致（点 > 棱 > 面 > 线）。

**拖动中的画面（不改文档）**：文档在整次拖动期间**不提交**（一次拖动 = 一步撤销），画面靠下面三件事保持自洽：
- 圆按预览半径用 `refreshPrimitiveObject(轨道 id)` 重建（场景里保留一个 `circleRadiusPreviewRef`，重建时用 `{ ...primitive, radius: 预览值 }`）；
- **绑在它上面的点**用 `circleHost3(…, 预览半径)` 按当前宿主参数重算坐标并重建——与"拖绑定点"那条预览路径同源，所以拖半径时点始终贴在新的圆周上，不会等抬手才跳过去；
- 半径手柄移到新圆周；三色环按既有 `handleRadius` 的比例**整体缩放**（比例用"构建时的环半径"算，避免逐帧累积），抬手后由内容同步按新半径精确重建。

**抬手**：清掉预览 → 提交一次 `{ op: "updatePrimitive", id, patch: { radius3 } }`（一步撤销）。**没有实际改变半径就不提交**。

**读数**：`data-track-radius`（当前选中轨道的半径；拖动期间给预览值，没有轨道时为空串）——e2e 用它断言"拖着的时候半径已经变了"，而不是只看抬手后的结果。

## 8. 检查器

- 「空间圆轨道」块：`圆心 X/Y/Z` 从只读读数变成**可编辑字段**（写 `center`）；半径、法向读数、相对旋转保留；**删掉**"圆心跟着那个空间点走"那句说明。
- 创建入口的指引文案补一句"建完与那些点无关"，避免再出现"我以为它还跟着点"。

## 9. 创建入口

交互不变（1 个点 = 圆心 + 默认半径 1.5；2 个点 = 再定半径；3 个点 = 三点定平面），语义改成**取一次坐标就脱钩**：`center: { ...center.position }`，不再写 `centerId`。三点共线 / 两点重合的拒绝逻辑照旧。

## 10. 退化与诚实

| 情形 | 结论 |
| --- | --- |
| 旧文档里的圆心点已不存在 | 丢掉那一条轨道，其余照常打开（见 §4） |
| 拖半径拖到圆心 | 半径夹在 `0.01`（与属性栏同一下限），不会产生零半径的退化圆 |
| 指针射线与圆所在平面平行 | 本帧不更新半径（不猜一个值出来） |
| 半径手柄被实体挡住 | 与旋转环同一套做法：只对手柄/环做射线求交，被挡住的半边也抓得到 |
| 未命中手柄 | 行为完全不变（仍走平移 / 选择） |
| 多边形轨道 | 保持由点定义，本轮不动；要独立需另立图元类型 |

## 11. 测试策略

**RED 先行**（每条先贴真实失败输出再实现）：

1. **DSL**：新形状校验通过；圆心非有限 / 半径非正 / 法向为零 → 拒绝；旧形状（只有 `centerId`）经 `decodeMgeo` 后是 `center` 且没有 `centerId`；悬空 `centerId` → 只丢那一个图元；迁移幂等；encode→decode 往返。
2. **内核**：`conic3FromCircle3(primitive)`（无点表）给出圆心处的精确圆；`host3FromPrimitive` 不再需要点表。
3. **场景图**：平移改 `center`、绕自身转只改 `normal`（`center` 不动）、给 `pivot` 时圆心公转；删掉原来的圆心点**成功**且轨道还在；`rotationHandleGeometry` 仍为轨道给出环心 = `center`、reach = 半径（**这条专门守"环会静默消失"那个坑**）。
4. **画布纯函数**：手柄位置 = 宿主参数 0（与 `circleHost3(...).evaluate({u:0})` 逐位一致）；`radiusFromPointer` 的平面求交、0.01 下限、平行时返回 `null`。
5. **App / 检查器**：创建后轨道 `center` = 第一个点的坐标且不引用它（删掉那个点轨道仍在）；检查器改圆心 X 写入 `center`。
6. **e2e**（一条主链路）：建轨道（点 A、B）→ **拖圆本体**（A、B 坐标不变）→ **拖半径手柄**（拖动中 `data-track-radius` 已变，抬手后提交；绑定的点落在新圆周上）→ **拖 X 环 90°**（朝向读数变、圆心不动）→ 绑定的点沿圆滑动残差 ≈ 0 → **删掉点 A 成功**且轨道还在。
