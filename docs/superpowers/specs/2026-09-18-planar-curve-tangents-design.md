用户口径（本轮目标的原始表述）：

1. 「现在实现平面几何的切线功能。逻辑是：创建一条曲线后，可以点击这条曲线，右侧功能栏里应有一个选项是创建一条在这个曲线上的切线。曲线包括抛物线，双曲线，圆，椭圆。」
2. 「现在需要对动点功能进行拓展，动点在轨道上能够在动点位置画切线，同时切线能根据动点位置进行动态变化，第二动点能够作为圆心作圆，圆的半径能够调节，也能够根据动点位置进行动态变化。」

## 为什么要单独设计，而不是"给切线多接几种来源"

文档里早就有 `tangent` 图元，但它只描述**函数图像**的切线：`sourceId` 是函数、`x` 是切点横坐标、
几何交给数值导数。三条曲线（抛物线 / 双曲线 / 圆 / 椭圆）放进来会立刻撞上三件现有抽象回答不了的事：

1. **"切在哪"需要一个新的真值。** 函数的自然参数就是横坐标 `x`，所以一个数字够了；圆锥曲线的自然参数
   是角度或轴向参数，与切点的 `x` 不是一回事。用 `x` 兼作参数是一个**会静默切错地方**的歧义
   （圆上参数 1.0 的切点是 `(r·cos1, r·sin1)`，而横坐标 1.0 对应两个完全不同的切点）。
2. **切线会竖直。** 圆的左右顶点、部分朝向下的抛物线顶点，切线斜率是无穷大。`y = kx + b`
   在那里直接坏掉（`Infinity` 写进 `slope` 还会让 schema 校验失败）。
3. **"切点跟着动点走"是一条依赖关系，不是一个数值。** 如果创建时把当前参数抄下来，切线就是一张快照；
   用户要的是拖点切线跟着转。

因此本轮的实现是：**新增一个定位真值（`TanrentAnchor`），把切线几何从"斜截式"换成"点 + 单位方向"，
并把定位写成可被依赖图跟踪的引用。**

## 数据模型

### 1. 切线的定位方式：`TangentAnchor`

```ts
type TangentAnchor =
  | { kind: "parameter"; parameter: number; branch?: number }   // 曲线自然参数
  | { kind: "point"; pointId: string }                          // 一个点图元
```

`TangentPrimitive` 增加可选 `anchor` 与可选 `halfLength`（绘制半长）。

- **函数来源的旧切线不带 `anchor`**，`recompute` 仍走原来的数值导数路径，旧文档逐位不变。
- **非函数来源强制要求 `anchor`**（DSL schema 层面）：缺了它就只能读 `x` 当参数，正是上面第 1 条那个歧义。
- 分支 `branch` 是为双曲线的两支准备的。

分派判据是"**有没有 `anchor`**"，不是"来源是什么类型"：
函数图像也是动点可以绑定的轨道，所以"在动点处作切线"完全可能落在函数图像上。
按来源类型优先分派会把那条切线的 `anchor` 静默忽略 —— 表现是"切出来了，但拖点它不动"。
（这是实现过程中真实踩到并按测试钉住的一个缺陷，见 `curveTangents.test.ts` 的函数轨道用例。）

### 2. 圆的圆心与半径：`centerPointId` / `radiusFrom`

```ts
interface CircleRadiusRule { pointId: string; factor: number }
// CirclePrimitive 新增：
centerPointId?: string        // 圆心就是这个点图元
radiusFrom?: CircleRadiusRule // r = |圆心 → 那个点| × factor
```

- `center` 与 `radius` 仍然是圆的**派生缓存**：重算按上面两条规则写回去。
  这样渲染、求交、测量、导出**一行都不用改**——"圆过那个动点"对它们就是一个普通的圆。
- 半径被驱动时给一个不可见的正下限（`MIN_DYNAMIC_CIRCLE_RADIUS`）：驱动点与圆心重合时半径会算成 0，
  而 schema 要求 `radius > 0`。宁可画出一个极小的圆，也不能让文档存不下去。
- `centerPointId` 与 `rotationAbout` **互斥**：两者会争夺同一个 `center`。`curveRotationOf` 在圆心被点接管时
  直接返回 `undefined`，让"圆心就是那个点"这条语义赢。

## 内核：`constraintTangentAt`

```ts
constraintTangentAt(constraint, parameter, branch) -> { point, direction, parameter, branch } | null
tangentSegment(tangent, halfLength) -> { a, b }
normalFromTangent(tangent) -> CurveTangent
```

三件刻意的事：

1. **返回点 + 单位方向，不返回斜率。** 竖直切线因此天然可表达；`vertical` 是几何事实，不是 `slope = Infinity`。
2. **切点由 `evaluate` 求出**，不从切向积分回去。后者会累积漂移、切点慢慢离开曲线
   （与 `dynamic-points.ts` 是同一条不变式）。`tangent(parameter)` 只提供方向。
3. **周期参数折回参数域。** 圆上转过十圈之后参数是 20π，切向仍然对，但读数与"切点参数"滑块会一路飘走。

这套抽象复用了内核**已经存在**的解析 `PlanarConstraint.tangent(parameter, branch)` ——
圆、圆弧、椭圆、双曲线、抛物线、函数图像、隐式曲线各自都有实现，本轮没有新增任何切线公式，
只是把它接出来并补上"点 / 方向"这个更诚实的表示。

## 重算与依赖

| 对象 | 依赖边 | 说明 |
| --- | --- | --- |
| 切线（点定位） | `anchor.pointId` | 点一动，切线重算 |
| 切线（任一） | `sourceId` | 来源曲线一动/被删，切线重算/级联 |
| 圆 | `centerPointId` | 圆心跟着点 |
| 圆 | `radiusFrom.pointId` | 半径跟着点 |

- 圆心 / 半径的推导写在**主循环里**（`recomputePrimitive`），不放在"绕定点旋转"那样的预扫描里：
  预扫描读的是本趟开始前的快照，拖动时会慢一帧，用户看到圆心追着点跑。依赖图声明的边保证拓扑序里
  点排在圆前面，所以主循环读到的永远是刚算出来的坐标。
- 圆的查找从**快照 Map 改成活引用**（`circleOf`）：圆会在主循环当中被改写，
  快照会让"直线与这个圆的交点"读到改写前的旧圆（交点慢一帧、甚至粘在旧位置）。
- 点定位的切线**优先读动点绑定里的参数**，而不是它的坐标：坐标是派生缓存，读它同样会慢半步。

## 级联删除

- 圆心点被删 → 圆一起消失（与"动圆"同一个判据：派生随宿主注销）。
- 半径驱动点被删 → 圆**保留**，丢掉规则、半径停在最后一次算出的值。
  圆心还在、半径也还有值，圆的含义是完整的；悬空引用会让半径冻住且再也改不动。
- 切线的定位点被删 → 切线一起消失（它是纯派生的，不知道切在哪的切线没有意义）。
- 来源曲线被删 → 切线一起消失（沿用既有的函数分析级联）。

## 界面

- **曲线属性面板**：圆 / 圆弧 / 抛物线 / 椭圆 / 双曲线都多一个「创建切线」按钮
  （抽成 `CurveTangentAction`，四处共用一份文案与禁用条件）。切点默认落在曲线的**自然参数原点** ——
  四条曲线的参数 0 都恰好是顶点，所以这是"教科书上那条切线"。
- **切线属性面板**：「定位方式」在"曲线参数 / 跟随动点"之间切换，前者给「切点参数」输入框
  （参数域取自该曲线），后者给点下拉；再加一个「切线半长」。
  切换时切线**留在原地**：切回参数方式时参数取当前切点在曲线上的**投影**，而不是切点的横坐标。
- **点属性面板**：新增「以点为圆心作圆」与「在动点处作切线」。
  后者只在动点**已经绑定到一条可作切线的轨道**上时可用 —— 与 App 里的处理走同一个名单
  （`isTangentSource`），"按钮亮着但点下去没反应"是最难查的一类缺陷。
- **圆属性面板**：「半径随动点」下拉 + 「半径倍率」。半径被驱动时半径输入框禁用并说明原因。
- **画布交互**：拖动"以动点为圆心"的圆 = 拖动那个圆心点（直接把位移写进 `center` 会被重算覆盖，
  用户看到的是"拖了没反应"）。半径被驱动的圆**不再画半径手柄**：拖出来的 `radius` 补丁会被距离覆盖回去，
  留一个假控件比少一个更糟。
- **画布视觉（2026-09-18 用户第二轮反馈后收细）**：切线与其他图元共用 `strokeWidthFor`，
  线宽从"选中 5 / 未选中 3"收到 **2.5 / 1.5**，点半径从 4 收到 **2.5**。
  切线在 3px 时会盖住它贴着的那条曲线，看不清"相切"这件事本身。
  命中区（`strokeWidth="18"`）**不跟着缩** —— 那决定的是"点不点得中"。
  这套尺寸同时用于 SVG 导出（`svgStyleFor` 复用同一份），屏幕与导出保持一致。

### 拖动切线（用户反馈："切线不能在曲线上自由拖动"）

两个根因，缺一个都表现为"拖不动"：

1. 画布上切线那一组**只有 `onClick`、没有 `onPointerDown`** —— 指针按下时拖动根本不成立，只能点选。
2. 就算起拖，平移一条**算出来的**切线也是空操作：切点由定位方式决定，`translatePrimitive` 对切线不做任何事。

修法是给 `createDragAction` 加一个 `DragTangentTarget`（与既有的 `DragRotationTarget` 同一个约定：
**由界面解析好传进来，`interaction.ts` 不读文档，保持纯函数好测**），它提供一个
`parameterAt(worldPoint)` —— 界面用内核的 `pathConstraint(...).project` 构造，与动点、与检查器里
切换定位方式**共用同一份投影定义**。语义按定位方式分三种：

| 切线的定位方式 | 拖本体时的行为 |
| --- | --- |
| 曲线参数 | 投影指针到来源曲线，改 `anchor.parameter` |
| 跟随动点 | 位移转给**那个动点**（复用已跑通的"拖动动点"通路，`dragBoundPoint` 会把位移投影回轨道参数） |
| 函数来源的旧切线（无 `anchor`） | 横向位移加到 `x` 上，沿函数图像滑（补丁校验与应用补丁两处以前都不支持切线带 `x`） |

一个容易忽略的细节：`parameterOffset`。按下时记下"切点参数 − 按下处投影参数"，拖动时保持这个差值。
没有它，用户在离切点很远的地方抓住这条线时，切点会**一按下就瞬移到指针脚下**。
这与动点的 `beginDrag` 记偏移量是同一个理由。

另外两处配套：选中时在**切点**上画一个控制点（"这条线能拖着滑"不是一个看得出来的性质）；
投影时把当前切点参数作为 `previousParameter` 传进去，拖过双曲线时不会跳到另一支。

- **界面**（`App.test.tsx`）：真的点按钮、真的改输入框、真的走指针手势 ——
  四类曲线各创建一次切线并断言切点在曲线上（圆的竖直切线专门断言）、
  动点切线创建后改「路径参数」切线跟着走、定位方式切回参数时切线留在原地、
  以点为圆心作圆 → 改半径 → 半径随动点 → 倍率、
  以及在切线上 `pointerDown → pointerMove → pointerUp` 断言切点沿圆滑到 (0,3) 且该处切线变成水平
  （没有 `onPointerDown` 时这条会失败，所以它是这轮修复的回归守卫）。

## 已知边界

- **法线**：内核与重算都支持曲线来源的法线（`normalFromTangent`），但没有加"创建法线"的界面入口
  （用户口径只要求切线）。选中一条曲线只能创建切线。
- **割线**仍只支持函数来源：曲线上的割线需要第二个切点参数，"两点割线"是另一个交互，不在本轮口径内。
- **圆弧**：可以作切线，但圆弧**不能**作为动点的驱动点/圆心这类新能力的主体 ——
  `centerPointId` / `radiusFrom` 只给圆（弧还多着两个端点角，叠加起来没有用户口径）。
- 切点参数滑块的范围取自曲线的自然参数窗口；无界曲线（抛物线 / 双曲线）用的是与图形尺度成比例的
  默认窗口，不是真的无穷区间。
