# 真实模型文字作图恢复 Implementation Plan（2026-11-10）

> 执行纪律：逐任务 RED→GREEN，禁止未经用户授权委派子代理、付费扩测、发布或自动提交。

**Goal:** 在保留宿主安全证书的前提下，恢复纯文字显式作图题的可确认图形交付。

**Architecture:** 复用题意 IR、同一生产规划器、草稿隔离与 W1 证书；按目标→路由→构图→逐条条件证书→确认/提交的现有链路逐层修复，不另造求解器。

**Tech Stack:** TypeScript、React、Vitest、Playwright、Tauri 原生 Provider、现有 geometry-kernel。

**Spec:** `docs/superpowers/specs/2026-11-09-text-only-certified-drawing-design.md`；失败证据 `docs/audit/2026-11-10-live-drawing-failure.md`。

## Global Constraints

- 纯文字输入；OCR、图片识题、未授权的第二模型与自动提交一律不恢复。
- 原题/题集哈希、模型/构建版本、逐题分母和实际调用次数必须复核。
- 作图证书的题干/场景/草稿哈希绑定、提交前重验与用户确认不得降低。
- 旧 W5 暂停；本方案 D0–D5 均待实施，不由本次文档提交自动启动。

> **状态：待实施；旧 W0–W4 工程包已结项，旧 W5 已撤出，不在本方案中复活。** 本文针对真实模型作图 0/20 可确认的缺口。新任务 D0–D5 必须有 RED→GREEN 的逐题证据；禁止把旧包“已完成”解释为“真实作图已达标”。

**目标**：显式要求作图的纯文字题，先安全保留全部原题条件，再走到有图元、有完整宿主来源证书、可在浏览器确认的草稿；无法满足时说明具体原因并拒绝提交。目标是逐阶段提高覆盖率，**不承诺任意自然语言题 100% 都能画出**。

**边界**：不恢复 OCR/图片输入，不调用未授权第二模型，不自动提交，不绕开 W1 证书/CAS/用户确认；先修路由与可观测性，再扩构图/修复，最后真实 UI 验收。独立验证选择题答案与作图条件，题中待证结论不能充当作图已知。

## 一、基线与依赖

[失败审计](../../audit/2026-11-10-live-drawing-failure.md)逐题记录 20 题（平面 10、立体 10）、真实模型 31 请求、草稿 3、可确认 0；错误路由发生在 13 道改写公开题；3 个本地立体证书因前缀来源未归属被拦；4 个原生立体构图未收敛。这是**核心服务**基线，不是 UI 或视觉正确率。题集及独立 oracle 必须再审核；7 个回归夹具和 13 道改写公开题单列，不混为“20 道原卷作图真题”。源质量有歧义的题另列，不悄悄移出分母。

依赖链：`D0 题集与追踪 → D1 显式绘图目标保留 → D2 证书原文归属 → D3 构图与修复 → D4 浏览器真实交付 → D5 扩样复测`。D1/D2 是安全和正确性的前置条件，不能为了提高百分比跳过。

## D1：修复“请作图 + 单选”被只读短路（P0）

- **触点**：`packages/agent-core/src/solveContext.ts`、`problemUnderstanding.ts`、`apps/web/src/agent/problemSolveService.ts`、`modelPlanner.ts` 及对应测试。
- **RED**：以 `text-128`（双曲线）和 `text-180`（球）为代表：`taskIntent=drawing-and-answer` 但 `goals=[single_choice]`、`requestedSkillIds=[]`、模型提示“无需作图”、最后只有答案；再测纯选择题无“请作图”不得生成图元、多问/附件缺失不得凭空补图示。
- [ ] **GREEN**：按原文显式绘图命令创建**独立宿主作图目标**，保留原单选/证明目标与稳定源 span；`answerOnlyChoice` 仅在 `taskIntent=readonly-answer` 且没有绘图目标时成立；混合意图必须把规划器动作/技能与必答目标同时交付。`modelPlanner` 的“无需作图”只适用于确定的只读题，混合题用明确“图 + 答案”的合同，禁止 `kind=answer` 冒充完整交付。不要让选项反推图形已知量。
- **闸**：路由定向回归（平面+立体至少各 3 题）必须生成含作图目标的上下文；原只读 40 题“0 意外图元”保持；对无足够条件的题可澄清，不能画伪图。先单测再真实 DS 小样 2+2，原生模型事件逐题存在、能进入编译/暂存阶段；**进入阶段不等于通过整图**。

## D2：来源覆盖证书不误杀明确作图前缀（P0）

- **触点**：`packages/agent-core/src/verification/drawingCertificate.ts`、`solveContext.ts` 的源 span；`apps/web/src/agent/draftStore.ts`、`coordinator.ts`、`hostBridge.ts` 的提交硬闸及测试。
- **RED**：Case 1–3 的 `请作图。如图...` 当前有 20/23/22 图元和 `diagramStatus=passed`，但 `unaccounted source text remains`；对比隐藏原始尺寸、删垂直条件、把“如图”改成仅图中可读的未给定尺寸、伪造 prompt span 均仍必须拒证。
- **GREEN**：把作图命令作为可追溯的**目标 span**登记；“如图”只在文字已完整描述且不存在不可获得图示条件时登记为引用性标记，存在图形缺口则请求澄清；证书只能忽略已被宿主登记并逐字验证的目标/纯标记 span，绝不能粗暴 `.replace('如图','')` 或整句跳过。让 `report passed → full certificate → awaiting_confirmation` 的状态有单一诊断来源；仍由授权、提交端独立重验并绑定 prompt/scene/preview hash。
- **闸**：3 道已暂存立体在当前明确文字条件下到达可确认；至少 6 种删改/伪证/过期负例 0 错误确认；用户未确认前活画布写入 0。若独立 oracle 判题目条件互相矛盾则如实阻断，不“修”成假通过。

## D3：构图动作与有界修复收敛（P1）

- **触点**：`apps/web/src/agent/modelPlanner.ts`、`packages/agent-core/src/planCompiler.ts`、`coordinator.ts`、`apps/web/src/agent/draftStore.ts`；复用现有 `spatial-modeling`/平面技能与已有几何核验器。
- **RED**：Case 4 两版 `vertexNames` 缺失/折前折后点名混淆、E19 垂足 E 先引用后创建、E23 `BD=3` 残差；平面双曲线/抛物线缺语义构图、圆的多解不应擅自选唯一配置。逐题保存编译诊断、每轮动作、残差与终止原因。
- **GREEN**：优先语义形状与几何约束动作，不让模型裸手算复杂面环；产出“先创建具名顶点/曲线→再构造垂足或绑定点→最后连线/翻折”的可核顺序。为 `missing vertexNames`/`segment_reference_missing`/几何残差提供**有界且局部**修复请求，只允许修改指定动作，其他已核条件回归复算。高于容差时只报错/澄清，不通过提高容差或编造点名过闸。技能选择按目标/工作区筛选，避免无关说明导致请求膨胀；参数和模型请求预算留在宿主，超限拒绝。
- **闸**：平面圆锥曲线/圆题与立体翻折/辅助点各至少 2 个真实模型端到端草稿；原始负例与属性扰动全部仍被拒；E19 必见辅助点 E、E23 BD 实测=3 才可确认。逐题记录是否本地确定性或 DS；不把本地通过算作 DS 成功。

## D4：真实浏览器画布交付验收（P0 发布前）

- **触点**：现有 Agent 对话、确认面板、平面/立体画布与 `e2e/agent-*.spec.ts`。复用已存模型配置，只在用户同意的预算内调用，不把单测代替 UI。
- **RED**：分别复现“返回答案却无图”“图元已暂存却无法确认”“点名/折叠几何错误仍想确认”“提交后仍显示等待确认/可重复确认”。
- **GREEN/证据**：每题经过输入→模型/确定性路由→草稿预览→逐条题设宿主证书→用户确认→画布实物→刷新仍存在→撤销恢复；保存前后 scene hash、图元类型/命名/条件读数和截图，人工目检标签/遮挡，确认后不出现旧按钮。没有证书的图必须维持不可确认；真实 Provider 与本地路线分轨。
- **闸**：预先冻结的平面、立体正例/歧义负例均满足其独立 oracle；错误图批准数 0、未经确认写盘数 0、重复确认数 0。至少 2 平面+2 立体完整浏览器提交与撤销，经真实模型路径者另报题号。不得靠 20 题核心服务结果冒充完成本块。
