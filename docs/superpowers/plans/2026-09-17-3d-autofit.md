**Goal:** 3D 视口按**可见图元的世界 AABB**自动取景：加载、图元增删与内容越界时平滑重置，保留 30% 安全边距，并提供可关闭的开关（关掉后不抢用户视角）。

**Tech Stack:** TypeScript、three.js、React、Vitest、Playwright。

### Task 1: 取景数学（纯函数）

**Files:** Modify `apps/web/src/threeScene.tsx`；Create `apps/web/src/sceneFit.test.ts`

**Interfaces:**
- `export const FIT_MARGIN = 0.3`
- `export function fitCameraState(state: CameraState, bounds: THREE.Box3, camera: THREE.PerspectiveCamera): CameraState`
  —— 保留视角角度，target 移到 AABB 中心；把 AABB 八个角投影到相机右/上/前三轴得 `halfRight/halfUp/halfForward`，
  `needed = max(halfUp / tan(vfov/2), halfRight / tan(hfov/2)) + halfForward`，`distance = needed / (1 - FIT_MARGIN)`，夹到 `[0.05, 1e4]`（旧实现夹在 `[3, 60]`，正是"小模型不能靠近、大模型看不全"的原因）。
- `export function isContentOutOfView(state: CameraState, bounds: THREE.Box3, camera: THREE.PerspectiveCamera, padding = 0): boolean`
- `export function interpolateCameraState(from: CameraState, to: CameraState, t: number): CameraState`
- `export function shouldAutoFit(inputs: { enabled: boolean; dragging: boolean; documentChanged: boolean; boundsChanged: boolean; cameraTouched: boolean; outOfView: boolean }): boolean`
  —— `enabled && !dragging` 是前提；文档换了或内容越界 → 一定拟合；否则只有"内容变了且用户没动过相机"才拟合（用户手动调过视角就不抢）。

**实现要点**
1. **逐角点求最小距离**，而不是"沿三轴各取半宽相加"：后者假设"最偏的角同时最靠近相机"，对斜视角的盒子偏保守（实测 4×4×2 的盒子只能填到 55% 而不是 70%）。逐角点 `d ≥ |投影|/tan - 纵深` 取最大值后，构图接近满 70%。
2. **近远平面随距离缩放**：固定 `near = 0.1` 会让"0.01 单位的小模型凑近看"整块被近平面裁掉——这是"小图形框不满"的另一半原因。
3. **距离夹取从 `[3, 60]` 放宽到 `[0.005, 1e4]`**（缩放共用同一组边界，否则拟合到 0.02 之后一滚轮就被夹回 3）。

**偏离计划的一处收窄（重要，属行为变更）**
原计划按 `shouldAutoFit = enabled && !dragging && (documentChanged || boundsChanged && !cameraTouched || outOfView)` 实现"增删也拟合"。实测**打断了 7 条既有浏览器流程**：拖动实体时相机跟着实体走、移动截面时视角跳、按已知屏幕坐标点击顶点的用例全部失准。用户的真实痛点是"图形太小 / 跑到视野外"，而不是"编辑时视角必须回到中心"，因此收窄为：

```
shouldAutoFit = enabled && !dragging && (documentChanged || outOfView)
```

即"打开文件/切换工作区/恢复草稿"与"内容跑出视锥"才重置；**编辑过程中永不抢视角**。需求里的"增删时重置"以"增删后若内容越界就重置"的形式满足——这正是"新加的图元看不见"的解法。`AutoFitInputs` 随之去掉 `boundsChanged` / `cameraTouched` 两个字段，单测同步改写。

**测试侧的配套改动（都是行为变更带来的，不是放宽断言）**
- `geometry3d.spec.ts`「frames an opened figure…」：原来断言"编辑时相机不动"，改为断言加入新点后自动取景（`data-camera-fit` 2、target `0.50,0.50,1.50`、距离变大），随后仍验证手动缩放与「适应视图」。
- `geometry3d-drag.spec.ts`「drags only the solid under the pointer」：该用例按固定屏幕位移拖动、依赖相机稳定，因此在开头**关掉自动取景**（把第一个立方体挪到 (8,8,0) 会让内容越界并触发重新构图）。
- 两处新的按钮点击改用 DOM 派发（显示控制那排在窄视口下会换行，`locator.click()` 会等"位置稳定"而超时；仓库里「取面」已有同样先例与注释）。
