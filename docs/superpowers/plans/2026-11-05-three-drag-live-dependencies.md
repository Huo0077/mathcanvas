# 立体拖动过程中依赖图元实时更新：实施记录

日期：2026-11-05

## 1. 问题与目标

拖动 A 时，经过 A 的直线已移动，但绑定在线上的 C 和后续依赖对象停留在旧位置，直到松手才跳到新位置。此问题涉及整个立体场景的拖动预览，不局限于动点。

目标：按住鼠标拖动期间，宿主、绑定点、多级依赖使用同一份计算结果；松手不发生追赶跳变；一次拖动仍只产生一次可撤销操作。

## 2. 根因

旧预览通过 Three 对象位移及有限的线、棱、面刷新实现，没有执行正式的依赖计算。完整计算只发生在松手提交后，因此未被预览白名单覆盖的对象滞后。

## 3. 实施方案与代码职责

### 3.1 临时文档计算

新增 `apps/web/src/threeDragPreview.ts`：

- 从正式文档和当前累计拖动量生成临时文档，不从上一帧结果继续叠加，避免漂移。
- 复用正式操作及依赖计算，统一处理平移、受约束拖动、宿主参数变化、旋转、圆半径和截面位移。
- 受约束拖动使用与松手提交相同的规划器和功能开关。
- 校验完整结果；无效候选位置不进入显示，交互层恢复上一帧有效的拖动参数。

### 3.2 增量显示

修改 `apps/web/src/threeSceneContent.ts`，允许显示指定的临时文档；保留既有签名比较，只重建发生变化的显示记录，复用未变化的对象、网格和渲染器。

`apps/web/src/threeSceneDragVisuals.ts` 统一生成、恢复及清理预览，移除原来手工偏移与有限类型刷新的方式。

### 3.3 交互与提交

`apps/web/src/threeSceneInteraction.ts`、`apps/web/src/threeSceneEffect.ts` 接入统一预览：

1. 移动鼠标：生成并校验临时文档，更新依赖对象并重绘。
2. 候选无效：保留有效画面及参数，不把错误状态带到松手提交。
3. 松手：清理临时显示，调用一次原有正式提交；预览不写入正式文档、保存数据或撤销历史。
4. 无变化或提交被拒绝时，也安排下一帧重绘，避免残留预览画面。

## 4. 回归与验收

### 自动化覆盖

- A → 直线／线段／射线 → C → 后续线段 → D 的多级依赖在松手前更新。
- 面、立方体、圆柱、圆锥及其内部绑定点的实时跟随，松手前后位置一致，一步撤销恢复。
- 实际显示对象中的面、平面、派生球更新，而不仅是数据变化。
- 圆轨迹平移、旋转和半径变化；截面沿法向移动；连续累计拖动、回到原位。
- 受约束拖动、无效实体顶点、三点共线导致平面失效的候选拒绝。
- 动点直接拖动、保存重载、相机与拖动模式、旋转环、半径手柄、场景生命周期。

### 手工验收步骤

1. 打开原问题场景，按住 A 连续拖动，不松开鼠标。
2. 确认 C 始终在新直线上，C 的下游图元同步变化。
3. 松开鼠标，确认没有二次跳变；撤销一次应恢复本次拖动前的状态。
4. 对立体、面及其内部绑定图元重复测试；拖到无效几何位置时应停留在最后有效位置。

## 6. 范围与性能说明

本次修复统一预览通路，使用项目已有的几何依赖规则；不新增尚未实现的几何约束语义。自动化用例覆盖上述代表性类型，不能代替所有用户场景验收。

每次有效预览仍需计算临时文档，并遍历显示记录进行增量比较。本次验证了渲染器不重建、正式文档不在拖动中反复提交；尚未进行大规模复杂场景性能基准。后续若出现性能问题，应依据实际耗时评估增量依赖求值或合帧，而不能省略依赖更新。
