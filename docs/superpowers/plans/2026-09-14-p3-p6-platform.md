# P3 与 P6 实施计划

## 总结

按“先 P3、后 P6”顺序推进。P3 完成函数分析与可保存派生对象；P6 完成参数化 3D 教学工作区。每个独立可验证切片都必须经过测试、类型检查和必要的浏览器验证，然后立即 commit 并推送到 `origin/main`。

## P3：圆锥曲线与微积分

- 增加表达式编译缓存、自适应采样、定义域/值域诊断和近似状态。
- 实现一阶/二阶导数、零点、极值和拐点数值分析。
- 新增可保存派生对象：导函数、切线、法线、割线、积分区域和分析结果集合。
- 派生对象保存来源函数 ID 与计算参数，来源变化后由 Scene Graph 自动重算。
- 微积分工作区增加分析工具、属性编辑、Algebra View 条目和画布标记。
- 无定义区间、采样不足和数值失败必须显示明确状态，不生成虚假结果。
- P3 排除符号微分、完整 CAS、Agent 和题图解析。

## P6 v2：点驱动通用立体几何（新增规划）

P6 v1 已交付四种参数化实体和基础 3D 工作区，但它不是高中立体几何的最终对象模型。按照已确认的方案 C，P6 后续改为“基础对象 + 拓扑对象 + 参数化模板”的分层设计：点位置是构造真源，线和面由点引用确定，实体由顶点/棱/面组合，立方体、棱锥、圆柱和圆锥降为可拆解、可编辑的快捷模板。

## 每个切片的固定流程

1. 明确本切片涉及的文件和接口。
2. 先写失败测试并确认失败原因正确。
3. 实现最小生产代码。
4. 运行聚焦测试、全量测试和类型检查。
5. 涉及 UI 时运行构建和 Playwright。
6. 检查 `git diff --check` 和工作树。
7. 请求只读 code review，修复 Critical/Important 问题。
8. 执行独立 commit，例如：`git commit -m "feat(p3): add numerical derivative objects"`。
9. 推送当前切片：`git push origin main`。
10. 更新项目进度、功能目录和实施计划后，再进入下一切片。

## 验收标准

- P3：函数、导数、切线、法线、割线、积分和分析结果可创建、联动、保存、恢复、撤销、重做和导出。
- P3：数值结果明确标记为近似，所有无定义和失败状态可解释。
- P6：立方体、棱锥、圆柱和圆锥可创建、编辑、保存、恢复、旋转、拾取、剖切和展开。
- P6：3D 对象能进入 Algebra View，派生对象拥有稳定来源引用。
- 全部切片均有对应测试和独立 Git 提交。
- 最终运行全量单测、类型检查、生产构建和 E2E，并同步验证证据。

## 默认取舍

- 顺序：先 P3，后 P6。
- P3：数值分析 MVP，派生对象可持久化。
- P6：原生 Three.js、参数化教学模型。
- 持久化：扩展 DSL，保持 `schemaVersion: "0.1"`。
- 提交策略：每个切片一个 commit，验证通过后立即推送 `origin/main`。
- 不修改 P4 Agent、P5 题图解析和 P7 工程制图范围。
