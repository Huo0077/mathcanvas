# MathCanvas 功能目录

这份目录记录当前可用能力、已确认的下一阶段能力以及明确的限制。它是产品说明，不替代 DSL 类型和测试。

## 当前已实现

- React/Vite 工作台、SVG 画布、Algebra View、选择、删除、锁定、分组、对齐和可见性控制。
- **截面的几何与「转为图元」**：截面是"平面与实体的真实截交**闭合多边形**"——内核按面边界求交后沿相邻面连成环，**带孔或分成多块的截面会保留全部环**（外环带半透明填充、内环只画轮廓，不会把孔洞盖住）。默认剖切面是过实体中心的**水平面**（世界 Z 轴朝上），棱锥 / 圆柱 / 圆锥的默认刀口也落在实体内部（此前它们的回退几何还是 Y 朝上的旧坐标系，刀口会切在边界上甚至切空）。选中截面后属性栏有「**转为图元**」：把每一环物化成独立的点 / 棱 / 面图元，**与来源解耦**——之后删掉截面或宿主实体都不影响它们，它们也能被移动、求交与测量。
- **3D 背景坐标系自适应，且网格严格 1:1**：栅格与坐标轴按当前相机与内容自动铺满可见范围，**格边长恒为 1 个世界单位**（1 格 = 1 单位，不随缩放变成 2/5/20 这类"好看"的值），每 10 格一条主线；缩放改变的是**覆盖范围**（按 2 的幂长大，同档内栅格连位置都不动），缩得很远时细线按"一格占多少像素"淡出、主线仍在。所以点的坐标写到 20 甚至 200，坐标系照样铺到那里，也不会出现"缩放时网格自己变大变小"、拿网格当尺子却量不准的情况；3D 画布本身也填满它所在的网格行（不再用 `calc(100vh - 420px)` 这种与真实工具栏高度无关的猜测值）。
- **3D 视口自动取景（Auto-Fit）**：相机按可见图元的世界坐标 AABB 自动构图——逐角点求出"让八个角都落进视锥"的最小距离，再留 **30% 安全边距**；近远平面随距离缩放，所以 0.01 单位的小模型和超大模型都能框得住（旧实现用包围球 × 1.25，且距离被夹在 3～60，小模型永远凑不近、大模型永远框不全）。触发时机：打开文件 / 切换工作区 / 恢复草稿，以及**内容跑出视锥**时；拟合是约 250ms 的缓出插值（系统开启 reduced motion 时直接跳变）。画布上有「自动取景」开关（默认开，偏好跨刷新保留），并且**编辑过程中永不抢视角**——只有内容越界才会重构图。
- **画布尺寸在交互中途不会变**：状态栏横跨工作台整宽，并且它所在那一行是**固定高度**（宽屏 72px，窄屏按提示行数加高）。此前状态栏被挤在左面板那一列（240px 宽、116px 高），指针一悬停到剖切面预览、提示变长，页脚就涨到 150px，而 3D 画布填满上面那一行——画布被压矮 34px 后，同一个屏幕坐标不再对应同一个世界点，于是"悬停时明明高亮了预览，点下去却没反应"。现在文案再长也不动画布（状态栏自己滚动）。窄屏（≤960px）下右侧检查器整宽另起一行但那行有 45% 的上界：属性再多也只让检查器自己滚动，3D 画布不会像以前那样被挤成 0 高度。
- **3D 动点可以绑定到宿主，并严格沿宿主滑动**：选中空间点后可把它绑定到空间直线 / 线段 / 射线 / 棱 / **空间圆轨道** / 面 / 圆柱与圆锥侧面（面与曲面用 u、v 两个参数）。绑定参数是**唯一真值**、坐标由参数派生，所以点永远不会漂离宿主：在画布上拖动时指针落点先投影回宿主参数、再由参数算出坐标（拖动期间可读 `data-host-residual`，实测残差 ≈ 0），下游由点驱动的线 / 棱 / 面在拖动过程中就跟着重画，**动点自己**在拖动期间也一路跟着走（2026-09-17 修的缺陷：此前它要等抬手才跳过去，见下方「约束轨道」一条）；一次拖动只提交一个参数，因此**一次 Ctrl+Z 精确复位**。解绑即恢复自由点，坐标字段重新可编辑；宿主参数也能直接在属性栏里键入。
- **动点还可以约束在实体内部**（2026-09-17，用户要求"动点的约束应该可以在立方体内"）：下拉里每个实体多一条「**实体内**」（`inSolid`）——点可以在体内自由移动、**出不去**：拖到外面会被沿实体表面夹回去（凸实体逐面投影，非凸输入不会给出体外的点）。参数是实体**包围盒内的三个比例** `uvw ∈ [0,1]³`（属性栏给「体内参数 u / v / w」），所以实体平移或缩放时参数不变、坐标跟着走；实体被删除时该点降级为自由点并保留位置。
- **宿主移动时绑定点会跟着走**（2026-09-17 修的缺陷）：模板物化出来的点 / 棱 / 面现在都声明**依赖所属实体**（此前只有反方向："多面体依赖它们"），所以"移动立方体、绑在它面上的点却留在原地"不再发生——从实体出发的依赖闭包会经过它的所有子对象，再到绑在子对象上的点。
- **圆柱与圆锥的默认分段数是 48**（2026-09-17，用户反馈"圆柱不圆"）：它们是多边形近似，24 段时屏幕轮廓能看出明显的棱；48 段把弦高误差降到约 0.7 像素。预览的配额（单次 12 对来源、每对最多 96 个面 / 12 个交点标记）与它配套，所以 48 段的圆柱参与相交时不会被"面数超限"截断。分段数仍可在属性栏里改（3–256）。
- **圆上只有四个点，母线不画**（2026-09-17，用户反馈"圆相关的内容不要这么多标点，只需要四个点就够了"与"有太多母线，用不上这些"）：圆柱 / 圆锥是多边形近似，48 段会有 96 个细分顶点；现在每个圆只保留 **4 个象限点**（0°/90°/180°/270°，圆柱上下底共 8 个：A–H；圆锥底面 4 个 + 顶点 E），它们是**可见、可点选、可拖动**的用户点；**母线**（圆柱连接上下底的棱、圆锥连接底面与顶点的棱）一条都不画、不列、点不到，只有两个圆环自身的棱作为用户棱保留（标签按可见顺序重编为 `棱 1…N`）。其余细分顶点与母线标 `tessellation: true` 且没有标签——仍留在文档里（面 / 棱 / 交线 / 剖切 / 布尔交集读它们的坐标，48 段精度不变），但画布不画、对象列表也不列出（`apps/web/src/primitiveVisibility.ts` 是"谁算用户对象"的唯一判据）。分段数不能被 4 整除时取**最近的互异**顶点（六边形取 0/2/3/5 号），顶点不足 4 个（三角形近似）时如实少给，不凑数；立方体 / 棱锥 / 棱柱的顶点与棱全部保留（本来就少且都有意义）。**旧文档（草稿 / `.mgeo`）在加载时补齐这些标记**：`migrateLegacySolids` 对已有模板的实体只改可见性与**自动生成**的标签，不重建子对象，所以用户拖过的位置与改过的名字都留着（内核导出的 `templatePointLabel` / `templateEdgeLabel` 就是用来判断"这个名字是不是自动生成的"）。
- **3D 渲染管道不再重建**：进入立体几何后 `WebGLRenderer` 与 canvas **只创建一次**，编辑、选择、展开、拖动都走命令式内容同步（`data-scene-builds` 恒为 1，`data-scene-syncs` 只在内容真的变化时增长）。此前任何一次 App 重渲染都会 `dispose()` 旧渲染器再 `new WebGLRenderer`，画面闪、开销大。
- **3D 的删除不会卡住，也不会留下悬空引用**：删除宿主实体时，被删除对象一次算清——测量 / 2D 标注 / 工程标注 / 约束随宿主注销，截面与截线等纯派生对象一并删除，分组只摘掉被删成员；**绑定在宿主上的空间点会降级成自由点并保留当前位置**，所以文档仍然合法、用户内容也不会被静默丢掉。批量选择（例如"点 + 依赖它的线"）按**并集**一起校验，不再出现"两个都删不掉"的情况；只有**锁定**仍然拒绝删除。
- **多解交点各自独立，并按屏幕距离就近吸附**：直线与曲线、圆与圆等有多个实根时，每个解是**独立实体**（解索引是任意非负整数，不再被夹成 0/1），并且记录"用户点的是哪个解"的 `hint`——形状变化导致解数组顺序翻转时，重算会取离 hint 最近的解，所以选中的那个解始终跟着走；画布上点击时按**屏幕像素距离**在命中半径内取最近的那个标记，不再由绘制顺序决定。
- **切走再切回立体几何，视角保持不变**：3D 场景组件是跟着工作区挂载/卸载的，相机现在会按"某个文档配某个视角"记在会话里——转动、缩放、平移之后切到平面几何再切回来，视角与离开时完全一致（此前会回到默认视角并重新取景）。刷新页面仍是默认视角。
- **编辑与展开不再整场重建 3D 场景内容**：每个场景对象按"内容签名"（自己的数据 + 它依赖的图元 + 影响外观的视图状态）判断要不要重建，签名没变就沿用原对象。实测展开动画的每一帧只重建那张展开网（其余 11 个对象沿用），切换选中只重建该重建的那一两个对象（此前是整场 29 个全部释放重建）。直接可见的差别是展开与选中时不再有闪动，拖动与缩放也更省。
- **3D 标注就地更新**：测量标注与空间点标注不再每次重画都整体重建 DOM，而是按对象复用同一个元素、只更新文字与位置。除了拖动更省，更重要的是读屏软件不会把同一条 `role="status"` 标注当成新消息反复播报，标注的入场动画也不会在拖动时反复重播（表现为闪烁）。
- **手工调整过的模板顶点不会被无关改动覆盖**：模板实体（立方体 / 棱锥 / 圆柱 / 圆锥）只在**它自己的参数**变化时才按参数重同步顶点；改别的对象、或手工编辑文档，都不会把已经手工调过的顶点拽回去（"全量重算"仍会按参数修复它）。
- 点、线、线段、射线、折线、圆、圆弧、抛物线、椭圆、双曲线和函数图像的基础创建或属性编辑。
- **拖动动点很跟手**：拖动时**只重算与拖动对象相关的图元对**的交点，其余交点整段沿用上一次的结果（`data-preview-pairs` 读数可以直接看到"这次重算了几对"）。旧实现每移动一次都要把全文档两两求交一遍——实测 52 个图元 / 6 条采样曲线时是 **76.5ms/次**，拖动只有约 13fps；现在拖一个点是 **0.12ms/次**，真实浏览器里帧间隔中位数 16.7ms（60fps）。被拖动对象**自己**涉及的交点仍然实时重算，不会停在原地。
- **平面几何动点**：任何点都可以绑定到一条曲线（直线 / 线段 / 射线 / 折线 / 圆 / 圆弧 / 函数图像 / 椭圆 / 抛物线 / 双曲线）成为动点。绑定参数是该曲线的**自然参数**——直线是仿射比例、圆与椭圆是角度、函数图像是 x 本身、抛物线与双曲线是轴向参数——所以"能滑多远"由曲线自己决定：直线无限、射线只向前、线段与折线有界、圆与椭圆整周。**两条驱动通路写同一个参数、完全等价**：画布上直接**拖动**（指针位置投影回曲线，点永远精确落在曲线上）、属性栏**「路径参数」输入框**。（原「动效演示」栏的滑块与播放已按用户要求**删除**：播放时只看得到起始与结束两帧，与其修不如去掉。）抛物线与双曲线额外提供可编辑的「参数域」；双曲线可选择「分支」，把点往对面拖也不会跳支。**绑定入口本身也有提示**（2026-09-17 按用户反馈补）：选中一个自由点时状态栏直接说"在右侧「路径绑定」里选一条曲线或直线，它就成为动点，之后可以直接拖它"，文档里还没有曲线时改成"先画一条路径"，已经绑定时说明拖动 / 路径参数 / 记录轨迹三种用法；属性栏下拉下面也写了同样一句。
- **曲线上的切线（2026-09-18，用户口径：「创建一条曲线后，可以点击这条曲线，右侧功能栏里应有一个选项是创建一条在这个曲线上的切线。曲线包括抛物线，双曲线，圆，椭圆」）**：选中圆 / 圆弧 / 抛物线 / 椭圆 / 双曲线后，右侧属性栏多出「**创建切线**」按钮，点一下就得到该曲线的一条切线，**切点默认落在顶点**（四条曲线的自然参数原点都恰好是顶点）。切线是**解析**的，不是数值差分：几何来自内核 `constraintTangentAt`，它同时给出切点与**单位切向**——刻意不用斜截式，因为圆的左右顶点切线是**竖直**的（斜率无穷大，斜截式在那里直接坏掉），竖直这件事由 `vertical` 单独表达。切点严格由 `evaluate(参数)` 求出，所以它永远精确落在曲线上（与动点同一条不变式）。绘制长度按来源曲线自身的尺度自适应（圆 = 直径），也可以在切线的属性里用「切线半长」改。
- **切点可以沿曲线滑动，也可以跟随一个动点（2026-09-18）**：切线的属性栏里有「**定位方式**」——「曲线参数」给出「切点参数」输入框（参数域取自该曲线的自然参数窗口），「跟随动点」则列出文档里的点。两种方式切换时切线**留在原地**：切回参数方式时参数取当前切点在曲线上的**投影**，而不是切点的横坐标（后者会让切线跳到曲线上完全不同的地方）。抛物线 / 双曲线这类无界曲线的参数、双曲线的两支分支都照旧可用。
- **动点在轨道上作切线，切线随它动态变化（2026-09-18，用户口径：「动点在轨道上能够在动点位置画切线，同时切线能根据动点位置进行动态变化」）**：选中一个已经绑定到曲线轨道上的动点，右侧出现「**在动点处作切线**」。切线保存的是那个**点的引用**（`anchor: { kind: "point", pointId }`），不是当时位置的快照——因此拖动动点或改「路径参数」，切线沿轨道跟着转。重算优先读**动点绑定里的参数**而不是它的坐标：坐标是派生缓存，读它会让切线在拖动那一帧慢半步，看起来像在追着点跑。依赖图里声明了「点 → 切线」这条边，级联删除也一并接上：动点删掉，切线跟着消失。锚点也可以是一个**没绑在这条曲线上**的自由点，那时取它到曲线的**投影**作为切点（"在曲线附近放一个点、在它那里作切线"是合理用法，不该被拒绝）。
- **第二动点作为圆心作圆，半径可调、也可随动点变化（2026-09-18，用户口径：「第二动点能够作为圆心作圆，圆的半径能够调节，也能够根据动点位置进行动态变化」）**：选中一个点后右侧出现「**以点为圆心作圆**」，生成的圆保存 `centerPointId`（圆心就是那个点，拖动点圆心跟着动，直接拖圆本体也会转成拖圆心点）。半径有两种方式：默认是**可直接编辑的数字**；一旦在「半径随动点」里选中另一个动点，半径就变成"圆心到那个点的距离 × 倍率"，于是圆**始终经过那个动点**，它沿轨道滑动时圆的大小自动变化（倍率用来做「半径 = 2 倍距离」这类题）。`center` 与 `radius` 都是**派生缓存**，真值是那两个点图元，重算在主循环里读刚算出来的点坐标（放在预扫描里会慢一帧）。半径被驱动时检查器里的半径输入框会禁用并说明原因，画布上也**不再画半径手柄**（拖了会被重算覆盖，留一个假控件比少一个更糟）。删掉圆心点，圆跟着消失；只删掉半径驱动点，圆保留、半径回到最后一次算出的值（悬空引用绝不留）。
- **切线可以用鼠标直接沿曲线拖着滑（2026-09-18，用户反馈："切线不能在曲线上自由拖动"）**：在切线**任意位置**按住拖动，切点就沿来源曲线滑过去。两个根因都修了：① 画布上切线那一组**只有 `onClick`、根本没有 `onPointerDown`**，指针按下时拖动从不成立，只能点选；② 就算起拖，平移一条**算出来的**切线也是空操作（切点由定位方式决定，平移会立刻被重算覆盖）。现在的语义按定位方式分三种：**曲线参数**定位 → 投影指针到来源曲线、改 `anchor.parameter`；**跟随动点** → 位移转给那个动点（复用已经跑通的"拖动动点"通路）；**函数来源的旧切线**（无 `anchor`）→ 横向位移加到 `x` 上。另外记一个**按下偏移**（"切点参数 − 按下处投影参数"），拖动时保持它，否则在离切点远的地方抓住这条线时切点会一按下就瞬移到指针脚下。选中时切点上会画一个控制点，因为"这条线能拖着滑"不是一个看得出来的性质。
- **平面画布整体收细（2026-09-18，用户反馈："平面画布中的线都太粗了，点也还是过大，变小"）**：图元线宽 **3 → 1.5**（选中 5 → 2.5），**点半径 4 → 2.5**，交点标记 4/5 → 2.5/3.5、圆锥曲线特征点 5 → 3.5、分析集标记 6 → 4、圆心小点 3 → 2、交点预览标记 4 → 3、定点十字圈 5 → 3.5、坐标轴 1.5 → 1.25（保住"几何 > 轴 > 网格"的主次）、控制点手柄 5 → 4。**命中区一律没动**（`strokeWidth="18"` / `r="14"` / `r="12"`）—— 那决定的是"点不点得中"，不是"看起来多大"；控制点手柄本身就是命中区，只从 5 收到 4，再小就不好抓。线宽由 `primitiveStyle.ts` 的 `strokeWidthFor` 单点决定，**SVG 导出复用同一份**，所以导出的图与屏幕一致；用户手动设过线宽的对象不受影响。

- **读数分得清"精确"与"近似"（A1，2026-09-17）**：圆柱 / 圆锥体积 `πr²h`、`πr²h/3`，立方体 / 棱锥体积，空间圆面积 `πr²`，平面多边形面积，都是闭式 → 标**输入精确**；多面体体积是**网格求和**（对 48 边形的圆柱 / 圆锥就是不精确的），距离 / 长度 / 角度 / 二面角由坐标推出，一律保持**数值近似**。同一个「解析截面」块还会给出**解析面积与周长**：圆 `πr²` 与 `2πr` 标精确，椭圆面积 `πab` 精确而周长是级数、如实标数值近似；**被端面裁切的截面**（椭圆弧 + 端面弦）如实显示"由端面裁切，无解析闭式"，不拿 `πab` 冒充那个区域的面积。
- **交点 / 交线 / 交面是三个各自独立的图元，自动铺开、点一下就建**（2026-09-17）：画布不再等用户选中两个对象，而是**自动枚举场景里所有两两相交的顶层实体**（`cube/pyramid/cylinder/cone/polyhedron3`；模板物化出来的点/棱/面/多面体不算独立实体，面与平面不参与，避免一个立方体的 6 个面互相刷出几十条噪声交线），每一对给出三类**可独立点击**的预览：
  - `pair:<a>|<b>:线` 虚线**交线**（两个表面的公共边界）→ 点它创建 `intersectionLine`（段数 / 总长度）；
  - `pair:<a>|<b>:面<i>` **交集的每一个面各一份**半透明**交面**片 → 点哪块建哪块，创建 `intersectionFace`（**一个表面**：面积、法向、顶点数，**填充色 / 描边色 / 透明度可改**）；
  - `pair:<a>|<b>:点<j>` **交线上值得标的交点**圆点标记 → 点它创建 `intersectionPoint3`（跟随两个来源重算的空间点）。标记只取**真正的角点**：相邻线段**转折 ≥ 18°** 的顶点、悬挂端（只连一段）与分叉点（连三段以上），最多 12 个；立方体↔立方体仍然是那 8 个角。**光滑交线一个点都不标**（圆柱↔圆柱这类只留交线与交面可点）——旧实现把折线的每个顶点都标一个点，一对 48 段圆柱会冒出上百个标记；中间版本折中成"没有角点就沿交线均匀补 4 个"，用户随后否掉："曲线相交时交点太多了，完全不是我们需要的那种"。实测两个正交圆柱（48 段、交线 96 段）现在只有 2 个标记，且都落在底面圆的边上（交线拐到端面圆环上的真角点）。状态栏文案据此说"拐点"。
  完全包含时两个表面根本不相交：只有交面、没有交线与交点（这是数学事实，不是缺省）。状态栏会说明"已自动标出 N 处交线、M 处交点、K 个交面：点虚线创建交线，点圆点创建交点，点面片创建交面"。

- **桌面版 Agent：一句话 → 草稿预览 → 你确认 → 真的落盘 → 一步撤销（G1 / G2，2026-09-21）**：Agent 工作区里把要求写成一句话，运行会走"检查环境 → 读取场景 → 规划（真实模型，provider 与通道由「服务」里**正在使用**的那一份决定）→ 暂存**隔离草稿** → 校验 → 等你在确认面板上看过 → 提交"。**确认之前画布一个字节都不会变**，确认用的同意凭据由宿主一次性铸造（不可伪造、与预览哈希绑定、会过期），撤销一次就回到原样。确认面板把"会新增/改动多少、按类别怎么分、模型替你做了哪些假设、只占一步撤销"写清楚，**不打印整份文档**；认不出要求时它**问**你，而不是编一段回答。**两条与"画布上已经有东西"有关的硬保证**（2026-09-21 修的真实缺陷）：①新对象的 id **一定避开文档里已被占用的 id**（手工画图的取号规则与 Agent 共用同一条，不再有两份；此前画布上已有一个立方体时，Agent 新建的第一个立体必然撞号失败）；②应用**启动恢复**过的文档照样能被 Agent 起草（恢复时物化出来的子对象带有 `undefined` 字段，规范化哈希现在与 JSON 语义一致：`undefined` 等于"没有这个字段"）。**如实缺口**：图像输入（`vision` 探针没有对真实服务跑过）、Anthropic 档的真实往返、`tauri dev` 热重载与打包安装器；密钥"存 → 重启 → 检测 → 轮换 → 删除"的手动验证需要你本机操作。
- **剖切面自由摆放**（2026-09-16）：属性面板新增「剖切面」区块（法向量 / 截面点数 / 分类读数 + 绕 X/Y/Z 各 ±15° 倾斜按钮），画布显示控制新增「取面」——点它再点实体上的某个面，该面即成为选中截面的剖切面（不共面的环会被拒绝）。旋转绕**实体中心**（而不是平面自身垂足）进行，否则刀口会被推出实体（实测平面到原点距离 1.5 → 0.15，截面消失）。**曾经的限制**"法向正好落在坐标轴上（如恰好 90°）时截面解析失败"**已修**（2026-09-17）：根因是旋转给出的法向带 ~1e-17 残差、同一个交点在不同面上算出的坐标差几个 ulp 而被当成不同点；点键改为按模型尺度量化后，默认水平面与「取面」选到的侧面平面都能正常成环。

## 明确限制

- 等长/等角约束尚未纳入 DSL：为避免出现“能校验但算不出残差”的约束类型，本切片只声明点在线、点在面、共线、共面、平行、垂直和固定距离；等长/等角需要先确定角度表示，随空间关系教学切片加入。
- **三维约束当前在界面上不可创建、也不可查看**：2026-09-16 的右侧面板精简移除了「几何约束」手风琴与约束列表面板（原 `ConstraintPanel`，已删除），唯一的约束入口函数 `constraintOptionsFor` 因此没有任何界面调用点。**约束数据仍然完整保留**——`document.constraints`、`addConstraint`/`deleteConstraint` 等 Scene Graph 操作、`constraints3d` 残差与冲突诊断、`.mgeo` 编解码与校验都未改动，旧文件里的约束记录照常读写；缺的只是 UI。若要恢复，可按 `diagnoseConstraint3` + `constraintResidual` 重建面板（两者仍在内核中并有测试覆盖）。
- 三维约束目前只做诊断、残差与冲突解释，不做投影求解：`solvePoint3Constraints` 返回当前点位置与诊断，不会移动任何点；投影求解与内角/外角选择一并排入后续切片。
- 固定距离约束的残差内核已实现，但同样受上一条限制：界面既没有数值输入入口，也没有约束列表可查看。
- 二面角已按内角报告并可选外角，但尚不区分“有向二面角”的符号约定；同一对相邻面在不同顶点顺序下仍是同一个内角。
- 点到直线/平面的垂足计算已在内核实现并有测试，但画布还没有绘制垂足与投影辅助线，距离测量只显示数值。
- ~~剖切平面目前不可在界面中调整~~ **已更新（2026-09-17 复核）**：新建截面仍默认用穿过来源包围盒中心的水平面，但剖切面**可以摆**——自由拖动模式下拖动截面（或按方向键）沿法向平移，属性栏「剖切面」块有绕 X / Y / Z 轴 ±15° 的旋转按钮；也可以用画布左上角「**以面为剖切面**」点实体上任一面，把该面直接当刀口。**仍没有**的是"直接键入法向量 / 偏移量"的数值输入框（旋转与平移走的是交互，不是数值编辑）。
- 布尔交集（交面）目前**只对凸实体成立**：L 形棱柱等非凸输入返回 `insufficient-data` 与"只对凸实体成立，这里不做近似"的诊断，而不是给一个看着像的错几何。**圆柱 / 圆锥这类曲面实体**（2026-09-17 A2 起）：交面按**支撑曲面**分组，一个连续曲面只给一个交面区域，边界是**解析的**（整圆 / 圆弧 + 端面弦），画布按屏幕误差把这块曲面画成**光滑曲面**（见「当前已实现」里的 A2 条目）；仍然**是网格布尔**——区域的多边形与曲面区域的面积来自 48 段网格（面积如实标 `areaExact: false`，侧带比真值小 0.071%），精确的二次曲面互交（圆柱∩圆柱那类交线是四次曲线）不在当前范围内。
- 交面 / 交点预览的配额是硬编码的（单次最多 12 对来源、每对最多 64 个面 / 12 个交点标记）：实体多且两两相交时后面的只画一部分，状态栏会说明，但还没有"按音量排序 / 只画视锥内"的取舍。**细分顶点仍存在于文档里**（圆类实体的面 / 棱 / 交线要用它们的坐标），只是不显示、不列出；要连文档里也不留，需要改成"隐式顶点"并重做 `face3`/`edge3` 的引用模型。
- `intersectionSolid`（交集整体）只剩旧文档兼容：新文档不会再创建它，展开图与二面角测量也**不**把 `intersectionFace` / `intersectionPoint3` / `intersectionSolid` 算进去。
- 截线/截面**不做布尔运算**，也不把实体真实切开显示内部：只提取并绘制交线，实体本身完整保留。
- 两个实体相交时给的是**面环之间的真实交线**，不为"任意两实体"猜一个剖切平面——想用默认剖切平面就先只选中一个实体。两个面**共面**时没有唯一交线，此时不预览。
- **圆柱与圆锥的"面环"仍是多边形近似**（48 段，文档里存的就是这些顶点，拾取 / 面片 / 展开读它们），但也有解析的一面（2026-09-17 A1 / A2）：**平面截它们得到的截面是精确圆锥曲线**（`section.exact`，画布是真曲线），**交面区域的边界是解析的**、曲面本身按屏幕误差画成光滑曲面，**边界圆（上下底 / 锥底）画的是真圆**；精确的**二次曲面互交**（两曲面相交的交线，多数是四次曲线）不在当前范围内——那种交线仍由网格求交得到。
- 展开状态目前不持久化：折叠进度是临时界面状态，`.mgeo` 不记录“已展开”，重新打开文件后回到折合姿态。
- 展开图重叠只做诊断不做自动布局：出现重叠时在诊断里说明是哪两个面，不会重新排布根面或面序。
- 未生成拓扑的旧截面文档走模板棱表回退路径，其交点按同一套平面内角度规则排序，因此新旧路径的截面点序一致。
- 两个点本身不能唯一确定一般抛物线；产品不会悄悄猜测一条抛物线。
- 采样函数和曲线的交点是数值近似，必须显示“采样/近似”状态，不能伪装成符号精确解。
- 采样曲线对的交点列表有 64 个上限：`sin(1/x)` 这类在视口内近乎无限次相交的病态函数不会无限增长标记，超过上限时只保留前 64 个数值解。
- 删除一个函数会连带删除它的导函数、切线、法线、割线、积分区域和分析集（它们是同一个对象）；但被**保存交点**引用的图元仍受来源删除保护，需要先删除引用它的交点。
- 极点、渐近线和无穷远交点不作为普通有限坐标点写入 `.mgeo`。
- 动画帧不逐帧产生撤销记录；只有停止、确认或手动改值才提交文档。撤销/重做可用按钮与 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`、`Ctrl/Cmd+Y` 触发（文本框内不抢键），无可撤销内容时按钮为禁用态；刷新后草稿恢复的是文档内容，历史不保留，因此此时撤销按钮为禁用。
- 任意 JavaScript 表达式、网络加载脚本和不受限用户代码不属于函数输入能力。
- 平面（`plane3`）画出来的是**有界**面片：默认按所属图形的包围盒自适应，也可在属性面板填入「半边长」固定尺寸（「恢复自动」清除该值）。仍没有在画布上拖动平面边界的手柄，也不能隐藏面片只保留平面定义。
- 四类参数化模板（立方体/棱锥/圆柱/圆锥）的朝向由可选 `rotation`（弧度，X → Y → Z）描述，属性面板按度输入并提供 0/90° 快捷角度；模板生成的顶点**只在模板自己的参数变化时才按模板重建**（2026-09-17 起），因此手工调过的顶点不会被无关改动拽回去，而"全量重算"仍会按参数把它修复。定向请用朝向参数。**新建实体的默认落点统一成"坐在地面上、分在四个象限"**（2026-09-17，用户反馈"图有点怪"）：四个模板的底面都在 `z = 0`（此前立方体与棱锥有一半埋在地面下、圆锥还悬空 3 格），四个足迹两两不重叠（此前立方体与棱锥本就相交），原点正好落在它们中间；只影响新建实体，已有文档不动。
- 在三维画布上点击**模板实体**（立方体/棱锥/圆柱/圆锥）的棱或面，默认选中整个实体（这是让实体可被点选的关键规则）；需要选具体棱/面时按住 **Alt 点击**即可，也可继续在左侧代数区展开拓扑后选取。模板生成的**顶点**仍可直接点选，保留点驱动编辑。
- ~~`circle3` 目前只在 DSL 与内核中存在，画布没有渲染分支~~ **已更新（2026-09-17 A1）**：`circle3`（空间圆）现在**真的画出来了**——`conic3FromCircle3` 把它变成解析圆，画布按屏幕误差细分成真曲线（可点选、进对象列表、可导出到工程图并投影成真椭圆）。界面入口仍然没有（它是给构造 / 旧文档与投影用的图元类型，不影响课堂流程）。
- 三维视角的移动范围被有意限制：枢轴只能在以当前图形包围盒中心、半径为其 3 倍的范围（无几何时为原点周围 ±12）内平移，避免把图形拖出画面；需要更大范围可先「适应视图」或移动图形本身。

### 体检结论与已知限制（2026-09-17）

- **"实体内"（`inSolid`）宿主只对凸实体提供**：凹实体（例如 L 形棱柱）不再返回宿主——夹取几何在凹体上会停在空腔里、甚至把绑定点留在空中，因此宁可让约束报"数据不足"。面平面朝向改用**有符号体积**判定（不再用可能落在体外的顶点形心），面法向的退化判据也随实体尺度缩放，因此毫米 / 微米量级的实体照常可用。绕向自相矛盾的拓扑同样被拒绝。
- **退化直线上的平行 / 垂直 / 共线约束被跳过**：求解结果把它们列在 `unsatisfiable` 里（不再假装"已满足"），但**不会**让求解失败——`recomputeDerivedObjects` 在 `!converged` 时抛错，若把退化也算失败，"把一条被约束的线拖成一个点"就会让整份文档报错。
- **剖切平面的法向必须有效**：零法向（或相对模型尺度可忽略）以前会"凭空造出一片截面"并报 `polygon`，现在返回 `insufficient-data`，不产出任何点。
- **顺时针圆弧的参数域是升序区间** `[endAngle, startAngle]`，投影参数也折回该区间；滑块与动点因此不会一拖就跳到端点。
- **PDF 导出只支持 WinAnsi 字符**：中文注释与中文诊断会被替换成 `?`（导出成功、内容如实标出"有字打不出来"）。真正的 CJK 需要内嵌字体（体积与许可证都要考虑），尚未实现。
- **不可读的草稿会被保留**：能解析成 JSON 但当前版本解不出来的草稿挪到 `mathcanvas:draft:<工作区>:unreadable` 旁路键并提示用户；只有"根本不是 JSON"的垃圾数据才会被清掉。多标签页 / 打开文件覆盖草稿仍**没有**版本比对（需要 `storage` 监听与修订号语义）。
- **e2e 现在构建当前工作区**：`e2e/global-setup.mjs` 按 `apps/web` 的 vite 配置重新构建 `build-check/mathcanvas-current` 再起 preview。之前它直接 preview 这个可写目录，实测跑的是几天前的旧 bundle——"Playwright 全绿"曾与源码无关。用户在 127.0.0.1:4175 上手工验收的预览也是同一个目录（刷新页面即取到新产物）。
- **仍未修的性能项**：`DrawingViewport` 移动阈值会丢弃编辑、每帧自动保存草稿（已确认不会丢数据，属体验优化）；`boolean3d` 的顶点索引已在体检第四批改为哈希表（48 段 137ms → 27ms）。
- **角度标注（两条棱）在公共端点处测量**：折线拐角（一条棱的终点正好是另一条棱的起点）量的是那个角；两条棱没有公共端点、或完全重合时没有唯一可量的角，报"数据不足"而不是给一个错的度数。
- **工程图导出不再限制视图数量**：SVG 画布高度按行数增长、PDF 每个视图一页、DXF 直接列出全部视图（此前三者都硬写"最多 4 个"，第 5 张起会被静默丢掉）。
- **导出 CSV 带 UTF-8 BOM**：Excel（Windows）在没有 BOM 时会按本地 ANSI 解码，中文标签会变成乱码。
- **`persistence/mgeoStorage.ts` 已删除**：它只是 `encodeMgeo` / `decodeMgeo` 的转发壳，全仓库没有生产调用点；原先经它执行的 3 个往返用例改为直接调用真实编解码入口（`mgeoRoundTrip.test.ts`），覆盖不变。
- **仓库无乱码注释**：体检时按字节扫描了 280 个源文件与文档的乱码特征字符，没有任何命中（此前在终端里看到的中文乱码是 `Get-Content` 按 ANSI 解码的**输出**问题，不是磁盘内容；仓库改文件仍一律用编辑工具）。
- **射线交点判据随坐标尺度**：`onRay` 的垂距容差改为 `scaledTolerance`，在 ~1e6 的坐标上不再把"确实相交"误判成"交点在射线起点之后"（真正落在起点之后的解仍然被挡掉）。
- **展开（`unfoldPolyhedron3`）的面法向用整个环的 Newell 法向**：环上前三点共线是合法多边形，旧实现取前三点叉积会得到零向量、把展开角当成 0 度、让侧面留在折合姿态却报 `ok`；现在只有环真的零面积才失败，并且是**明确报数据不足 + 诊断**（"环无法确定法向（面积为 0），展开角不可解"），不再静默折合。
- **死代码清理：`store.ts` 的预览三件套已删除**（`beginPreview` / `previewParameter` / `commitPreview` / `cancelPreview` 与 `previewBase` 全仓库没有调用点，且 `apply` 会清掉 `previewBase`，预览中途再改一次永远回不到基线）。
- **布尔交集的顶点索引改为哈希表**：`clipByPlane` 原来每插入一个顶点就线性扫描并重建字符串键（O(F·V) 次键构造）。实测两个圆柱近似的**一次**交集：48 段 137ms → 27ms、96 段 1025ms → 83ms（体积逐位一致）。大体量用例（6 次 96 段交集）现在是**性能回归的软守卫**——旧实现在默认 5s 测试超时内跑不完。
- **相机记忆按文档保存**（最多 4 个，最近使用的优先保留）：此前只有一个槽位，交替打开两个 3D 文档会让前一个的视角被覆盖掉；记忆仍只在内存里，刷新回到默认视角。
- **工程标注不抢指针**：投影视图里的尺寸 / 公差文本加了 `pointer-events: none`，标注压在图元上时点击仍然落到图元（标注本身没有点击处理，只是读数）。
- **草稿夹点可用键盘操作**：已选图元的夹点是可聚焦的按钮（`role="button"` + `aria-label` 读对象名），方向键按 1 个世界单位移动、Shift 加速 10 倍，走与鼠标拖动同一条提交路径（因此撤销粒度一致）。
- **`Tab` 不再是键盘陷阱**：多个捕捉候选重叠时的 `Tab` 循环只接管**不带 Shift** 的按键，Shift+Tab 交还浏览器，键盘用户可以走出绘图视口（WCAG 2.1.2）。
- **内核容差与输入护栏（2026-09-17 体检第六批）**：`polyline.pointOnRay` 的垂距判据随坐标尺度缩放（~1e9 坐标上不再误判）；只有一个点的折线，`distanceToPolyline` 返回"到那个点"的距离而不是 `+Infinity`；`buildSolid` 的内部异常诊断会带上原始消息（不再把内部崩溃说成"输入不合法"）；`MAX_SOLID_SEGMENTS = 256` 卡住分段数上界（`segments: 1e9` 不再去分配十亿个顶点，与 DSL schema 的上限一致）。
- **自动保存的实测结论**：`encodeMgeo` 单次开销在示例文档上 0.029ms、200 图元 0.219ms、3000 图元 2.631ms——课堂规模的文档下可忽略，因此**不**为它加防抖（防抖会削弱"刷新即恢复草稿"的保证）。"一次按键一条撤销记录"是既有测试钉住的设计（历史上限 100 条），不是缺陷。
- **折线偏移要求每段都有方向（2026-09-17 体检第七批）**：带重复顶点的折线（连续两点重合）偏移时返回 `null`，不再抛 `TypeError`（旧实现只给末段判空）。
- **平面法向必须真的能归一化**：`(1e-30,0,0)` 这类数量级的法向在加载时仍算"非零"，但归一化会得到零向量——此时点到平面的距离测量报 `insufficient-data`、点面约束的残差为 `null`（不再把它当成"距离 0 / 永远满足"）。非单位但可归一化的法向（如 `(0,0,5)`）照常工作。
- **数值选项一律归一化（2026-09-17 体检第八批）**：二面角弧的 `arcSteps` 非有限时退回 12、并夹到 720 上限（`NaN` 以前会得到一个"标记存在但弧为空"的假结果，`1e9` 会去分配十亿个点）；公开的等距采样 `sampleFunctionSegments` / `sampleFunction` 的 `steps` 夹到 `1..4096`（`0` 以前算出 `NaN` 采样并静默返回空数组），定义域不是有限区间时返回空。
- **隐式投影的迭代上限（第九批）**：`maxIterations` 传 `0` / 负数 / NaN 时不再"一次都不迭代"，而是按默认 40 处理（此前会返回 `null`，让动点拖拽卡住）；正的有限值照旧尊重。顺带删掉同函数里只写不读的 `totalIterations`（lint warning 15 → 14）。
- **隐式约束的残差在梯度退化时给真实距离（第十批）**：梯度为零的点（例如椭圆中心）以前退回 `|F|`——那是 F 的量纲不是距离（实测 16，而真实距离是 1）；现在改用精确投影的距离。
- **参数容差与长度容差分开（第十批）**：`inUnitInterval` 用的是固定的无量纲 `PARAMETER_TOLERANCE = 1e-12`，不再接收调用方的长度容差（否则长线段上端点之外的点会被算成"在段内"）。
- **体检覆盖说明（收口）**：审计方声明未覆盖的两块已由本轮补齐并判定无缺陷——`IntersectionPreview3dCache` 的剪枝（缓存只含本次扫描的 pair、`truncated` 不入缓存、上限 120 生效）与 `threeScene` 的 rAF / 拖动内部（`pointercancel` 有绑定、卸载会取消取景动画并清运行时引用、拖动会话与指针状态同生共死）。**仍未改**：`pointercancel` 提交拖动而非中止（需要先确认触摸平台的手势语义）；依赖图对 3/4 目标约束（共线 / 共面）不建边；`boolean3d.compact` 每面一次 `sort + join` 的签名拼串（微小开销）。
- **平面画布的网格是固定尺寸（用户要求）**：一格恒为 **1 个世界单位**（`GRID_CELL`），每 10 格一条主线（`GRID_MAJOR_EVERY`），缩放只改变**可见范围**（看到更多 / 更少的格），格子的世界尺寸不变——与 3D 背景坐标系同一套语义。旧实现按屏幕像素挑"好读"的步长（0.1/0.2/0.5/1/2/5/…），缩放时格子本身会变，网格因此不能当尺子用。画布上有 `data-grid-cell` / `data-grid-major` 读数可供断言，`e2e/planar-grid-cell.spec.ts` 在真实浏览器里量相邻网格线的世界间距恒为 1。
