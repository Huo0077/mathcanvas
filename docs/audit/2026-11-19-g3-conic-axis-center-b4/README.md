# G3-F9 B4：模型参数与真实二次曲线方向一致（零付费）

- **真实问题背景**：[上一轮36题原生 DS 审计](../2026-11-18-g3-f9-native-36-10x/README.md)中 `construct_conic` 调用 18 次，其中 12 次有 `missing_required_parameter` 回执；GK-P08 题面含纵轴双曲线。历史逐题报告未保留原始工具参数，因此**不能说当时模型传了轴/中心，也不能把这12次全部归因于本缺陷**。
- **代码证实缺陷**：`construct_conic` 已向模型发布 `axis/cx/cy` 字段，旧执行器却把双曲线固定成 `axis:x`、双曲线与椭圆中心固定成 `(0,0)`；非法轴还会静默变成横轴。这可导致图元存在而图像含义错误，比明确失败更危险。
- **修复**：现在把合法的 `cx/cy` 带入几何内核的 `center`，把双曲线 `axis:y` 带入最终 `planar.create_conic` 和物化图元；保留原先未提供时中心原点、横轴的兼容行为。显式非法的 `axis`、中心数值以及跨曲线族不兼容字段均返回可修复错误，绝不偷换方向或忽略假参数；模型可见工具描述同步列出方向与中心含义。
- **RED/GREEN**：新增纵轴偏移双曲线及偏移椭圆的动作和真实 `compilePlan` 图元验证；原实现曾报告 `axis:x`、`center:(0,0)`。新增非法轴/中心、错误曲线族字段反例，原实现会错误 accepted。更改后定向 Vitest 220/220、类型检查通过，既有 GK-S09 浏览器正例 1/1。本检查点不发起 DS，不提高旧版通过率。代码和测试仍不证明新模型会选择对的参数。
- **剩余**：多数失败仍是缺参数、缺实体引用或终止前澄清；通用 `construct_conic` 参数虽已公开，但每个曲线族的条件必填仍需要进一步收敛。13题缺核验原图、原生真实交付和新固定提交下真实 DS 复测仍未完成，需另获付费授权。
