# 比例构造与立体评测修复

## 修复来源

基于`6aa8a7f`的评审，已复现“同题英文冒号通过、中文冒号失败”及“编译失败但题设报告passed仍被计为成功”。同时发现真实评测会随带密钥的普通测试自动启动，请求没有截止时间，注释所说的报告文件并未写出，原30题也没有覆盖翻折。

## 几何构造

`solver/foldRatios.ts`直接消费统一题设IR的given/supported条件，折片构造不再维护另一套比例正则。`AE:AD=2:5`、`AE：AD=2：5`、`AE=2/5 AD`及反向`AD:AE=5:2`使用相同参数。比例必须落在线段内部；冲突条件不互相覆盖，也不把越界值夹成0或1。最终仍由整题核验确认坐标，测试独立量取AE及AF长度。

## 计分

成功出图必须同时满足：计划类型为plan、编译ok、有非空草稿、整题核验passed。原始计划存在错误动作时，即便部分题设报告passed，仍计为失败。`evaluateSolidPlan`由在线评测和离线回放共用。

欠定反例若编译失败、无草稿且出现预期诊断码，单独计入`expectedRejections`；若模型给出合法澄清信封，则单独计入`expectedClarifications`。两者均不增加成功出图数。澄清不是数学证明；对于要求成功作图的正例，澄清仍不算通过。传输失败、空输出或不可回放行不能伪装成“正确拒绝”。

## 入口与预算

普通`npm test`排除真实模型用例。环境里只有`DEEPSEEK_API_KEY`也不会发请求；独立配置还检查显式运行标记及整数请求上限。

```bash
# 无网络、无需密钥：先验证可回放的错误计划不会误计成功
npm run eval:solid -- --replay test-fixtures/solid-eval/failed-plan.json

# 只查看选项，不调用服务
npm run eval:solid -- --help

# 以下是会调用付费服务的手工命令；本轮未执行
# 先在本机环境中设置DEEPSEEK_API_KEY，密钥不要放进命令、文档或仓库
npm run eval:solid -- --allow-paid --max-requests 36 --suite all
npm run eval:solid -- --allow-paid --max-requests 6 --suite folds
```

| 选项 | 行为 |
| --- | --- |
| `--max-requests` | 必填整数1–60，包含规划器的传输重试；耗尽后剩余题记录预算失败，不再请求 |
| `--suite` | `solid30`原30题、`folds`翻折6题、`all`共36题；默认all |
| `--timeout-ms` | 单次HTTP请求及响应体读取共同截止；默认60000，允许100–180000ms |
| `--max-tokens` | 输出上限，默认4096，允许1–131072；仍须符合所选模型实际限制，首轮沿用产品策略最多4096 |
| `--replay FILE` | 读取v2报告中的原始计划和题面，重新编译、核验、计分，不调用provider |

配置兼容`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_TIMEOUT_MS`及`DEEPSEEK_MAX_TOKENS`。请求上限必须由命令显式给出，不把环境里的旧预算当成本次授权。`--allow-paid`是用户运行命令时的明确选择，不会因为存在密钥而自动启用。

每题发起一次规划调用；产品规划器内部仍可能恢复传输失败，额外请求计入同一总上限。本入口没有驱动协调器的编译/格式修复，也没有覆盖Rust传输、真实预览提交或数值答案证明。次数上限不等于美元上限；报告记录tokens，不在缺价目表时假装费用为0。

命令成功表示评测执行并保存了报告，不表示全部题成功；效果以报告的严格计分及每题诊断为准。离线回放只能重算已保存的计划，没有计划的传输/解析失败行保留为未通过，不会自动发起补跑。

## 题单与报告

原30题不改编号及分母。另增：f01单折距离反求、f02中文冒号、f03明确角度的连续两折、f04双未知角、f05三未知角（约束PB/QB/RB）、f06双未知角且缺少终态条件。扩展题用于补齐覆盖，不与历史4/30直接比较。

CLI为每次运行生成唯一的`eval-results/solid/*.json`路径，并在结束时打印位置。该目录已被Git和lint忽略，独立于Playwright会清空的`test-results`。报告包含：

- 代码提交、系统提示词版本、模型、请求/输出/时间限额、开始时间、选定题数和完成状态。
- 每题原文、预期行为、HTTP请求消息、响应体及归一化事件；不保存鉴权请求头。
- 原始计划、编译结果、完整诊断和核验报告、构造假设，以及按严格口径重算的计分。
- 请求和token计数；运行中题号、已完成题目及其逐题检查点。

报告先写临时文件再原子替换，初始化、每题开始、每题结束与正常退出/取消均保存。取消会传至HTTP信号，超时也中止读取；即使某个fetch实现不理会abort，评测本身仍会按截止时间返回。强制杀进程只保证保留最后一个完整检查点，进行中题目的请求计数和token用量可能尚未保存。

历史脚本只打印汇总且未保存完整原始计划，无法据此复算历史4/30。该数值继续留在[历史记录](2026-10-25-solid30-model-eval.md)，已经标明旧统计缺陷与未复测状态。
