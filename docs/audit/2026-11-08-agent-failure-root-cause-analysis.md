# 历史错题与未完成问题：根因复核（2026-11-08）

## 1. 结论先行

问题不是一个统一的“模型不够聪明”，而是五类故障叠加：

1. **读错或漏读题设**：三视图尺寸、图形选项、连接与虚实线丢失后，推理建立在错误输入上。
2. **题意与目标不完整**：忽略矛盾条件；合并问句漏问；折前、折后与不同小问作用域混在一起。
3. **数学推理错误却缺少独立否证**：错误使用勾股、全称不等式方向反转，并非调用工具成功就能解决。
4. **协议与交接失败**：回答带计划分支字段、只读工具与计划混批。某些旧故障已有修复，不能重复列为现存问题。
5. **交付状态不准确**：内部算出但无正文；空答、请求补图、错误选项都可能以 completed 结束。它表示流程结束，不是题目已做对。

**推荐顺序：先让系统准确说明“回答了什么、验过什么、还缺什么”，再增强数学与视觉能力，最后通过真实入口重新评测。** 不建议只换模型、扩长答案或针对每道原题加正则。

本轮是调查、离线证据与待实施方案；**未修改生产代码，未宣称缺陷已修，未新测真实模型成功率，未发布或推送。**

## 3. 分类型根因与解决方向

### F1：三视图缺尺寸后“自补题设”

- **mm-005**：参考 B=9。旧读图未给全网格尺寸，规划器先设 3×3×3，算得不在选项后，又借“常见版本”换尺寸，最终选 A=6。
- **mm-009**：旧推导得到 16+4π，不在选项后改尺寸并选了其他答案；参考为 16+8π。
- **mm-075**：视图对应与高度读错；回答要求核对原图，但仍以 answer 完成，没有明确选项。

机制：尺寸没有来源约束；选项反向成为补题设的依据；主规划器仅收到读图文字摘要，不能自主回看原图。

源码：apps/web/src/services/problemImagePrompt.ts 的证据交接；apps/web/src/agent/modelPlanner.ts:307–320 只把 imageNotes 加入规划消息；agentRunner.ts:565–582 已对结构化疑点提供澄清，但无法发现模型根本未声明的遗漏。

**置信度**：历史失败原因高；当前文字交接限制由源码确认；后续识图修复后旧题的真实重现频率未知。用户勾选代表核对来源，不代表数学真值。

方向：尺寸、投影轴、图像区域建立来源关系；关键尺寸缺失时局部重读或澄清。候选实体必须重投影一致；不唯一时明确不唯一，不能用选项补齐。

### F2：圆锥曲线推理错误而缺少答案级核验

#### text-128：双曲线离心率

旧答把 OP 与 OF₁ 当作垂直，用 PF₁²=a²+c² 得 e=√5。这个垂直关系不成立。

取 P=(a²/c,ab/c)、F₁=(-c,0)、c²=a²+b²，独立展开：

~~~text
OP²=a²
PF₁²=(a²/c+c)²+(ab/c)²=c²+3a²
PF₁²=6OP² ⇒ c²=3a² ⇒ e=√3（参考 C）
~~~

本轮反例：a=1,c=√5 时 PF₁²=8，题设要求为 6，可在交付前否证旧答案。

#### text-198：椭圆全称不等式

对所有椭圆上点 P 满足 PB≤2b，令 t=sinθ∈[-1,1]，距离平方为：

~~~text
q(t)=(b²−a²)t²−2b²t+a²+b²
~~~

必须检查端点、驻点是否在区间以及参数分支，不能只写“求导后显然”。正确条件为 a²≤2b²，即 0<e≤√2/2（参考 C）。旧答反转了方向。

本轮反例 a=2,b=1,t=-1/3 给出 PB²=16/3>4。完整核验还需 a>b>0、a²=2b² 边界与驻点越界分支。

**置信度**：高，属于数学错误而非 OCR。只读回答允许空工具引用，不要求答案级数学判据。

方向：先做有限的距离/代回/二次最值核验，支持域外返回 unknown；数值抽样未遇反例不能等价于全称证明。

### F3：折叠题条件、目标、状态交接不完整

本轮 24 题核心参考判据仍为 18/24：

| 条目 | 本轮观察 | 根因 |
| --- | --- | --- |
| E06 正方形措辞 | 未命中求解 | 等价表达覆盖不足 |
| E10 合并问折前折后 | 仅输出折后长度 | 目标拆分与状态丢失 |
| E13 口语问长度 | 有计划但无长度和正文 | 作图计划不等于完成解题 |
| E15 只问折前 | 仍要求折角 | 未按目标依赖裁剪求解 |
| E18 对角线条件矛盾 | 仍交付结论，未报矛盾 | 题设读取或检查不完整 |
| E19 辅助垂足 | 缺 E 点，未核验 | 辅助定义未进入依赖 |
| E23 反求折角 | 内部约135.951°，无答案正文 | 求解结果未进入交付 |

E23 核心数值检查为通过，但不能算用户看到了答案。rectangleFoldPlan.ts 目标类型与答案组装仍有上述边界；应先修逐目标交付，而不是仅多生成一个图元。历史材料见 [24题说明](2026-11-03-agent-example-validation.md)。

方向：复用已有 IR，补子问、前后状态、辅助定义与依赖，逐目标组装答案。只问折前不得先追问无关折角。

### F5：completed 未表达数学核验结论

coordinator.ts:607–627 对 answer 只检查引用结果存在后，即可进入 completed，空 toolResultRefs 合法；schema 还允许空回答。本轮三类脚本注入走到了同一条结束路径。

**项目已有草稿编译、题设几何核验、任务验收和用户确认，不能说完全没有核验。** 但这些不覆盖所有只读数学答案；obligationIR.ts 也明确目标不可自动当作已核验。

方向：运行阶段与解题状态分离。未核验回答可展示但标明未核验；空答不得标已作答；缺条件应待澄清。不同答案类型分开验收，不能要求普通聊天和证明题也有 A/B/C/D。

### F6：题族路由窄，现有 IR 尚未贯穿全部链路

本轮标准三角递增题命中 functions；同式递减与自然措辞不命中，随后会回退，不必然错误。但同一数学能力因措辞不同走不同路径，稳定性不足。

已有 obligationIR.ts、claimEvidence.ts 包含角色、来源与判定力，numberedProblem.ts 支持部分连续编号；应扩展并贯穿，不新建第二套事实源。分母分组在本轮样例已修，diagramVerification.ts 已有按身份选曲线逻辑，不能继续把旧报告的这两点原样当待做任务。完整泛化仍需新测试，单样例不足以证明。

## 4. 分层诊断

| 层面 | 风险 | 应建立的约束 |
| --- | --- | --- |
| 输入与视觉 | 漏读且无法回看 | 可追溯证据、受控重读 |
| 题意上下文 | 条件/目标/状态丢失 | 统一义务结构、逐问覆盖 |
| 规划与能力 | 窄模式路由 | 能力清单、语义变式回归 |
| 工具合同 | 分支误填、混批、参数类型错 | 同源合同、全批拒绝、结构化反馈 |
| 数学核验 | 无依据关系、量词/边界错 | 独立代回/否证/解析判据 |
| 恢复编排 | 缺证据与数学错同样重试 | 有类型失败、共享预算 |
| 状态呈现 | 内部结果未交付、完成误读 | 逐问结果、证据等级可见 |
| 评测发布 | 核心链路不等于产品入口 | 双轨、留出集、版本标识 |

这不是完整12层全栈审计；未逐项审 Rust 网络、全部工具、CAD 与所有 UI/供应商。

## 5. 方案取舍与推荐

- **只补提示/换模型**：快，但不能强制来源、目标覆盖与答案状态，仅作为辅助。
- **不断增加原题规则**：固定样例可能好看，但易过拟合；确定性解法应以可复用题族为边界。
- **推荐渐进路线**：复用 IR 和安全草稿，补目标化交付、有限独立核验、视觉闭环与分类恢复，每阶段独立验收和回退。

详见 [具体实施计划](../superpowers/plans/2026-11-08-agent-reliability-remediation.md)。首批建议合同、空答/澄清状态，再修目标遗漏与折叠问题，不等待通用求解器。
