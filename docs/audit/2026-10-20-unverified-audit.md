# 2026-10-20「无核验项」7 道审计（联考 30 题）

2026-10-19 那份 30 题评测（[`agent-drawing-eval-20261019.md`](../agent-drawing-eval-20261019.md)）里有一栏读数最难解释：**「无核验项」7 / 30**。它的意思只是"这一题没有解析出可核对义务"，既不代表画对了，也不说明为什么。本文把这 7 道逐个审一遍：**题面到底是什么、今天读出了什么、缺的到底是哪一层**。

本文只记**读得出 / 读不出**这件事，不涉及重新花钱跑 provider。

## 一、口径：这里说的"无核验项"到底是哪个空

评测文档原文写的是「无核验项（`verification` 为空）」。**这句表述不准**，本审计先把它改对：

- 核验报告（`verifyDiagramObligations`）**永远不会是空的** —— `checks` 为空时它会补一条"没有可靠识别到可核验的题设，不能用空报告宣布全部通过"的未核验项（`packages/agent-core/src/diagramVerification.ts:1422`）。
- 7 道的实情是 **`givens`（可核对义务）为空**。其中 5 道连 `unverified`（读不出但显形的从句）也是空的。
- 在批量 harness 里，这 5 道表现为 **`diagramVerification === undefined`**（`planCompiler.ts:742` 的闸门要求"有义务或有未核验"才出报告），也就是**核验这一步根本没有发生**，既不是通过、也不是未通过。

所以正确的说法是：**2 道"读了但读不出"，5 道"没有跑核验"。** 后面这种更糟：报告不存在，而界面上"确认并提交"照旧出现。

## 四、分类：缺的是三种不同的东西

### A 类｜标量尺寸（5 道：joint-01 / 07 / 09 / 10 / 12）

题面给的是一串**标量**：底面半径、母线长、底面积、侧面积、底面周长、侧棱长、仰角、高度。这类条件今天**两层都缺**：

1. **判据层没有"实体尺寸"这一类义务**。既有义务全是"点名之间的关系"（长度、角度、共线/共面、垂直/平行、点在曲线上……），`solidDimension`（"这个圆锥的半径是 2"）根本不存在，所以解析器即使认出"底面半径为 2"也无处安放 —— 读成 `unverified` 才是诚实的。
2. **更早的一层就断了：核验根本没跑。** `planCompiler.planHasVerifiableFigure`（`packages/agent-core/src/planCompiler.ts:80`，白名单在 `:51`）只认"能让题面点名的顶点拿到坐标"的动作：`solid.create_polyhedron` / `solid.create_face` / `planar.create_point` / `planar.create_conic` / `function.create_graph` / `function.create_tangent`，以及**带 `vertexNames` 的** `solid.create_prism`。**圆锥与正 N 棱锥不在里面** —— 它们的顶点只有模板自己的顺序编号（`P1…Pn`），题面的 A、B、C 一个都对不上。于是 `obligations` 是 `null`、`diagramVerification` 是 `undefined`，`givens` 与 `unverified` **一个都没产**。

第 2 条是主因。它是**刻意的边界**（那条注释就写着"模板实体的原文核验是另一件工作，要单独做、单独取证据"），不是疏忽；但它带来的用户可见后果此前没被说清 —— 见 §五。

### B 类｜曲线参数（1 道：joint-23）

题面给的是**双曲线的中心、右焦点、离心率**，没给方程 —— 方程要**解出来**（c = 2√5、e = √5 ⇒ a = 2、b = 4）。今天解析器只能从**方程**认曲线，从"焦点 + 离心率"反推曲线这一族义务不存在。所以"没有可核义务"在这道题上是**正确行为**，缺的是一条新判据（`conicFromFocusEccentricity` 之类），不是读取器。

> **2026-10-20 补记（同一轮的第二批）**：B 类**已经能读了** —— 但它**不需要新判据**：中心在原点 + 焦点在一条坐标轴上 + 离心率把标准位置的曲线**唯一确定**，推出来的 `a`、`b`、轴正好是既有 `conicAxes` 判据要量的那三样（`a = c/e`，椭圆 `b² = a² − c²`、双曲线 `b² = c² − a²`、抛物线 `p = 2c`）。补的是读取器 `resolveFocusEccentricity`，四条边界一起钉住（没说中心在原点 / 只有离心率 / 只有焦点坐标 / 离心率与种类矛盾 ⇒ 一律落未核验并给理由）。接缝证据：同一份计划喂 `compilePlan` —— 画成 `x²/4 − y²/16 = 1` ⇒ `conicAxes: passed`；两个半轴对调 ⇒ `failed`（不是"未核验"）。**边界**：只认标准位置（焦点必须在坐标轴上）；"中心不在原点 / 焦点是斜的 / 还有 `过点` 与焦点联立"这些今天仍然读不出。

### C 类｜已被后续批次覆盖（1 道：joint-16）

`圆 x²+y²−4x+3=0` 与 `双曲线 x²/16−y²/9=1` 今天**各读出一条 `conicAxes`**（共 2 条），因为评测之后的第五轮补了圆的一般方程读取器、第三轮补了"曲线名 + 标签冒号"那类写法。也就是说：**这道题在评测当时是 0 条，今天不是 0 条** —— 但**收益没有复跑确认**（要花钱跑真实 provider），只能说"方程认出来了"，不能说"这题已经全过"。渐近线本身仍然不读（它是从方程派生的，不该单独核）。

## 五、真问题：`diagramVerification === undefined` 时界面什么都不说

这是本次审计认定的**产品缺陷**（不是文档措辞问题）：

- 确认面板的核验那一段是 `{draft.diagramVerification && …}` —— 报告不存在时**整段不渲染**；
- 而"确认并提交"的闸门是 `diagramVerification === undefined || status === "passed"`（`apps/web/src/components/agent/ConfirmationPanel.tsx:269`）。

两条合起来：**"系统没有核"和"系统核过了"在界面上看起来一样**，用户会点确认。联考那 4 道（`joint-07/09/10/12`）正好落在这个格子里。

本轮修法（很小，只把话说清楚，**不动确认闸门**）：

- `ConfirmationPanel` 在 `diagramVerification === undefined` 时渲染一段 `data-status="not-run"` 的题设核验区，标题是「这一轮没有题设核验报告」，正文说清两条来路（不带题面点名的实体 / 题面本来就没有可核条件），并明说「核对这一步**没有发生**，系统没有替你核」。
- 判据在 `apps/web/src/components/agent/diagramConfirmation.test.tsx`：无报告⇒这一段在、且 `data-status="not-run"`、且确认按钮仍在（现状不变）；有报告（passed / unverified / failed）⇒这一段不出现，原读法一字不动。

**为什么不动确认闸门**：`undefined` 也覆盖"画一个正方体"这类**本来就没有题设要核**的题面，把它一刀切成不许确认是另一件事，需要单独裁决；这一轮只消灭"沉默"。
