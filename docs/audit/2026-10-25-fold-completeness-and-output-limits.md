# 翻折完整性与输出链路第二轮修复

基线：`fd50801`。本轮是开发改动，尚未发布，也没有执行付费模型评测。

## 翻折核验

此前仅创建满足底图条件的四边形，也可能被判定全部通过；即使题面明确要求 30°，模型给出的 90° 翻折也可能通过。

现在由 `verifyDiagramObligations` 在同一份报告中核对折前点、折后点、折痕、刚性与显式折角。缺少折后点或折角不匹配会形成失败项，不能沿用底图的 passed。编译与草稿复核都传递有效题面，防止预览层再次丢掉这些检查。没有其他数值条件的纯翻折题同样进入这条路径。

折角通过候选坐标在折痕垂直平面内的投影夹角独立测量，不以动作中填写的角度为核验结果。未指定方向时核验转角大小，不把两种旋转方向混成题面已指定的侧别。方向语义及任意多未知折角联立求解仍不是通用已交付能力。

对救援构造，保留内部的几何计算结果用于取折前坐标；失败结果仍不产生公共草稿。补折时遵守题面明确角度，不再无条件使用 90°。

## 连续翻折

读取器为每条变换记录原文起止位置，并按原文顺序合并不同句式。每个显式角度只绑定其所在变换，不再用全局数字数组的位置配对。因此“第一步未给角度、第二步为60°”不会误认为第一步为60°。

新增回归覆盖混用“使点A到达P”和“翻折至三角形”两种句式，以及第一步或第二步单独缺角度。折片点名也按完整点名切分，避免把撇号当成独立顶点。

## 输出模式和限额

- 旧 `json` 能力记录只证明模型曾按提示返回 JSON，不能证明服务接受 JSON mode。新的探针在健康记录中保存 `json_mode_v1` 证据；规划器与设置界面共用同一判断。旧配置无需删除密钥，重新验证能力即可获得新证据。
- 输出结束原因为长度限制或明确拒绝时，先返回对应失败，再决定格式修复；不会因为半途恰好形成合法 JSON 就执行工具。
- 模型服务设置新增可选的“单次输出上限”。该值在 TS 与 Rust 两端检查为 1–131072 的整数，并存入配置。填写时仍须遵守所选模型实际支持的上限。
- 配置上限后，首次请求最多4096 tokens；截断修复可提高到所配置上限，继续使用原有共享调用预算和修复次数。留空保持服务原有默认值，不猜测模型上限。
- `responseSchema` 已接到 Rust 命令参数及实际 RequestOptions，修复此前 IPC 层固定丢弃 schema 的问题。这不代表所有服务已验证支持严格 schema；运行时仍按能力选择模式。

## 回归与验证方式

`packages/agent-core/src/foldCompleteness.test.ts` 使用正确底图构造漏折和错角反例，检查折后点必须存在、30°条件必须被独立核对。测试初次运行时5项失败，修复后通过。原有翻折相关23个文件、116项回归亦通过。

输出限额覆盖实际设置表单保存、profile解析与磁盘重启恢复、请求限额传递、截断修复上限，以及旧能力证据失效。

Rust验证使用仓外临时 Cargo 工程，直接引用本仓 provider、凭据与配置模块和现有测试；避免引入本环境没有的 WebKitGTK/Tauri GUI 依赖。101项检查通过。此结果不等于完整Tauri命令注册或Windows打包已验证，后两者仍需桌面构建环境。
