## 1. 结论与范围

这几次故障有共同原因。输入、题意、模型工具合同、动作编译、独立核验和发布产物之间，仍有语义与规则不一致的地方。已存在隔离草稿、确认门禁、独立几何判据、失败修复预算、单元测试、浏览器测试与 CI。这些基础应继续使用。

当前最高风险是公式归一化改变数学含义。本轮复现了正确函数被拒绝、错误函数通过编译和题设核验的情况。其次是工具 schema 与运行时不一致，以及多小问题目的条件作用域缺失。

前两次针对原题的确定性修复仍有效，但对自然语言变式的覆盖不足。仅扩展答案字数或再添加一条题型正则，不能完成本轮整改。

本次实际检查了题图交接、表达式归一化、题设与目标抽取、规划器选择、计划合同、编译与修复、函数图核验、只读答案路径、离线评测与发布标识。没有对 CAD、所有画布工具、Rust 网络层逐项作完整审计，也没有调用真实视觉或文本模型。

本轮产物是审计、复现脚本和实施方案。未修改生产代码，未重新打包桌面程序。

## 3. 已确认的缺口

### R1 / P0　公式转换改变分母含义

证据位置为 `packages/agent-core/src/latexNormalisation.ts:65`、`diagramObligations.ts:833`。分数归一化只在操作数包含显式算符时加括号，`2x` 的隐式乘法不在此列。后续补乘号使语义改变。

| 原式 | 当前解析 | 正确图的核验 | 错误图的核验 |
| --- | --- | --- | --- |
| `\frac{1}{2x}` | `1/2*x` | `1/(2*x)` 被拒绝 | `x/2` 通过 |
| `\frac{x}{2x}` | `x/2*x` | `x/(2*x)` 被拒绝 | `x*x/2` 通过 |

第一行已走 `compilePlan`。正确图返回 `ok=false`、没有草稿。错误图返回 `ok=true`、产生草稿、题设核验为 `passed`。这是编译与核验层的复现，本轮没有在桌面上提交错误图。

**修复任务**

1. 立即保留每个分子、分母的完整分组。所有归一化表达式必须经语法解析，失败时保留原文与具体错误。
2. 把公式处理逐步迁到共享表达式树，节点至少包括数字、符号、加减乘除、幂、函数调用。LaTeX 分组和隐式乘法在构树时处理，不在丢失分组之后补猜。
3. 几何标注的长度读取继续使用既有能力，通过适配器接入，避免一次替换所有几何词法。

**验收**为上述两题正确图通过、错误图拒绝，并加入分母含乘积/括号/函数、负指数、嵌套分式与根式、定义域空点的独立反例。原题数值期望直接写入测试，不能由同一个归一化函数生成。

### R2 / P0　模型工具合同与运行时规则不一致

证据位置为 `apps/web/src/agent/modelPlanner.ts:225` 与 `packages/agent-core/src/schemas.ts:267`。工具 schema 把三类回复的字段放在同一个对象，运行时按 `kind` 分开允许字段。

用仓库现有 Ajv 验证真实 `buildPlanToolSchema`，再调用真实 `parsePlanEnvelope`，结果如下。

| 载荷 | 工具 JSON Schema | 运行时 |
| --- | --- | --- |
| 有有效建图动作的 `plan` 携带 `toolResultRefs` | 接受 | 拒绝多余字段 |
| `answer` 携带 `actions` | 接受 | 拒绝多余字段 |
| `plan` 缺少 `actions` | 接受 | 拒绝缺失动作 |
| `goal` 长度 513 | 接受 | 拒绝，限长 512 |

已修复的 `answer` 4096 上限只解决一个字段，其他合同差异仍在。

**修复任务**为在 agent-core 建立唯一分支定义，派生工具 schema、运行时读取规则和提示词示例。为兼容不同 provider，可按能力输出带分支约束的 schema 或分开发布计划/答案/澄清工具，三种输出都收敛到同一内部合同。仅对有唯一含义的传输包装做有记录的归一化，冲突字段继续拒绝。

**验收**为每个分支的合法/缺失/多余字段、上下限和动作输入都做双方一致性测试。传输层接受的结构不得在运行时因另一个结构规则被拒绝。引用是否存在和数学是否成立仍由下游判定。

### R3 / P0　多小问没有统一条件作用域

`packages/agent-core/src/diagramObligations.ts:2144` 在第一次遇到“证明/求证”时切开题设与目标。对 Q17 通用解析，`AD⊥PB` 被纳入 givens，但第（2）问的 `AD⊥DC` 和二面角正弦条件都落入 goals 的长字符串。

当前 `scopedPyramidPlan.ts` 为原题选择第（2）问绘图作用域。实测原题命中，但将“证明”改为“试证明”，或把 `(1)/(2)` 改为 `①/②`，都会退出这一专门路径。退出确定性路径不代表在线模型必然失败，本轮未调用模型评估后续结果。

**修复任务**为新增题目级结构，在现有 obligation IR 外层记录 `stem`、`parts[]`、每问 `givens/goals`、继承关系、原文区间和绘图作用域。优先结构化分问，再分别调用既有条件读取器。`若/假设` 进入对应小问，待证命题保持为目标。构造、求解和核验消费同一份题目结构。

**验收**为编号/语序/“证明、求证、试证明”变式产生相同作用域。同问增添限制必须进入核验，不同小问的独立条件不能混合。第（1）问的图不得标为第（2）问已验。

### R4 / P1　修复入口依赖字面句式，评测入口也不完全相同

`trigMonotonicityPlan.ts:10` 与 `:17` 限定问法和前缀。实测以下 5 个语义相同的输入只有原题命中本地确定性入口。

- 原题，命中。
- “单调递增区间”改为“递增区间”，未命中。
- 小问编号改为 `(i)`，未命中。
- 增加 `17.` 题号，未命中。
- “求 f(x)”改为“求函数 f(x)”，未命中。

本次另外测得 `\sin^{2}x`、`\sin 2x`、嵌套根式、`\frac{1}{2\pi}` 和 `\frac{1}{2(x+1)}` 的正确函数无法核验。后续模型重试不能修复解析器本身不支持的表达式。

`agentRunner.ts:536` 先尝试新的 Q17/三角函数路径，而 `reliabilityEval.eval.test.ts:169` 直接选 `createLocalPlanner` 或 `createModelPlanner`。已有 runner 测试覆盖原题，但默认可靠性评测不等于完整产品入口覆盖。

**修复任务**为把能力选择收成共享路由器，按结构化目标和表达式类型匹配。原题专用构造作为能力实现保留，产品、本地评测、模型回放共用路由，并显式记录最终命中的能力或未支持原因。

**验收**为等价文字/LaTeX/点名/数值变式覆盖多个题型，且生产与评测的路由结果一致。对限制定义域、新增小问等语义变化，不能错误套用原题解法。

### R5 / P1　题图疑点和定位信息在交接中丢失

`ProblemImageComposer.tsx:137` 只把题干与 `reading.diagram[].text` 传入 `imagePrompt`。图片编号、框位置与 `uncertainties` 未进入 Agent 请求。`canUse` 只检查题干是否含 `[看不清]`，没有结构化记录某个疑点是否被解决。发送成功还会清空组件内图片与读取结果。

现有识别器提示词已区分可见信息、疑点和题面指令，界面也能定位疑点，这些能力应保留。现有 `e2e/problem-image-reader.spec.ts` 用真实 PNG 测上传流程，但模型返回由测试桩固定，不能据此判定识别准确率。

**修复任务**为引入结构化题图附件，保留原图本地引用/摘要、图片编号、框、转录版本、疑点和用户修订记录。几何条件、可见连接、虚实线和不确定观察分别标记来源。影响长度/角度/点名的未解决疑点触发局部复读或针对性澄清，轻微外观疑点只标注。需要复读时再调用视觉模型，不必每轮重复发送整图。

**验收**为关键数字模糊、虚实线误读、遮挡、水印、多图、用户修订均有交接测试。以人工标注图集分别统计公式字符/分组正确率、点名连接正确率、虚实线正确率和关键疑点检出率。有限样本只报告样本结果。

### R6 / P1　曲线按数量识别，核验原因混在一句话里

`diagramVerification.ts:618` 要求本轮新增函数图恰有一条。实测正确 `f(x)=x²` 加一条辅助函数后返回 `unverified`，虽然存在正确曲线。报错同时包含“没有唯一曲线”和“表达式解析不了”，无法让修复器选择针对性的动作。

导函数图元使用独立类型，不会自动被计为第二条普通函数图。不能把用户那次失败武断归因于画了导函数。

**修复任务**为在题目结构中分配 `functionId`，规划动作声明题目函数/辅助图角色，核验按实体引用绑定。给出 `expression_parse_failed`、`function_missing`、`function_binding_ambiguous`、`function_mismatch` 等独立错误码。

**验收**为原函数、导函数和辅助函数共存可正确核验。未指定角色又存在多个可能匹配对象时，报告歧义，不能任选一条放行。

### R7 / P1　错误传播与修复决策缺少根因关联

`planCompiler.ts:725` 起的编译循环在一个建图动作失败后继续编译后续动作。因此“实体没建成”会引发“找不到 P”。`planCompiler.ts:3610` 针对缺点给的主要建议却是调整顺序。用户日志中共面偏差约 1.15，远大于 2e-9 容差，这一失败不能归因于普通浮点舍入。

`coordinator.ts:703` 对编译失败有有限修复；`:756` 左右的最终核验门禁失败直接终止。`agentRunner.ts:921` 起仍从文本识别部分错误，最终对外大多为 `run_failed`。

**修复任务**为使错误包含 `stage/code/sourceSpan/actionKey/blockedBy/recoverability`。创建动作失败时，把依赖动作标为被阻塞，优先修根因。唯一可确定的依赖排序由系统处理，有歧义、循环或实体创建失败时保留明确错误。核验失败先区分解析能力、真实数学冲突、对象缺失、临时请求问题，再选择本地修复、有界重新规划、澄清或明确终止。

**验收**为无效底面导致的 P 缺失只产生一个主因及依赖说明，不建议无效排序。确定性解析失败不重复消费模型请求。保留既有总预算、取消与禁止未核验提交的门禁。

### R8 / P1　答案内容和图形核验是不同证据

`coordinator.ts:608` 的只读答案分支检查引用来源后可以直接完成。图形计划通过时，附带自然语言答案也不会自动逐句获得数学证明。现有数值核验报告已经声明实例证据不等于全称证明，这一点是正确基础。

**修复任务**为在已有证明/核验模块上增加有限类型的答案声明，例如所求长度、角度、单调区间、平行垂直目标。把答案值和已识别目标绑定，记录对应独立计算或证明证据。解释文字保留为文字，未经数学验证的解释不得继承图形通过状态。

**验收**为正确图加错误 `AD` 数值、遗漏周期项的单调区间、伪造“题目矛盾”均不能显示为已验证数学结论。无法形式化的一般证明允许如实标明验证范围，不要求本轮建设通用定理证明器。

### R9 / P1　回归题集与发布标识尚不足以覆盖真实使用

CI 已运行单元测试、Web 构建、浏览器测试和离线评测，应继续保留。默认 reliability 题单实际为 29 道，全部标为 `unreviewed`，主要集中于翻折与基础立体。本文件说明仍写“27 条”，也有统计漂移。该评测直接使用规划器，不能代替图片识别准确率或桌面完整链路。

`runEventClient.ts:48` 的版本信息包含提示词、工具、schema 和 provider 能力，未包含应用构建指纹。`tauri.conf.json:4` 仍是 4.2.0。多个同版本修复 exe 需要仅靠文件名分辨，不利于重现。

**修复任务**

1. 建立带独立期望值的固定验收集，将用户失败记录转为脱敏回放，不只保存最终合法计划。回放应包含 provider 原始工具参数、解析失败、修复轮次和终态。
2. 增加从生产 `runPrompt` 入口开始的组合测试，覆盖文本/题图交接、已有同名对象、草稿、确认与提交。
3. 注入应用版本、构建时间、Git revision、源码状态摘要、schema/parser 版本。界面与错误导出都带同一指纹。当前工作区有未提交修改，仅 HEAD 无法唯一标识构建。
4. 交付前在本次生成的 Windows exe 上运行固定冒烟题，记录 exe 哈希和实际启动路径。Web 测试通过与桌面验收分别报告。

## 5. 验收标准

### 固定题集

建议建立 60 道经复核的基础题，覆盖函数 15、立体 15、平面/圆锥曲线 10、多小问与折叠状态 10、缺条件/矛盾/未支持输入 10。原题与等价变式至少各 4 种表达，总计至少 240 个文本输入。多小问题及负例会与数学家族交叉，统计时按唯一题目 ID 去重。

另外收集至少 20 张有人工标注的真实题图，含水印、小分母、点名撇号/下标、遮挡和虚实线。图片回放测试与在线视觉读图指标分别统计。

### 放行标准

- 原文分组和条件保持测试全部通过。固定反例中错误题设、错误图、错误结构化答案的误通过数为 0。
- 合同结构差分测试全部通过，已支持题型的作用域和路由变式全部通过。
- 确定性支持范围内的固定题集全部通过。未支持题须精确指出未解析的输入或缺失条件，不能伪装完成。
- 每个题目的结果分别记录解析、构造、图形核验、答案核验和提交状态，不能只记“生成了草稿”。
- 真实模型评测单独报告首次成功率、修复后成功率、误通过数、延迟及请求量。本轮没有实测这些指标。建议首轮验收目标为首次成功率至少 90%、有限修复后至少 95%，明确分母和样本规模，后续按产品承诺调整。
- 不放宽几何正确性与文档确认门禁来提高成功率。函数采样等价仍标明数值证据范围，不能当成全定义域符号证明。
- 每次交付包含构建指纹、固定冒烟题结果与可重放失败记录，用户日志可直接定位到源码状态。
